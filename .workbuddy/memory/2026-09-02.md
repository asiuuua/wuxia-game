## 主菜单按钮：悬停选择音效（2026-09-02 凌晨）
- **需求**：给主菜单 5 个按钮（开始/继续/设置/额外/退出）增加「鼠标悬停时播放选择音效」。
- **关键发现（根因）**：
  1. 代码早已存在悬停音效链路：`WuxiaMenuButton.gd` 的 `_on_mouse_entered` → `_play_hover_sfx()` → `AudioManager.play_ui_sfx("hover")`。
  2. 但 `resources/audio/sfx/` 目录**完全是空的**——`ui_sfx.json` 里注册的 8 个音效（hover/click/confirm/cancel/back/open/close/error）全部缺失；`AudioManager.play_ui_sfx` 在 `ResourceLoader.exists(path)` 失败时空静默跳过 → 所有 UI 音效一直无声。
- **修复**：
  1. 新增 `tools/gen_ui_sfx.py`（纯标准库合成 8 个短促占位音效，16bit/44100/mono，45~200ms），生成到 `resources/audio/sfx/`。占位音；正式音频替换同名文件即可，配置表不用动。
  2. **修了一个隐藏的鼠标拦截 bug**：`WuxiaMenuButton.tscn` 里 `bg_panel`(800.8x131.6) 比按钮(286x47)大且 `mouse_filter=2(STOP)`，会拦截鼠标导致按钮本体 `mouse_entered` 不触发（连悬停高亮都可能不灵）。把 4 个装饰子节点(bg_panel/icon/label_main/label_sub)的 `mouse_filter` 全改为 `0(IGNORE)`，事件穿透到按钮本体，悬停音效/高亮/点击都可靠触发。这是 Godot 装饰子节点不拦截输入的标准做法。
- **验证**：提交 `f6a52ef`（10 files：8 wav + tscn + 生成脚本），GATE1 通过（`RC=0` 零解析/编译/加载错误）。纯游戏侧改动，无工作室工具/端口动作。
- **备注**：用户是电脑小白，无法自产音频；合成占位音是项目「占位期文件未到位就静默跳过」设计的合理落地。正式音效让用户替换 `resources/audio/sfx/` 下同名 wav 即可。

## 登录界面卡死 BUG 修复（2026-09-02，重大修正）
- **现象**：进入游戏登录界面（主菜单）直接卡死/无响应，反复多次（用户连报"又双叒叕卡死了"）。
- **⚠️ 根因更正（关键）**：首轮误判为"190MB 未压缩纹理触发显卡 TDR 超时"。**此诊断错误**——用户实测显卡是 **NVIDIA RTX 3070 Ti（8GB 独显）**，且日志显示引擎在跑（帧 1→138 递增、Bootstrap 已就绪），独显不可能因 190MB 显存 TDR。
- **真正根因（已定位+修复）**：`scenes/ui/components/ui_background/UIBackground.gd` 的 `_sample_edge_stops()` 用 `tex.get_image().get_pixel()` 采样背景图边缘色做渐变垫底。把纹理改压缩导入（mode=2）后，`CompressedTexture2D.get_image()` 返回压缩数据，对其 `get_pixel()` 疯狂报错 `Can't get_pixel() on compressed image, sorry.` **9024 条 ERROR 刷屏拖死主线程 = 用户看到的"卡死"**。这是"修压缩反而暴露 latent bug"的典型。
- **修复**：`_sample_edge_stops()` 改用 `Image.load_png_from_buffer(buf)` 直接解码源 PNG 字节取像素（跨 4.x 稳定实例方法；`Image.load_from_file` 在 4.7.2 已非实例方法，会 Parse Error）。与导入压缩解耦：既保留压缩纹理小显存/快加载，又能正常取像素。非 PNG/源缺失则静默回退硬编码绿渐变。
- **验证（决定性）**：无头复现 `godot --headless --path` 至主菜单，`get_pixel` 错误 **9024→0**，日志 **99332→61 行**，能正常进主菜单不卡。GATE1 零 SCRIPT/PARSE/COMPILE ERROR。
- **全量压缩（双保险第一层已落地）**：除登录 9 张外，工程里还躺着 **162 张未压缩纹理**（matte_* 124 张、half_body、battle_bg、resources/ 等）。本轮全量治理：145 个 `.import` mode=0→2、2 张超大源图缩放备份、3 个 resources/ 纹理压缩、修复 `preset_12x12.jpg`（实为 2048×1152 PNG 被错命名 .jpg，Godot 无法导入→改名 .png 并改 JSON 引用）。最终 **157 个纹理全部压缩**（`.s3tc.ctex`），删除 19 个孤儿未压缩 .ctex，无残留未压缩引用。
- **双保险机制（用户硬性要求"自动压缩+双保险"）**：
  1. **工作室路径**：`tools/desktop_studio/tscn_assets.py` 的 `write_import` 模板已写死 `compress/mode=2` + `process/size_limit=2048` → 今后工作室传图自动压缩。
  2. **本地/LocalSend/拖拽路径**：新增 `tools/compress_textures.py`（扫 `assets/`+`resources/` 所有 mode=0 纹理→改压缩+限速+删对应 .ctex 强制重导；支持 `--dry-run`；跳过 `_backup` 目录）。今后任何非工作室导入的图，跑一次脚本即全量兜底。
  3. **重导铁律**：手改 `.import` 参数**不会**触发 Godot 重导（仅源 md5 变化或缺 .ctex 才重导）；必须 `godot --headless --editor --quit --path` 全量重导生成 .ctex，否则仍按旧缓存加载。
  4. **项目级默认预设方案已证伪**：`.godot/imports/texture.import` 在 Godot 4.7 不识别（新图仍 mode=0），已删；可靠兜底就是上面 1+2。
