## 新增：把项目喂给外部 AI（ChatGPT）的导出工具

- **用户诉求**：想让 ChatGPT 读项目代码，但文件包太大传不上去。
- **体积真相（实测 du）**：`assets/` 119M + `resources/` 88M 全是图片，占仓库 99%；**真正的代码只有约 1.3MB**（scenes 782K + tests 525K + data 362K + services 273K + autoload 195K + core 166K + addons 51K）。图片 AI 既读不懂也不需要。
- **第二个更关键的瓶颈**：不是上传大小，是**上下文窗口**。全部源码导出后 1.32MB ≈ **51 万 token**，超过任何模型上下文——传上去也读不完。所以正确姿势是"分层投喂"而非打包整个仓库。
- **新增工具 `tools/export_ai_context.py`（已提交 ab021c4）**，三模式：
  - `--mode summary`（默认，首选）：导出人工整理的架构摘要（`projects/wuxia_game.yaml` 的 ai_context + 协同启动卡 + 契约总表 + README + MEMORY.md + 目录速览）→ **104KB / 约 3.2 万 token，一次能读完**。
  - `--mode module --module <关键字>`：只导相关源码，如 `--module quest` → 52KB / 约 2.1 万 token（命中 services/quest/、data/configs/quests/ 及名字含 quest 的脚本）。
  - `--mode all [--with-docs] [--with-tests]`：全部源码 1.32MB / 约 51 万 token，**仅供 Custom GPT / Project 检索，不适合直接对话投喂**（工具会主动告警）。
  - 自动排除：图片/音频/字体/`.import`/`.uid`/`.bak`/`.pyc`/`build`/`dist`/`__pycache__`/`addons`/设计参考目录。输出目录 `_ai_export/` 已加进 `.gitignore`（第63行），可随时重新生成。
- **投喂 SOP（给用户的结论）**：① 先传 `01_架构摘要_先传这个.md` 让 AI 懂架构；② 再按问题用 `--mode module` 补对应源码；③ 想让 AI 随时查全代码才把 `99_全部源码.md` 放进 Custom GPT/Project 知识库（检索用，不是一次读完）。

## 架构判定：顶层「层优先」不动，领域已在 services/ 内部落实（用户问"我们按领域分了吗"）

- **结论（实测）**：**系统确实是按领域划分的，不是按表堆的**——`services/` 已拆 12 个领域（ability/alchemy/bond/combat/dialogue/equipment/forge/inventory/quest/save/sect/shop），`data/configs/` 同构（abilities/alchemy/battles/bond/combat/dialogs/forge/items/npcs/quests/regions/sect/shop/world...）。文档那句"按领域而非按表划分"这个分水岭，**我们已经站对了边**。
- **但与文档有两处结构差异（判定：都不需要大改）**：
  1. **顶层是「层优先」不是「域优先」**：我们是 `autoload→core→data→services→scenes→resources`（技术分层），领域住在 `services/` 与 `data/configs/` 内部；文档主张顶层直接是 Core/World/Character/Combat/... 领域。**决定：保持层优先，不改成域优先顶层**——理由：① 现有单向依赖铁律正是靠这个分层强制的（改成域优先会削弱依赖方向约束）；② Godot 工程惯例按层组织；③ 单人 2D 项目改成域优先是纯 churn，零收益。**其他 AI 窗口不要去做"顶层改域优先"的重构。**
  2. **`core/` 只有 10 个 Core 原语里的 5 个**：有 Event(EventBus)、Time(weather_time_service)、Random(core/utils/seeded_rng.gd)、Save(SaveManager+save_validator+core/interfaces/i_saveable)、Localization(localization_manager)；**缺 ID / Command / Condition / Tag / Reference 五个**。`core/` 目前实际内容 = constants(combat/game/item/path/ui_theme) + enums(ability/bond/combat/error/forge/item) + utils + interfaces + extensions。**补齐这 5 个原语 = 前面的 P3，是"让新增内容真正只加数据"的关键。**
