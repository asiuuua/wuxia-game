## 17:37 第 X+3 轮 — EventBus 60+ 个 "unused_signal" 警告

**问题**
- 编辑器错误面板跳到 77 个，全是 `GDScript::reload: The signal "X" is declared but never explicitly used in the class.`
- 实际是 EventBus 事件总线模式的**设计特性**——信号就是给外部模块 emit/订阅的，本类自己不发

**解决（精准一行）**
- `autoload/EventBus.gd` 类级加 `@warning_ignore("unused_signal")`
- Godot 4.4+ 引入的**类级抑制**（放在 extends 之后），对整个类后续所有 signal 都生效
- 验证：`--check-only --script res://autoload/EventBus.gd` 完全静默通过，0 警告

**为何不选其它**
- 改 `project.godot` 的 `gdscript/warnings/unused_signal=0`：项目级，会关掉所有文件→未来业务类真有未用 signal 也发现不了
- 加 `signal X.connect(func(_a): pass)` 自连：运行期内存/调用开销、噪音
- 每个 signal 单独加：`# warning-ignore:unused_signal` → 60+ 行重复

**学到的（值得记入踩坑清单）**
- `EventBus` 模式 + GDScript 静态检查 = 必然误报，解法是**类级 `@warning_ignore("unused_signal")`**，一行到位

## 17:55 第 X+6 轮 — project.godot 乱码配置 + 项目级关 unused_signal

**真根因**
- `project.godot:47` 有一行前几轮我错误写进去的中文注释当 key：
  ```
  "warnings/#全局事件总线：信号本类内不emit…关警告避免误报unused_signal"=false
  ```
- Godot 不识别这个 key，**等于没配**，整个 gdscript warnings 走默认值 = 全开
- 用户编辑器实例 GDScript::reload 仍报 97 个 unused_signal 警告（比之前 60+ 多，因新增 signal 也加进去了）

**修法（项目级开关 + 类级 pragma 双保险）**
- `project.godot` 删乱码行
- 加 `warnings/unused_signal=0`（标准 Godot 项目级 key）
- 保留 `EventBus.gd:11` 的 `@warning_ignore("unused_signal")` 类级 pragma 作兜底（项目级配置加载顺序/版本兼容性差异时，类级仍生效）

**为何改 trade-off**
- 之前顾虑"未来业务类真出现 unused_signal 时发现不了"
- 实际上：EventBus 模式是项目铁律（业务层已重构，service 不持 Node，跨模块只走 EventBus），项目里 90%+ 的信号都在 EventBus 这一个文件
- 万一未来业务类要查未用信号，单行把 `warnings/unused_signal=0` 改 `=1` 即可
- 比"依赖类级 pragma 在每个 Godot 版本都生效"更鲁棒（CLI 4.7.2 验过 OK 但截图证明 Editor 实例不一定生效）

**验证（双保险）**
- `--headless --quit` EXIT=0，无任何 signal/parse/identifier 警告（仅 performance_monitor 首帧抖动良性告警）
- `--check-only --script res://autoload/EventBus.gd` 完全静默（0 输出）

**踩坑记：project.godot key 不能写带 # 的注释**
- 任何 `key=value` 里 key 是合法字符串，但**不像 .ini 可以写注释** — Godot 把整行当配置项
- 注释**必须**在 `[gdscript]` 段内独占一行、用 `;` 或 `#` 起头
- 之前那行中文带 `#` 当 key 是无效配置——但 Godot 静默不报错，所以坑很深

**根因定位（#1 ESC 失效）**
- `MenuItem` 组件默认 `focus_mode = FOCUS_ALL`，鼠标**点击**会 `grab_focus()`
- EscMenu 关闭是 `close_screen`（不切场景，返回同一游戏场景），关闭后焦点**悬挂**在已被销毁的 MenuItem 上

**修复清单**
1. `scenes/ui/components/menu_item/MenuItem.gd` `_ready()` 加 `focus_mode = Control.FOCUS_NONE`（从源头消除焦点悬挂，注释说明避免吞 ESC）
