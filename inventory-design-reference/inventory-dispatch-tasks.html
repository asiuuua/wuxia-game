陆派单流程与验收纪律

6.1 派单节奏

P0：T1 → T2 → T3 → T4→ P1：T5 → T6 → T7 → T8 → T9 → T10 → T11 → T12→ P2：T13 → T14 → T15 → T16 → T17

服务层单（背包窗口）与 UI 单（UI 窗口）可并行推进；但 T3 依赖 T1/T2、T9 依赖 T8、T11 依赖 T10，UI 单必须等服务层接口合入后再开工，避免接口对不上返工。

6.2 双闸门验收（所有任务通用）

GATE1：godot --headless --path "D:/武侠游戏" --quit 零 SCRIPT/PARSE/COMPILE ERROR
GATE2：godot --headless --path "D:/武侠游戏" res://tests/unit/run_all.tscn 零 ✗ 且失败 0

任一闸门失败立即停手报告，禁止带红合入。GATE2 契约测试只做「声明存在 + 参数个数一致」的纯契约校验，绝不 emit EventBus 信号。

6.3 提交纪律

各窗口不自行 git commit/push，改完后过双闸门，用 python tools/commit_queue.py add --window <窗口名> --message "..." --files <具体文件> 入队，由 PM/AI-UI/AI-PM 统一 flush 提交。提交 message 带 [集成] 前缀，精确指定文件，禁止 -A。

6.4 派单命令速查
