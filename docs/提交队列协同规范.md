# 多 AI 提交队列协同规范

> 痛点：多 AI 并行开发同一 `master` 分支，每次要提交都得由用户跨窗口喊话告知 PM。
> 方案：各窗口把「待提交文件 + 提交信息」写进队列日志，PM 定时读取并**精确提交**，用户无需再介入。

生效日期：2026-08-29
负责人：背包窗口（兼 PM / 架构师）

---

## 一、总体架构

```
各窗口（写）                 PM / 背包窗口（读 + 提交）
─────────────               ───────────────────────────
完成任务并自行验证
      │
      ▼
commit_queue.py add  ──►  .workbuddy/commits/pending_<窗口名>.jsonl
      │                     （append-only，每行一条 JSON）
      │                                          ▲
      │                                          │ 每轮任务结束 / 每15分钟自动化
      │                                          │
      │                                  commit_queue.py flush
      │                                          │ 精确 git add 所列文件 → commit
      │                                          ▼
      └──────────────────►  .workbuddy/commits/done_<窗口名>.jsonl
                            （已提交记录归档，含 committed_ts / status）
```

- 队列目录 `.workbuddy/commits/` 已加入 `.gitignore`，**永不进版本库**，不污染任何窗口的提交历史。
- 每个窗口**只写自己的** `pending_<窗口名>.jsonl`，PM **只写自己的** `done_<窗口名>.jsonl`。全程 append-only，无跨窗口文件锁竞争。

---

## 二、各窗口（入队方）职责

**何时入队**：任务完成、且你自己已验证（双闸门 / 单元自测）通过之后，立刻入队。
**不要**在改动到一半、或还没验证时入队——PM 会原样提交你列的文件。

**命令**（managed python，纯 stdlib，无需 venv）：

```bash
C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/python.exe \
  D:/武侠游戏/tools/commit_queue.py add \
  --window 战斗窗口 \
  --message "[战斗窗口] M3-4 状态引擎扩护盾/反弹/复活" \
  --files services/combat/combat_core.gd data/configs/scenes/battles.json
```

- `--window`：你的窗口名（如 `战斗窗口`/`UI窗口`/`结缘窗口`/`背包窗口`），用于文件名与审计。
- `--message`：完整 git 提交信息，**必须写明窗口名与影响面**（参考既有提交风格）。
- `--files`：本次要提交的**确切文件列表**（相对仓库根，用 `git status --short` 核对），**不要图省事写目录或通配**。
- `--branch`：默认 `master`，仅记录，PM 不切分支。

**入队即承诺**：你列出的文件会被 PM 直接 `git add` 并提交。入队前请确认：
1. 这些文件确为本窗口主权内改动（不要替别的窗口代交，除非对方明确授权）；
2. 文件当前工作树状态是你想要提交的版本；
3. 已自行通过验证（PM 出队时**不跑 Godot 重验证**，避免与其他窗口抢 `.godot` 缓存）。

## 三、PM / 背包窗口（出队方）职责

**触发时机**：
1. 每完成一轮自己的任务后，主动跑一次 `flush`；
2. 每 15 分钟定时自动化 `提交队列定时出队` 兜底（无人值守）。

**命令**：

```bash
C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/python.exe \
  D:/武侠游戏/tools/commit_queue.py flush
```

**flush 行为（铁律）**：
- 读取所有 `pending_*.jsonl`，对每条**未提交**记录：
  - 用 `git status --porcelain` 核对所列文件是否真有改动；**全部无改动则标记 `no-op` 跳过**，不提交空 commit。
  - 有改动则**精确 `git add` 这些文件**（绝不 `git add -A` / `git add .`）。
  - `git commit -m <记录里的 message>`。
  - 提交成功 → 把该行移入 `done_<窗口>.jsonl`（附 `committed_ts` / `status`）。
- 若 git 处于 `MERGE` / `REBASE` / `CHERRY-PICK` 状态，**整体跳过**并报错，绝不火上浇油。
- **不跑 Godot 健康检查**（协议约定各窗口自行验证；PM 出队只做 git 层面的精确提交与无改动过滤）。
- 队列为空则简短报告「队列为空」。

**审计**：`done_*.jsonl` + `git log` 可回溯每次自动提交来自哪个窗口、哪些文件、何时。

## 四、主权与边界（不可破）

- 各窗口只交**自己主权目录**的文件；共享地基（`core/enums/*_enums.gd`、`autoload/EventBus.gd`、`ConfigManager.gd`、`ui/screens.json`、`strings.csv`）冻结，任何窗口改动须先协商。
- PM 出队**只忠实搬运**队列内容，不做内容评审、不替窗口重写代码；若发现某记录明显越权或会破坏共享地基，PM 应**暂停该条、在群里/@用户**确认，不擅自提交。
- 任何窗口不得在入队之外自行 `git commit`（除非独占式 hotfix 且已告知 PM 清空对应队列）。

---

## 五、兜底与异常处理

| 现象 | 处理 |
|------|------|
| 队列为空 | flush 输出「队列为空」，无操作 |
| 记录所列文件全部无改动 | 标记 `no-op` 移入 done，跳过 |
| `git add` / `commit` 失败 | flush 报错并保留该记录在 pending（下次重试），不影响其它记录 |
| git 处于 MERGE/REBASE | flush 整体跳过并报错 |
| 某窗口重复入队同一文件 | 以 done 去重（按 `id`），已提交的不再重复提交 |
| PM 想先看将要提交什么 | `flush --dry-run` 打印待提交清单，不实际提交 |

---

## 六、用户侧（你）需要做的

1. 把本规范与各窗口同步一次（其他 AI 会话里贴一段：「任务完成验证后调用 `commit_queue.py add` 入队，PM 会自动提交，不用再 @ 我」）。
2. 之后提交这事基本不用管；偶尔看一眼 `git log` 或 `done_*.jsonl` 即可。
3. 若某次自动提交你不满意：直接用 `git revert <hash>` 回退，并在群里告知对应窗口。

## 七、命令速查

```bash
# 其他窗口：入队
python tools/commit_queue.py add --window <窗口> --message "<信息>" --files a.gd b.json

# PM：出队提交（实际）
python tools/commit_queue.py flush
# PM：预览（不提交）
python tools/commit_queue.py flush --dry-run
# 查看待提交条数
python tools/commit_queue.py list
# 查看待提交原文
python tools/commit_queue.py pending
```
