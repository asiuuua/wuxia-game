# 变更通告 2026-09-02 · 列表刷新子节点 + 悬停动效令牌解析结果池化

> 模块：UI（性能优化）　改动范围：scenes/ui/components/ui_feedback/UIFeedback.gd + scenes/ui/overlays/hud/quest_track_panel.gd + tests/unit/test_hud_panels.gd + tests/unit/test_ui_feedback_cache.gd　commit：ff00d90

## 变更项
1. **悬停动效令牌解析结果缓存（UIFeedback.gd）**：令牌→Tween 枚举映射改为静态缓存（`_trans_cache`/`_ease_cache`，跨实例共享，配置启动时固定故缓存安全）；预设 dict / 时长 / 缩放幅度改为实例级缓存（`_cached_preset`/`_cached_duration_f`/`_cached_hover_scale_f` 等，`_preset` 在 attach 时固定）。`_animate_to` 走 `_cached_trans/_cached_ease/_cached_duration`，悬停动效高频触发不再每次重复解析令牌→枚举。
2. **任务追踪列表条目 Label 对象池（quest_track_panel.gd）**：`_refresh` 由「全量 free 重建」改为「回收复用」——旧条目经 `_pool_release` 回收进 `_label_pool`，新建条目经 `_pool_take` 复用（重置文本/autowrap/主题覆盖），避免高频刷新反复 new/free 造成 GC 抖动。追踪任务数量极少，池容量天然受限。
3. **回归测试**：新增 `tests/unit/test_ui_feedback_cache.gd` 3 项（静态缓存填充复用 / 跨实例共享 / 实例缓存填充 + `_animate_to` 走缓存）；`test_hud_panels.gd` 新增 `test_quest_track_pool_reuses_labels`（二次刷新复用同一批 Label 实例）。

## 变更原因
审计派单 fdfcce7396ed（审计→UI）：列表频繁重建子节点、悬停动效每次重新解析令牌，存在可观测的性能浪费。不阻塞流程，但做了能明显提升性能/手感。

## 影响面
- **纯 UI 性能优化，零行为变更**：动画数值仍全部来自 `data/configs/ui/ui_anim.json`，改手感只改表不动代码；任务追踪列表渲染结果与之前完全一致。
- **共享地基**：仅使用 `ConfigManager.get_anim_*` 现有接口（只读），未改 ConfigManager；未触碰其他窗口主权文件。

## 回滚方案
- UIFeedback.gd：删除静态缓存变量与 `_cached_trans/_cached_ease/_cached_preset_dict/_cached_duration`，`_animate_to` 恢复直接调用 `ConfigManager.get_anim_trans/get_anim_ease/get_anim_preset_duration`。
- quest_track_panel.gd：删除 `_label_pool` 与 `_pool_take/_pool_release`，`_refresh` 恢复 `child.free()`，`_add_empty/_add_quest_entry` 恢复 `Label.new()`。
- 删除 `test_ui_feedback_cache.gd` 与 `test_quest_track_pool_reuses_labels`。

## 协同方需知
- **UI 窗口**：UIFeedback 为公共交互反馈组件，缓存为纯增量（新增静态/实例变量与私有方法），不改变任何公开接口；若后续改动画数值表，运行期不变、重启生效，缓存自动失效无需清理。
- **其他窗口**：任务追踪面板渲染结果不变；对象池仅在面板生命周期内复用节点，面板释放时池随实例一并回收，无泄漏。
