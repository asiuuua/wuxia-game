# 变更通告 · M3-2 状态引擎扩护盾 / 反弹 / 复活（战斗窗口主权）

> 日期：2026-08-29　·　窗口：战斗　·　上游：M1 战斗逻辑内核 / M2 演出编排 / M3-1 敌人 AI 选技能
> 提交策略：**git 提交统一由 UI 模块执行**（用户治理规则），本窗口只产代码 + 本通告 + 对话内精确文件清单，不自 `git commit`。

## 一、目标
把状态引擎从「属性修正 + DoT/HoT」扩到三个战斗常用机制，全部**数据驱动**（走现有 `status_effects.json` + `_apply_status` 管线）：
1. **护盾 (Shield)**：吸收伤害，优先于气血扣减，持续到被消耗。
2. **反弹 (Reflect / 荆棘)**：受到攻击时，把所承受伤害的一部分反弹给攻击者（不引发连锁）。
3. **复活 (Revive / 不屈)**：单位气血归零本应死亡/倒地时，若挂有复活状态则消耗一层、原地拉起。

约束：共享地基**只增不改**；演出可视化（护盾条 / 反弹飘字 / 复活特效）归入 **M3-3 演出动效令牌化**，本 M3-2 只交付逻辑 + 事件契约，演出层对未知事件类型 `match` 静默跳过（已验证安全，不崩）。

## 三、共享地基（只增不改）
- `EffectType` / `CombatEvent.Type` 枚举**纯追加**，不重排既有值（既有代码/存档映射不变）。
- `combat_character.shield` 为新增 var（非方法，不进契约总表公开接口）。
- `EventBus` / `ConfigManager` / `screens.json` / `strings.csv` / `ui_anim.json` **均不动**。
- **契约总表无需同步**：gen_contract 仅扫「信号 + 公开方法」，本 M3-2 未增公开方法、未增信号，故无漂移（注：当前 `契约总表.md` 工作树里混有背包窗口未提交的 item 锁定/容量 API 改动——那不是本窗口范畴，本通告不纳入，已由战斗窗口还原该共享文件）。

## 四、顺带修复（既有缺口）
- **致命 DoT 不致死**：此前 `tick_unit` 的 DoT 直接扣血却**没走 `_try_down`**，毒/灼烧打到 0 血不会死、复活也对 DoT 失效。M3-2 在 DoT 写血后补 `_try_down`，现致命毒/灼会正确判负，`buqu` 也能挡致命 DoT。
