## 一、所有弹出窗口真正居中（用户：菜单/姻缘里所有弹出窗口全部居中）

**根因**：Godot 4.7.2 的 `set_anchors_and_offsets_preset(Control.PRESET_CENTER)` 会**忽略节点当前 size、把四个 offset 直接清零**（已用调试脚本实测）。结果是面板 `anchor` 全 0.5、`offset` 全 0 → 左/上边缘落在父中心，而非真正居中（视觉明显偏右偏下）。此前仅 `BondRomanceScreen` / `GameMenuScreen` 手工改过，其余 8 处仍中招。

**修复方案**：新增共享工具 `scenes/ui/ui_center_utils.gd`（`class_name UICenterUtils`），用「锚 0.5 + 对称 offset（±size/2）」手动居中，中心精确 = 父中心。全部 8 处弹出面板改为调用 `UICenterUtils.center_panel(panel)`（调用前先赋真实 `size`）：

| 文件 | 弹出窗口 |
|---|---|
| `screens/abilities/AbilitiesScreen.gd` | 技艺界面 |
| `overlays/map/MapScreen.gd` | 地图界面 |
| `overlays/inventory/InventoryScreen.gd` | 背包界面 |
| `screens/settings/SettingsScreen.gd` | 设置界面（游戏菜单打开） |
| `screens/save_load/SaveLoadScreen.gd` | 读档/存档界面（游戏菜单打开） |
| `overlays/attributes/AttributesScreen.gd` | 属性界面 |
| `components/confirm_dialog/ConfirmDialog.gd` | 通用确认框（姻缘/菜单各类弹窗复用） |
| `components/item_slot/ItemSlot.gd` | 拖拽预览内文字居中 |

> 注：`BondRomanceScreen` / `GameMenuScreen`（姻缘/主菜单主面板）此前已手工居中，本次未动；`EscMenu` 用对称 anchor 已居中，未动。

## 二、任务追踪栏可以拖动了（用户：点了拖不动）

**根因**：`QuestTrackPanel` 是 `Control`，但**从未显式设置 `size`**，整棵子树用 `FULL_RECT`/尺寸自适应，根 rect 实际为 `0×0` → 鼠标悬停永远落在空区 → `_gui_input` 永不触发 → 看似「不能拖」。

**修复**：新增 `_sync_root_size()`，在 `_build()` 与每次 `_apply_scroll_height()`（列表高度变化）时把根 `size` 同步为 `get_combined_minimum_size()`（≥80px 兜底）。根有了真实热区后，`_gui_input` 正常捕获左键拖拽、`_process` 跟随 `global_mouse_position` 移动、`_clamp_to_screen()` 夹在屏内、松开 `_save_position()` 持久化。`_make_drag_surface()` 仍让所有子节点 `IGNORE`、根 `STOP`，滚轮由根手动驱动滚动。

## 三、初始位置 = 状态卡 2 指头距离（用户明确要求）

- 旧默认 `(40, 240)` 改为按状态卡几何计算：`DEFAULT_POS = (状态卡左边 12, 状态卡顶 12 + 渲染高 318×0.667≈212 + 2×指头 16×2=32) ≈ (12, 256)`。即**正下方、左缘对齐、留 2 指头间隙**。
- 强化 `_load_position()`：读档坐标做合法性守卫（须为有限数且不显著越界），脏存档自动回退默认；`_ready` 后 `_clamp_to_screen()` 立即 + `call_deferred` 双夹，确保初始就在屏内。
