## 一、BUG 修复

### 1. 欢庆窗口只显示文字、不显示立绘（CG 视频不显示）
- **根因**：`celebrations.json` 里 `npc_su_waner` 的 `media_path` 指向 `.mp4` 文件。Godot 4 官方稳定版原生只支持 `.ogv`(Theora) / `.webm`，**`.mp4`(H.264) 需另行编译的 mpeg 模块，官方构建无法解码** → `ResourceLoader.exists` 通过但 `acquire_async` 返回 `null` → 媒体节点不建，只剩文字。另：原文件名 `1787996843939..mp4` 含双点笔误。
- **修复**：
  - `CelebrationOverlay._on_media_ready` 在资源加载失败 / 为空 / 非视频非图片时，**回退显示该 NPC 的半身立绘**（`_show_fallback_portrait`），保证窗口「有立绘可看」。
  - 修正磁盘文件名为 `1787996843939.mp4` 并同步 JSON 路径。
  - 后续美术导入 `.ogv`/`.webm`/图片即自动生效，无需改代码。

### 2. 对话框不显示 NPC 立绘
- **根因**：`DialogOverlay` 读取 `render.get("bust")`，而 `town_npcs.json` 的字段名是 `portrait`（玩家用 `bust`）。旧 `_resolve_bust` 对 NPC 已做 `portrait` 回退，但**大多数 NPC 根本没有 `portrait` 字段**（如猎户/长老/货郎），`beggar_face.png` 文件也缺失 → 立绘恒为 `null`。
- **修复**：新增统一解析入口 `DialogueService.resolve_half_body(npc_id, is_player)`，优先级 `half_body_portrait → portrait → bust`，三者皆空时**按 id 计算占位立绘路径** `res://assets/characters/half_body/<id>.png`（该文件由 `tools/gen_placeholder_portraits.py` 为所有 NPC 生成）。对话框、欢庆、NPC 面板统一复用。

## 二、半身立绘（占位 + 动态预留）

- **动态立绘预留**：`RomanceService.get_portrait_list` / `special_portraits.json` 的 `portrait_type` 字段支持 `static` / `frame`(帧动画) / `spine`(SK2D/Spine)，当前 `static` 生效，后续接入帧动画与骨骼分离立绘时按此接口扩展。

## 三、婘眷值（替换原「夫妻同心」）

- `RomanceService` 新增婘眷值：每配偶 `quanquan = {level, xp, unlocked_portraits}`。规则：
  - 1~10 级，每级 1000 经验（`QQ_MAX_LEVEL` / `QQ_XP_PER_LEVEL`）。
  - **仅婚后功能增加**：同游旅行 +5、寝欢(欢庆) +10、一家人协同出游(有子嗣) +15。
  - 每满 500 经验解锁 1 张特殊立绘（上限 20 张，`QQ_MAX_PORTRAITS`），广播 `bond_special_portrait_unlocked`。
- 配偶可在 **NPC 面板** 左右滑动查看已解锁立绘，勾选某张后对话框与该 NPC 属性面板切换为该形象（`get_active_portrait` / `select_portrait`）。
- 新增方法：`get_quanquan` / `add_quanquan` / `travel_together` / `family_outing` / `qp_get_level` / `get_portrait_list` / `get_selected_portrait_index` / `select_portrait` / `get_active_portrait`。
- 存档：`quanquan` 嵌套于 `spouses` 字典，`save()/load()` 已随 `spouses.duplicate(true)` 自动持久化。
