## 三、BUG 风险清单（按危险评级排序）

### 🔴 CRITICAL（1）

**BUG-01｜UIManager 缓存屏重开未回写屏幕栈 → 重开后键盘输入全失效**
- 位置：`autoload/ui_manager.gd:169-183`（缓存复用分支）对比 `:241-247`（close_screen 已 erase）、`scenes/ui/components/base_screen/BaseScreen.gd:112`
- 机制：`close_screen` 关闭时把屏幕从 `_screen_stack` / `_screen_layer` 移除并更新 `_current_screen`；但缓存屏重开（169-183）只 `visible=true` + 调 `_on_open/_on_reopen`，**不补回** `_screen_stack.append / _screen_layer[screen]=layer / _current_screen=screen`。
- 后果：重开的缓存屏（如 SaveLoadScreen、SettingsScreen）不在栈内 → `is_any_screen_open()` 误报 false；`BaseScreen.gd:112` 的 `_unhandled_input` 守卫 `get_current_screen() != self` 成立 → **键盘上下/确认/取消全部失效**，隐蔽且严重的功能回归。
- 修复：缓存复用分支末尾补三行（或合并 `elif` 逻辑），与首次打开路径一致。

### 🟠 HIGH（6）

**BUG-02｜open_screen 不防重复打开 → 实例叠加 + 信号双重监听**
- 位置：`ui_manager.gd:162-217` 无 `get_open_screen(name)` 校验；触发点 `:327` `_on_ui_action_requested` 直接 `open_screen`
- 后果：背包已开时再点"背包"会 `instantiate` 第二个 InventoryScreen 压栈，旧实例仍 `connect` 着 `inventory_item_added/removed` → 物品变动两实例各刷一次（叠加闪烁、焦点错乱），需逐个关闭才释放。
- 修复：`open_screen` 开头 `var ex = get_open_screen(name); if ex != null: ex.visible=true; return ex`

**BUG-03｜关系状态双写且不同步（脏档风险）**
- 位置：`services/bond/bond_service.gd:20-22,238,274,296`（自带 sworn/apprentices/masters 字典+方法）对比 `services/bond/relationship_service.gd:43,50`（只读 GameManager.sworn/master/romance_service）
- 后果：两条实现并存；走 `BondService.swear()` 时专用服务永不知情，关系图/UI 不显示，且该状态被 `save()` 写入存档（key="bond"）→ "已结义但游戏不认"的脏档。
- 修复：删除 BondService 内三套关系状态与方法，统一委托 SwornService/MasterService/RomanceService。

**BUG-04｜售卖锁定物导致银两凭空多出（经济漏洞）**
- 位置：`services/shop/shop_service.gd:109,114` 对比 `services/inventory/inventory_service.gd:267`（remove_item_by_id 跳过 locked）
- 机制：预检 `inv.get_item_count(item_id) < count`（含锁定物）；`remove_item_by_id` 跳过锁定实例、返回值被忽略；`ps.add_money(total)` 按全量 count 结算。
- 后果：5 个中 2 个锁定 → 卖 5 个只扣 3 个却付 5 个的钱，玩家白赚银两并保留 2 个锁定物。
- 修复：预检改用 `get_unlocked_count`，并据 `remove_item_by_id` 实际移除量计钱（或改用 `try_consume`）。

**BUG-05｜契约总表 docs/契约总表.md 已过期（High）**
- 位置：`docs/契约总表.md`（生成 2026-08-29）vs 契约源 `EventBus.gd`/`romance_service.gd` 等多处 08-30/08-31 后修改
- 后果：信号/方法已漂移，总表"代码是唯一真源，必须重跑"铁律被违反，跨 AI 协同易按过期契约改错。
- 修复：跑 `tools/gen_contract.gd` 重生成；建议在 CI 比对各契约源 mtime，过期即阻断合并。

**BUG-06｜WeddingScene 绕过回城钩子，跨场景资源未回收**
- 位置：`scenes/gameplay/bond/WeddingScene.gd:60-61` 直接 `change_scene_to_file(SCENE_TOWN)`，未走 `GameManager.return_to_town()`
- 后果：跳过 `ResourceManager.reclaim_all()`，CG/语音/立绘等温存资源不在婚礼→城镇边界统一回收，长期轻微内存累积。
- 修复：改为 `GameManager.return_to_town()`。

## 十、运行时冻结修复记录（2026-09-02 续）

### 现象
用户反馈点击主菜单「继续游戏」后游戏窗口冻结，截图停在「继续游戏」按钮界面。此前纹理压缩 freeze 已修复，但本次 headless 与 TownScene 单独加载均无法复现，说明是 GUI/场景树竞争相关的冻结。

### 根因
`MainMenu._continue_game()`、`DifficultySelect._proceed()`、`SaveLoadScreen._do_load()`、`EscMenu._load_game()` 等入口均遵循同一调用链：先 `UIManager.close_all_screens()` 批量 `queue_free()` 释放 UI 节点，再立即调用 `GameManager.load_game()` / `GameManager.start_new_game()`，其内部调用 `get_tree().change_scene_to_file()` 切换场景。由于 `queue_free()` 的节点删除与 `change_scene_to_file()` 在同一帧内竞争场景树，Godot 报告 `Parent node is busy adding/removing children` 并可能进入内部死锁/忙等，GUI 下即表现为窗口无响应冻结。headless 单测因无真实场景树竞争故不触发。

### 修复
- 文件：`autoload/GameManager.gd`
- 新增 `_deferred_change_scene(path: String)`：使用 `await get_tree().process_frame` 将 `change_scene_to_file` 推迟到下一帧，待 `queue_free()` 全部完成后再执行切换。
- 统一替换 10 处切场景入口：`load_game`/`start_new_game`/`start_battle`/`start_test_riverside`/`start_test_swarm`/`return_to_town`/`return_to_title`/`return_to_safe_point`/`goto_region`/`_on_bond_wedding_started`。

### 验证
- **GATE1**：headless `--quit`，0 SCRIPT / PARSE / COMPILE ERROR。
- **GATE2**：`tests/unit/run_all.tscn`，46 套件 / 0 失败 / 0✗。
- **专项验证**：临时场景在 `_ready` 中调用 `GameManager.load_game(1)`，此前必现的 `Parent node is busy adding/removing children` 报错已消失。
