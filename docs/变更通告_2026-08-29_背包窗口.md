# 跨窗口变更通告 · 2026-08-29 · 背包窗口

> 给其他 AI 窗口的通告：背包窗口本轮完成了一次评审 + P0/P1 修复落地。
> **动手前请先读本文件**，再按需读《docs/背包系统设计评审与实现方案.md》。

## 一、共享地基增量改动（均已向后兼容，不影响你已有代码）

| 文件 | 改动 | 对你的影响 |

| `autoload/EventBus.gd` | **新增** 2 个信号（未动任何已有信号）：`inventory_add_overflow(item_id, lost_count)`、`item_used(item_id, effect: Dictionary)` | 无破坏。想提示"背包满损失X"或"物品已使用"可自行 connect |

## 二、背包窗口主权内改动（其他窗口请勿改这些文件）

- `services/inventory/inventory_service.gd`：
  - 新增 API：`query_add`（纯计算预检，返回 `{added, overflow}`）、`can_add`、`try_consume(items, source)`（**两遍式原子扣料**）、`use_item(iid, context)`、`consume_instance(iid)`；
  - instance_id 改 `_next_iid` 发号器（格式 `item_id#N`），存档新增 `next_iid` 字段（旧档兼容）；
  - load 后强制重算负重（不信任存档 weight）。
- `services/shop/shop_service.gd`：buy 增满包预检 + 兜底退款（不再"钱扣了货没到"）。
- `services/forge/forge_service.gd`：产出预检 + `try_consume` 扣料 + `can_forge` 增加 `count` 参数（默认 1，不破坏旧调用）。
- `services/alchemy/alchemy_service.gd`：产出预检 + 原子扣料。
- `services/equipment/equipment_service.gd`：换装改"先抽新腾格→再卸旧退包"，满包不丢装备。
- `data/runtime/player_state.gd`：新增 `restore_mp(amount)`。
- `data/configs/items/*.json`：全量补 `flags`（丹药51/武器护甲67/材料19/demo玉佩3）。
- `scenes/gameplay/battle/BattleScene.gd` + `services/combat/combat_service.gd`：战斗内"物品"用药（`player_use_item` 作用于战斗快照，耗一回合）。
- `scenes/ui/overlays/inventory/InventoryScreen.gd`：按 item_id 聚合 + 消耗品"使用"按钮。

## 三、其他窗口写代码时的配合约定

1. **凡是"扣东西/发东西"的业务**（商店、锻造、炼药、任务发奖、掉落、回收）：扣之前先 `can_add`/`try_consume` 预检，**禁止**先扣后给且忽略返回值。
2. **消耗品判断**统一走：`type == "pill"` 或 `flags & ItemEnums.ItemFlag.CONSUMABLE`。
3. **战斗内不要直调** `InventoryService.use_item`（它会结算到 PlayerState，战斗面板不刷新、结算回写会覆盖）——走 `CombatService.player_use_item`。
4. 需要新的背包 API 先在本通告下追加约定，避免双窗口各写一套。
