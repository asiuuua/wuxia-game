# 剧情设计台 · 保姆级使用说明（给纯新手）

> 一句话看懂整套东西：**配好一段剧情 = ①管演员 → ②选演员 → ③写这段剧情 → ④看走向/自测 → ⑤画路线图**，五步全在一屏里做完。
> 本文档是「内容工作室」工具里《📖 使用说明》页的完整版，不需要懂程序也能照做，也能清楚现在哪些真能用、哪些还没接好。

---

## 〇、先去哪打开它

1. 双击 `tools/desktop_studio/studio_launcher.bat`（或 `python studio_server.py`），会自动打开浏览器 `http://127.0.0.1:8765/`。
2. 顶部导航里点 **「🎛 剧情设计台」**，就是融合好的三合一面板。
3. 顶部导航里的 **「📖 使用说明」**，就是这份说明的网页版。

> 如果界面还是旧的样子，在地址栏网址最后加 `?reload=数字`（数字随便换，如 `?reload=20260903`）强制刷新缓存。

## 一、这几个区块各是干嘛的（大白话）

| 区块 | 大白话 | 在游戏里对应什么 |
|------|--------|------------------|
| ① NPC 数据（演员编辑） | 管"人"本人：新建/删除、名字、站的位置、长啥样、多强、挂的 id。 | 每个角色的档案：id、名字、坐标、立绘、属性、对话/任务/战斗 id、好感、武学、背包 |
| ② 选演员（NPC） | 挑"现在要给谁写剧情"。 | 点哪个角色，中间就切到谁的台词，右边显示谁的走向 |
| ③ 写这段剧情 | 这位演员说的话、给你（玩家）的选项。顶部还能选任意对话 / 新建 / 删除。 | 点到这个人 → 弹出说话框 → 说几句话 / 给你几个选择 |
| ④ 看走向 & 自测 | 预览这一段任务怎么走，并一键检查有没有断掉。 | 决定"做完哪个条件，接下来发生什么"，像流程图一样的节点走向 |
| ⑤ 画路线图（任务流程图） | 像画流程图一样：拖方块、连线、改分支走向，存成任务图。 | 原「🗺 任务流程图」入口，已搬进本页，④ 预览用的就是这张图 |

> 以前的「剧情对话」「NPC 数据」「任务流程图」三个独立页，现在都并进这一个设计台了，不用来回切页签。

**为什么合并成一个台**：因为它们本来就是一条链——先有人（①），人才有位置/能力；挑中他（②），他才会说话（③），说了话才推任务走向（④），走向最终在流程图里排好（⑤）。以前分开管，小白容易找不到、填错地方；现在**同一屏、照着 ①②③④⑤ 顺序走下来，就算配好了一段剧情**。

## 二、怎么一步步操作（推荐只用「剧情设计台」这一屏）

### 第 1 步：① 管演员（NPC 数据）
- 最左列「① NPC 数据（演员编辑）」是"人"的档案：新建/删除演员、改名字/坐标/立绘/属性、填他的对话/任务/战斗 id。
- 上面是演员列表，点谁下面（那列里）就编辑谁；下面有「🗺 地图坐标预览」点一下地图可放位置，有「🧾 详细资料」管好感/武学/背包等。
- 平时只写剧情可以不用动这里；缺角色或要给人"配属性"才来这里。

### 第 2 步：② 选演员（NPC）
- 点「② 选演员」那一列列表里的一个角色（注意是 **② 列**，不是 ① 列的档案列表）。
- 该角色会用小标识显示绑定情况：`💬有对话`＝说话台词已配；`🗺有剧情图`＝任务图能查到；`✖无对话 / ✖未接任务`＝还没配。
- 选好后，③ 会自动带上这个人的对话，④ 会显示他的走向。

### 第 3 步：③ 写这段剧情
- ③ 顶部有个 **「选对话」下拉框**：会列出所有对话。① 在②选了演员会自动带上他的对话；② 也可以自己换个对话写，或点「＋ 新建对话」开一段、点「🗑 删该对话」删掉。
- 下拉框下面是台词编辑区：填**这句是谁在说、说了什么**（存一句点一下「💾 保存这句」）。
- 要分支就点「＋ 加选项（分支）」，填**选项文字**、**跳去哪一句**（jump_id），还可加条件（好感≥/flag 为真）。
- 还可填「下一句id」（空=本段结束）、「触发事件」（逗号分隔）。
- 以前独立的「剧情对话」页已合并到这里，不用再切页签。

### 第 4 步：④ 看走向 & 自测
- ④ 会自动预览这位演员绑定的任务走向（入口 → 对话 → 选择 → … → 结局），帮你"看见"整段流程。
- 点 **「🔍 自测当前」**，它会把台词和任务图**对照真实文件检查**一遍，告诉你有没有断掉：
  - 有没有"跳去一个根本不存在的台词/节点"；
  - 有没有"演员绑了对话 id 但文件里没建这段对话"；
  - 任务图的起点/连线引用是否完整。
- 有问题的条目会红色列出；能过的会绿色列出。

### 第 5 步：⑤ 画路线图（任务流程图）
- 在下面「⑤ 画路线图」：顶部**下拉框选一张任务图**，画布上能**拖动方块、点方块在右侧编辑、连线改分支走向**，改完点「💾 保存整图」。
- 保存前会校验"指向不存在节点的引用"会被拦截。④ 预览用的就是这张图。

### 怎么真的进游戏看
在 Godot 编辑器里运行项目 → 到城镇地图走到那个演员身边 → 点他说话 / 点「开始战斗」。

## 三、经实测：现在哪些真能用、哪些还没接好（2026-09-03 对照游戏源码得出）

**✅ 真能用（进游戏确实会跑）**
| 东西 | 依据 |
|------|------|
| NPC 摆到地图上、点他能开口对话 | `TownScene.gd` 读坐标摆人，点他按 `dialog_id` 开对话框 |
| 对话顺着说（next_id 一直接下去） | `DialogueService` 按 next_id 推进 |
| 选项跳转（jump_id） | 选了某个选项 → 跳到对应那句 |
| 对话选项的"好感≥ / 持某物品 / 任务激活中"三种条件会过滤（不满足就不显示该选项） | `DialogueService._check_condition` |
| 对话里点「开始战斗」能进真实战斗 | `DialogOverlay` → `CombatService.start_combat` |
| NPC 详情面板显示等级/攻击/气血/武学/送礼偏好 | `NpcPanelScreen` 读 `npc_stats.json` |

**⚠️ 部分能 / 有缺口**
| 东西 | 现况 |
|------|------|
| NPC 属性（攻击/气血/等级） | 只在详情面板**显示**，**不进入战斗数值**（战斗用另一套 battle/enemy 配置） |
| 剧情图里的发物品 / 记好感 / 记 flag | 节点写进去了，但游戏侧**没有 handler 落库**，画了不会真发物品/真记好感 |

**❌ 完全没接进游戏**（画了存了，游戏不会按它走）
| 东西 | 原因 |
|------|------|
| 任务流程图 `QuestGraph` | 引擎脚本写好了，但**游戏主流程从没调用它**（只在单元测试里用过）；而且它期望的数据层级和实际 quests.json 也对不上（`quest_graph.nodes` 会读成顶层 nodes）、`then_set` 那种写法它不认识、默认不落存档 |
| 对话文本多语言 | 台词是**直写中文**，没走 i18n 文案表，切语言还是中文 |

**实测发现的数据错位（值得注意的真实问题）**
- **村长老头**：给他写了整整 6 句的分支对话文件（`npc_village_chief`），但他的 NPC 记录里 `dialog_id/名字/坐标` 全是空的——所以进游戏**点他没有任何事发生**。他是个"有台词但没接上"的演员。
- **好几个 NPC 的 `quest_id`**（`demo_quest`、`q_bandit_001`、`q_wolf_001`、`q_sect_join_001`）在任务流程文件里**一个都找不到**（里面目前只有 `nv_qg_demo` 一张图），所以这些任务 id 属于"挂了号但没图"。

> 想自己在工具里验证上面这些？就在剧情设计台点不同演员看左侧的 `💬/🗺/✖` 标识，再点「🔍 自测当前」。

## 四、想继续往下做：改什么、先改哪个（按紧迫度排序）

**P0 先把"画了能跑"的根打通（游戏侧）**
1. 游戏主流程真正调用 `QuestGraph.run()`，并接上 handler：
   - `dialog` → 真正开对话；
   - `battle` → 真正开战斗，打完按 `on_win/on_lose` 把控制权交回流程图；
   - `give_item` → 真正发物品进背包（`InventoryService.add_item`）；
   - `flag / favor` → 真正写进存档的全局状态（`GameState` / `BondService`）。
2. 让 `QuestGraph` 读对层级（读 `quest_graph` 子对象）、兼容 `then_set` 的 Map 写法、并默认使用**持久化 store**（现在默认是内存，关游戏就丢）。

**P1 让两套逻辑并轨 / 换语言**
- 把战斗判定用的 battle_id 和任务的 objective 目标统一，避免"打赢了却记不上进度"。
- 对话文本与选项改走 i18n（`key + tr()`），多语言只加一张表。
- 剧情图的分支（choice）如果要"玩家点选"，需要补点击界面；现在它是服务端自动走第一个符合条件的。

**P2 打磨**
- 补上被写好了台词但没接线的村长老头的 NPC 记录（名字/坐标/`dialog_id`）。
- NPC 属性（攻击/气血）接进战斗，而不是只在面板摆个数字。
- NPC 详情的切磋/送礼/查看背包按钮补成真功能（现在是预留）。

## 五、后期可维护性和安全性怎么看

**可维护性**
- 现在其实是**两套任务推进体系**并存（旧的 `objectives`／新的 `quest_graph`），容易"同一条任务两条线"。建议明确：传统任务走 QuestService、剧情图任务走 QuestGraph，入口唯一。
- 状态来源分散：全局 flag、好感、任务进度各存各的。建议统一收口到 GameState（它已有 `global_flags` 接口）。
- 对话文本不 i18n，以后要出英文版就得全部手改。建议尽早统一成 `key + tr()`。
- `QuestGraph` 已有 `MAX_STEPS=800` 防死循环，但缺"一键校验节点引用完整性"，建议把编辑器"保存即校验"（本工具自测已提供同一类检查）。

**安全性**
- 外部的 JSON 配置会直接进游戏运行时逻辑：配置坏了可能丢节点/丢分支，但有 `MAX_STEPS` 兜底，不会死循环卡死。
- 存档用 `user://saves/`、按 `save_*.json` 命名，暂没发现路径穿越或跨档覆盖问题，属于低风险。
- 本工作室工具的接口只放行本机来源（防别家网页偷发指令），并有"删除进回收站 + 写前备份 + 操作日志"，误删可找回。

## 六、最省事的日常用法（背这 5 条就够）

1. 开工具 → 点「🎛 剧情设计台」。
2. ① 点一个 NPC → ② 填他说的话并 💾 保存（要分支就「＋ 加选项」）。
3. ③ 看右边走向预览，点「🔍 自测当前」确认没断。
4. 看到红色=有坑（对照本文第 3 节判断是真不能用，还是需要专人改游戏侧）。
5. 需要改游戏代码的项（P0 列表），把话转给"负责游戏侧"的窗口派单处理，工具这边已给出应改的文件与函数。
