# 05 · 战斗系统：逻辑内核 + 战术战棋（逻辑/视图接缝）

> 检索关键词：战斗、回合制、战棋、ATB、CombatCore、CombatService、网格、接缝、TacticalBattleScene
> 等级：E2

## 真源
`services/combat/combat_core.gd`（607 行）、`combat_service.gd`（500 行）、`scenes/gameplay/battle/tactical_battle_scene.gd`、`battle_grid_node.gd`、`core/combat_event_renderer.gd`。

## 分层与职责
- `CombatCore`（逻辑内核，`RefCounted`，**不持有 Node**）：接管原 `BattleScene` 流程编排（攻击→敌人回合→判胜负→结算），逻辑算完吐事件，不再一帧跑完。
- `CombatService`（门面）：从 `ConfigManager.get_battle` 读 JSON 构建 `CombatState`；难度倍率经 `DifficultyManager`（代码零 `if` 难度判断）；把战斗委托 `CombatCore`。
- `TacticalBattleScene` / `BattleGridNode` / `BattleEntity`（视图层）：等轴测战场绘制、HUD、输入状态机、演出；**不持有任何战斗逻辑**，伤害结算永远走 `CombatCore`。

## 回合制模型（ATB）
- `speed` 由 `agility` 派生驱动行动顺序；双资源 `hp`+`mp`；招式分阶 + 冷却 + 状态；真实状态引擎（层数/持续/每回合生效/属性修正）；**确定性随机**走注入 `SeededRNG`，同 seed 同结果（可存档/回放/单测）。

## 战术战棋网格（逻辑/视图接缝）
- 逻辑层：`CombatCore` 经 EventBus 派发 `grid_highlight_update({type:Array[Vector2i]})`（0 蓝可移/1 绿威胁/2 红技能范围）、`grid_unit_moved(unit_id, from, to)`。
- 视图层：`BattleGridNode` 用 `_draw()` **程序化绘制 45° 等轴测菱形网格**（不依赖 TileSet，headless 可编译）；连接 `grid_highlight_update` 刷新高亮；`cell_center`/`world_to_grid` 反算坐标供点击拾取；地形用 `MultiMeshInstance2D` 单 draw call。
- 输入状态机：`IDLE → 选行动 → AWAIT_TARGET → 结束回合`；自动战斗「走近最近敌人→普攻」带回合上限防死循环。

## 接缝铁律（高频坑）
战斗内高频有序流走**返回值** `Array[CombatEvent]`（不走 EventBus，避免信号刷屏）；只有跨模块通知（`combat_finished` NOTIFY）与网格视图更新才走 EventBus。

## 解决什么
- 去「战斗直调任务」反模式：`combat_finished` 发完即结束，由 `GameManager` 连线 `quest_service._on_combat_finished` 推进任务（事件闭环）。
- 去硬编码：难度/属性派生全走配置 + `DifficultyManager`，无魔法数。
- 去场景耦合：逻辑纯 `RefCounted`，切场景存活、可单测注入固定 seed。

## 隐患
- 视图层 `Tween` 与逻辑帧需对齐；网格几何依赖 `town.json` 底图（误删 = BUG-14）。
- `battle_entity.gd` / `battle_grid_node.gd` 属战斗窗主权，跨窗只派单不直改。
