# 07 · 双闸门门禁（GATE1 + GATE2）

> 检索关键词：门禁、双闸门、GATE1、GATE2、headless、run_all、零错误、非绿即阻断、回归

## 是什么
双闸门是工程**提交前强制回归门禁**，任何改动（含文档/配置误伤）都须全绿才能合并。

## GATE1 —— headless 零错误
```bash
# Godot console 版（有 stdout，推荐做解析）
"<godot_console>" --headless --path "<project>" --quit 2>&1 | grep -iE "SCRIPT ERROR|Parse Error|Compile Error"
```
- `--quit` 跳过主场景逻辑但仍执行 import 与 autoload 解析，能捕获 99% parse/compile/runtime 错误。
- 配合 `grep` 列出所有错误；**零匹配 = 通过**。
- ROOT 必须 Windows 风格路径；`.godot` 缺失 = 全崩，验证前须 import 完成。

## GATE2 —— 单测零 ✗
```bash
"<godot_console>" --headless --path "<project>" res://tests/unit/run_all.tscn 2>&1 | grep -iE "套件：|✗ "
```
- 跑 `run_all.tscn` 全部单元测试；判绿须**同时满足**：失败套件数 `M == 0` 且 `✗ == 0`。
- 当前实测：53~55 套件 · 失败 0 · 0✗。

## 铁律：非绿即阻断
- 任一门禁红 → **禁止提交**，先修到绿。
- 红门禁常是「别人刚改崩」信号（如某窗口未提交的 preset 改动），按主权边界**跨窗只派单（handoff）不直改**，待对方修绿。
- 例：本工程曾因战斗窗未提交的 `preset_12x12.json`（11x5→12x12）致 `test_studio_preview_uses_preset_layout` 失败；由架构窗从测试侧（治理域）对齐断言 11x5→12x12 解决，严格不碰战斗窗预设文件。
