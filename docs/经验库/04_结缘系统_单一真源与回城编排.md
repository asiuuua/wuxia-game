# 04 · 结缘系统：单一真源 + 纯聚合门面（回城编排）

> 检索关键词：结缘、好感、姻缘、配偶、结义、师徒、关系网、单一真源、BUG-03、BUG-10、RelationshipService

## 真源
`services/bond/bond_service.gd`（267 行）、`romance_service.gd`（536 行）、`relationship_service.gd`（226 行）、`sworn_service.gd`、`master_service.gd`。

## 核心模式
**状态下沉为唯一真源** + **纯聚合门面**对外拼关系图（回城编排）。

## 分层
- `BondService`（好感度**单一真源**）：好感度/等级/送礼/好感事件；`relations.json` 驱动。注释明确「结义/师徒已下沉至 `SwornService`/`MasterService`（唯一真源），本服务仅管好感度，不再持有关系字典，避免双写不同步+脏档（BUG-03）」。
- `RomanceService`（配偶名单**单一真源**）：只读 `BondService` 好感度不重写；`spouses` Dict 存配偶/阶段/子嗣/孕期/婘眷值；`propose` 事务式扣聘礼；`celebration_quotas` 与 `spouses` 解耦。
- `RelationshipService`（**纯聚合门面**，无状态/不进存档）：把 `BondService`+`RomanceService`+`SwornService`+`MasterService` 拼成统一关系图，供关系网视图/右上角姻缘按钮消费。

## 关键实现（代码技术）
1. **单一真源防脏档**：好感度只在 `BondService`、配偶只在 `RomanceService`、结义/师徒在 `Sworn`/`Master`；查询走 `RelationshipService` 聚合，不各自持有副本 → 根除 BUG-03。
2. **事务扣聘礼**：`propose` 逐项 `remove_item_by_id`，`deducted` 记录已扣，失败回滚 `add_item(dowry_rollback)`。
3. **单一判定源**（BUG-10）：`can_propose` 与 `propose` 共用 `_dowry_satisfied`，按钮禁用与点击拒绝一致。
4. **可扩展性**：`relations.json` 一次铺齐 M2+ 字段；`RelationshipService._node_of` 补两个状态来源即自动含结义/师徒，**UI 零改**。
5. **解耦时间源**：`advance_days(n)` 由 `TimeService`/休息动作喂天数，子嗣链（怀胎 300 天 → `_birth`）数据层预留。
6. **静态配置缓存**（BUG-21）：`special_portraits.json` 解析结果 `_special_portrait_cache` 缓存，避免每次取立绘重读盘。

## 解决什么
- BUG-03 关系双写脏档：状态下沉唯一真源，彻底消除双写不同步。
- BUG-10 求婚判定分叉：`can_propose`/`propose` 共用 `_dowry_satisfied`。
- 跨模块只走 EventBus + 读公开方法（`RomanceService` 读 `BondService` 不碰私有成员），符合铁律。

## 隐患
- `get_all_relation_ids` 全量遍历（N 小可接受）。
- 欢庆/受孕状态存 `spouses` 随存档；`celebration_quotas` 须同步 `reset`（已做）。
- 婚礼演出依赖 UI 监听 `bond_wedding_started`（场景缺失仅提示，不崩）。
- `services/bond/**` 属结缘窗主权，跨窗只派单不直改。
