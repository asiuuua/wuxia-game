# 00 · 架构铁律与分层

> 检索关键词：架构、分层、单向依赖、铁律、规范、autoload、services、RefCounted
> 等级：E1

## 项目定位
- 等距 2.5D 武侠 RPG 单机；Godot **4.7.2**；纯 GDScript；个人开发（新手友好）。
- 规模（实测）：201 个 `.gd` / 49 个 `.tscn` / ~35,000 行；战斗回合制 + 自动；平台 Win + 安卓；世界区域枢纽式。

## 分层与单向依赖（铁律）
```
autoload → core → data → services(RefCounted) → scenes → resources/tests/tools
```
- 依赖只允许**向下**，禁止回环；跨模块通信只走 `EventBus`。
- `autoload`：17 个全局管理器（GameManager / EventBus / UIManager / GameState / ConfigManager / SaveManager / DifficultyManager / PlayerState 等）。
- `core`：基础设施（ISaveable / ItemInstance / CombatEvent / GameLogger 等）。
- `services`：14 个业务域，全部 `RefCounted`（**不持有任何 Node**），可单测、切场景存活。
- `scenes`：视图/玩法场景；`data`：JSON 数值；`resources/tests/tools`：资源/单测/工具。

## 四底线
1. **单向依赖**：上层可依赖下层，下层绝不反向依赖上层。
2. **跨模块只走 EventBus**：模块间不直接持有对方引用调用逻辑（经 GameManager 取服务实例除外）。
3. **数值全进 JSON**：任何可调数值（价格/配方/难度/属性派生）进 `data/configs`，禁止代码硬编码魔法数。
4. **命名见名知意**：类名/方法/信号/字段一眼可读；私有成员前缀 `_`。

## 三类核心角色
- **GameManager**：装配中枢（DI 容器），持有并注入各 service 实例，是场景切换/读档/写档的统一入口。
- **EventBus**：跨模块唯一信号通道（100 信号，NOTIFY/CMD 分离）。
- **GameState / SaveManager**：存档唯一来源，各 service 实现 `ISaveable` 的 `save()/load()`。

## 主权边界（多 AI 协同防互踩）
UI 窗口 `scenes/ui/**`、战斗窗口 `scenes/**/battle*`、背包窗口 `services/inventory`、结缘窗口 `services/bond` 各有主权；跨窗**只派单（handoff）不直改**。

## 常见踩坑
- 在 `services` 里写 `Node` 引用 → 切场景即失效；逻辑必须纯 `RefCounted`。
- 数值硬编码在 `.gd` → 调平衡要改代码重打包；应进 JSON。
- 跨模块直接调用对方私有方法 → 破坏单向依赖，门禁/测试难覆盖。
