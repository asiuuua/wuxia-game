桌面端 · 多人协作 · 可扩展工坊改造方案

从「本地单机 Web 工具」演进为「纯 Windows 桌面应用 + 多人远程协作 + 插件可对接」 · 2026-09-03
给外行的一句话总纲：想做的事要拆成四根柱子管——① 桌面外壳、② 多人同时编辑、③ 别人可对接（插件化）、④ 不崩溃。四根里，桌面外壳几乎免费（现在已是 exe），多人协作是唯一要正规设计的大工程，插件化靠"标准接口"，不崩溃靠"分层 + 备份 + 隔离"。下面一根一根说清。

1. 先破除一个误解：桌面化最容易，多人协作才最难

你已经有一只脚迈进门了。你的工具里已有 build/工作室专业调教/*.spec——那是 PyInstaller 打包出来的 exe，它现在已经是个可双击的 Windows 程序。
  • 所以第①根柱子"桌面化"不是新工程，而是"把现在这个 web 工具包一个正式窗口外壳"，换个壳而已。
  • 真正难、唯一要用心设计的，是"几个人同时改同一个任务文件，还不互相盖掉对方"。这是第②根柱子，是整件事的天花板。
💡 顺序别乱：先搭稳单机桌面化 + 插件框架，最后再开多人并发，否则两边都做不好。

2. 现状盘点：你现在手上有什么

现在意味着
后端 Python 标准库 http.server+Threading，已处理一堆 /api/*逻辑成熟，能整体复用，别重写
前端单文件 index.html，原生 JS，零依赖画面和操作都在这里，桌面化直接复用
PyInstaller .spec 已能打 exe桌面入口已存在，只差"窗口体验"
已有一堆保险：备份、回收站、日志、路径穿越防护第④根柱子的地基已有一半

3. 四根柱子逐一设计

柱 ①　桌面外壳（纯 Windows 桌面应用）

目标：双击打开是一个有独立标题栏/菜单的真实窗口，不是浏览器标签。

方案简述体积/门槛评价
A · PyWebview（推荐）Python 起一个"系统内嵌浏览器"窗口，本地起服务、窗口加载你的 index.html打包 ~40–60MB，不用学新技术✅ 最贴现在：Python 后端全保留，前端一行不改
B · ElectronChromium 全家桶 + Node，包一层~150–250MB，内存高功能最全但"杀鸡用牛刀"，后端还得从 Python 换 Node
C · TauriRust + 系统 Webview，极轻~8MB，但要会 Rust，后端要重写最轻，但迁移成本最高
建议选 A（PyWebview）：把 studio_server 稍作整理后用 PyWebview 起本地服务并开窗，现有 index.html 和 studio_core 全部复用，最平滑。

柱 ②　多人远程同时编辑（真正的大工程）

先诚实摆清 tradeoff："多人同时编辑"有两种层次，天差地别——

层次什么样体验代价
轻量（务实，推荐先做）编辑前先取最新版；保存时服务器比对——若别人在你之后改过同一文件，提示"有更新，请刷新合并"，不让直接覆盖略多一步"刷新"低、可靠、够用
重量（实时协同）像腾讯文档：两人同改一个节点像实时打字一样合并最爽极高（OT/CRDT 算法+传输协议），独立大工程
💡 对"任务/数值编辑器"这种低频、结构化、按文件编辑的场景，强烈建议走轻量版：乐观锁 + 版本号 + 冲突提示。先别追腾讯文档级实时，那是给自己挖坑。

实施要点（轻量版）

  • 引入一台服务端：把"读本地 JSON 文件"抽成一层"数据访问接口"，底层可切：本地文件 → SQLite → 远程服务器数据库。前端代码基本不变。
  • 每个文件带 version；保存带 base_version，服务端比对，不一致则拒绝并返回冲突。
  • 加简单鉴权（网内账号/口令）+ 操作日志（谁何时改了哪）。
⚠️ 若将来真要求"两人同改一个节点实时无损合并"，那是独立的、以月计的算法工程。建议永远放最后、当可选增强，别当第一个目标。

柱 ③　别人可对接（插件化 / SDK）

目标：别人下载你的主程序，不改你核心代码，只放一个"插件文件夹"就能对接自己功能，互不干扰、坏了不影响主程序。

// 一个插件长这样：plugins/<plugin_id>/ |-- manifest.yaml // 插件身份证：声明页签、后端接口、依赖哪些数据表 |-- handlers.py // (可选)后端逻辑：暴露若干 handler 函数 |-- panel.js // (可选)界面加一个自己的页签 `-- assets/ // (可选)自己的图标/图片
// manifest.yaml 样例 plugin_id: my_prefab // 全网唯一命名，避免和别人的冲突 display_name: 预制体速查 version: "1.0.0" main_backend: handlers.py // 后端入口 tabs: // 要往主界面加的页签 - key: prefab label: 预制体 entry: panel.js data_schemas: [ "regions/*/quests.json" ] // 声明要读写哪些表(供鉴权/冲突检测)

主程序怎么做插件化（关键设计）

  • 启动扫描：启动时扫 plugins/，读每个 manifest.yaml，把插件页签注入界面、把插件 handler 注册进路由。
  • 后端注册表：主程序维护一份"路由表 URL → handler"；插件往表里挂自己的 handler，不碰别人已有的。
  • 前端容器：主页面只留一个"页签容器"，插件页签载入它自己的 panel.js，index.html 本体不被改。
  • 插件隔离：插件 handler 用 try/except + 超时包裹；崩溃只回滚该插件，不影响主程序（见柱④）。
  • 写一份开发者文档（SDK 说明：怎么写 manifest、怎么注册接口、命名规则），别人照着做即可。
这样"别人下载后对接自己功能"就成立：他把自己的 plugins/我的功能/ 整个文件夹拷进来、重启，就有自己专属的页签与接口，跟你互不干扰。

柱 ④　不崩溃与可恢复

  • 分层：UI(窗口) / 核心服务 / 存储 三层分离。窗口崩了能重启，不丢内存外数据。
  • 原子写：写文件先写临时文件再改名替换（tmp → rename），断电 / 写一半也不会留下半个文件。
  • 自动备份：每次改动前备份上一版（你已有 safety_data/backups，保留并强化），一键回滚。
  • 崩溃恢复：启动时校验数据完整性，发现损坏自动回退到最近备份并提示。
  • 插件隔离：插件错误捕获 + 超时 + 资源限制，坏插件只影响自己。
  • 统一日志：所有操作进 studio_log.jsonl（已有），出问题查得到时间线。

4. 分阶段演进路线（不推翻现有，每步可验收）

阶段干成什么要不要新依赖验收
P1桌面化：PyWebview 起窗，双击变真实应用PyWebview（打进 exe）双击打开独立窗口，功能与现在一致
P2抽数据访问层：把"读写文件"抽象成接口（本地文件实现先行）无现有功能不回归，接口可替换
P3轻量多人：SQLite + version + 冲突检测 + 网内鉴权 + 操作日志SQLite(内置)两人同时改同文件不会互相覆盖，能提示冲突
P4插件化：manifest 扫描 + 后端注册表 + 前端容器 + 隔离 + SDK 文档无写一个示例插件即能被主程序加载，坏插件不影响运行
P5(可选)实时协同 / 完整远程：真正的多人实时无损合并 / 云部署大腾讯文档级体验（很长的一段路）
💡 为什么这个顺序：桌面化先给"正式产品形态"；数据访问层是"多人"和"插件"共同的地基（它们都依赖"数据不是硬编码读文件"）；多人放插件前（P3 先于 P4），因为"多人冲突检测"和"插件数据写入"共用同一套"按文件+版本"框架。若你只抢核心，先做 P1+P2 就立刻受益。

┌─────────── 你(或别人)的 Windows 桌面 ───────────┐ │ 窗口外壳(PyWebview) │ │ ┌─ index.html 主界面 ─┐ 插件页签(panel.js) │ │ │ 页签容器 │ ───────────── │ │ └─────────┬───────────┘ │ │ │ HTTP(localhost) │ │ ┌─────────▼───────────────────────────────┐ │ │ │ 核心服务(Python) │ │ │ │ /api/* + 插件 handler(注册表) │ │ │ └─────────┬───────────────────────────────┘ │ └─────────────┼───────────────────────────────────────┘ ▼ 数据访问层(Data Layer) ← P2 抽的接口 本地文件 ─── SQLite ─── 远程服务器(多人, 版本+冲突检测)

6. 风险与注意

  • 别在前期就追"腾讯文档级实时"——那是整件事里唯一的高危大坑，留到最后的 P5 可选。前期用乐观锁完全够。
  • 后端别重写：现有 studio_core/studio_server 成熟，桌面化靠 PyWebview 复用，不推倒。
  • 多人不等于"必须联网外网"：局域网(办公室同一 WiFi)就能多人，不必上公网服务器。
  • 插件命名规范：manifest plugin_id 要求全局唯一前缀，杜绝互相撞车。
  • 安全：多人开启后，本地接口别裸暴露公网；持久则加鉴权与 HTTPS，沿用你已有的路径穿越防护。
结论一句话：桌面化用 PyWebview 最快落地；多人用 乐观锁 + 版本比对 最务实（腾讯文档级永久可作远期彩蛋）；插件化靠 manifest + 后端注册表 + 前端容器 + 隔离 实现"别人拷个文件夹就能对接"；不崩溃靠 分层 + 原子写 + 备份恢复 + 插件隔离。四根柱子 P1→P4 逐段验收，现有代码整体保住。
