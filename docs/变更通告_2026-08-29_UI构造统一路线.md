# 变更通告 · UI 构造统一路线规范（2026-08-29）

## 1. 变更概述
- **类型**：架构决策（ADR）规范 / 设计基线新增
- **窗口**：UI 窗口（主权内）
- **性质**：无生产代码改动，纯规范 + 文档落地；为后续 HUD 重构、新屏/新组件登记提供**统一构造路线裁决**
- **关联派单**：无（纯规范，不触发跨窗 emit 改动）

## 2. 背景与动机
此前「编辑器静态装配 `.tscn` 当 HUD 主模式」与「本项目全屏屏 `script.new()` 代码构建」路线未统一，属 PM 待拍板决策。经三视角评估（设计哲学 / 代码工程 / 安全严谨），结合本仓「代码主导 + 多 AI 并行同分支 + 配置驱动」的团队拓扑，拍板如下。

## 3. 决策结论（一句话）
- **全屏界面屏** → 保持 `script.new()` 代码构建（`open_screen` + `screens.json`）。
- **HUD 顶层面板** → 代码构建 `Control` 子类 + `setup()` 门面（沿用 `Hud.tscn` 壳 + 代码建内部 先例）。
- **HUD 叶子组件** → 优先 `.tscn` 预制（高复用纯展示件，preload 收益最大）。
- **核心判句**：机制服从团队拓扑，纪律重于机制——混合流派允许，但统一纪律对全部组件强制生效。
