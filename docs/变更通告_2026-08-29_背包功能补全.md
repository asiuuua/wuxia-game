## 一、补全清单（对照《背包系统设计评审与实现方案.md》）

| # | 功能 | 文件 | 说明 |
|---|---|---|---|
| 1 | `add_items(list, source)` 批量事务 | inventory_service.gd | 聚合同 item_id 需求，先 `can_add` 预检全部能装下才逐个 `add_item`；任一装不下整体返回 false、一个不加（原子） |
| 2 | `drop_item(iid, count)` 主动丢弃 | inventory_service.gd | 玩家手动丢垃圾；校验 `ItemFlags.is_discardable`、拒绝锁定实例（返回 LOCKED）；返回 `{ok,reason,item_id,dropped}` |
| 3 | `get_free_capacity(bag_type)` / `get_weight_ratio()` | inventory_service.gd | 分栏剩余空槽查询 + 负重比 0~1+（UI 进度条直接乘 100） |
| 4 | `ItemFlags` 静态类 | core/item_flags.gd（新） | 消除裸 `(flags & 16)` 位运算，提供 is_discardable/is_sellable/is_stackable/... 纯函数；自包含掩码常量 |
| 5 | `ItemInstance.serialize` 加 `ver` | item_instance.gd | schema 版本钩子（`SCHEMA_VERSION=1`）；deserialize 旧档缺省兼容 |
| 6 | `use_item` 按 `kind` 分发 | inventory_service.gd | heal/buff/cure/exp 分发；当前库仅 heal 有效，buff/cure/exp 留安全框架（未配置数据返回 NO_EFFECT 且不消耗） |
| 7 | `InventoryTransaction` 批量事务 | services/inventory/inventory_transaction.gd（新） | 收集 add/remove/consume 操作，commit 时各段原子应用（remove→try_consume、add→add_items、consume→consume_instance） |

## 四、踩坑记录（供复用）

1. **新增 `class_name` 必须重建全局类缓存**：`ItemFlags` / `InventoryTransaction` 两个新 class_name 加入后，`--quit`/`--check-only` 不重建 `.godot/global_script_class_cache.cfg`，导致 autoload 依赖图报 `Identifier "ItemFlags" not declared`。修复：跑一次 `--editor --quit` 重建缓存后再验证。
2. **`expect_eq` 的 String 比较触发 GDScript 4.7 类型严格推断**（"should be int but is String"）：字符串断言改用 `expect(a == b, msg)`。
3. `ItemFlags` 自包含掩码常量（不跨脚本引用 `ItemEnums` 枚举），规避 Godot 4 class_name 依赖图在 autoload 编译期的注册顺序问题。

## 五、影响面 / 主权边界

- 背包数据层核心功能至此全部做完（增删改查、堆叠、负重、锁定、容量、事务扣料、使用、排序/拆分/移动、团灭配置化、信号清理、count 缓存、槽位保真、iid 发号、存档 roundtrip + 本次批量添加/主动丢弃/便捷 API/use 分发/事务类）。
- 不动其它窗口主权；`InventoryTransaction` 仅作为编排层复用既有 `try_consume`/`add_items`/`consume_instance`，未改其逻辑。
