## 一、已完成的整改（UI 窗口主权）

### 1. 信号/处理器参数对齐（真实崩溃隐患，已修）
Godot 4.x 中，信号发射 N 个参数时处理器必须能接住 N 个，否则运行时抛
`Method expected K argument(s), but called with N`。本项目此前已在 `InventoryScreen._on_inv_changed`
踩过一次。本次全量扫描又抓到同类隐患：

- `AttributesScreen._on_changed` 原 `_p: Variant = null`（最多接 1 参），但连了
  `player_hp_changed`(2) / `player_mp_changed`(2) / `player_money_changed`(3) → 玩家一掉血/花钱就崩。
  **改**：`func _on_changed(_a=null, _b=null, _c=null)`（最多接 3 参）。
- `Hud._refresh` 原 `_p: Variant = null`（最多接 1 参），但连了
  `player_hp_changed`(2) / `player_mp_changed`(2) / `player_exp_changed`(2) / `quest_objective_updated`(3)
  → HUD/任务追踪一刷新就崩。**改**：`func _refresh(_a=null, _b=null, _c=null)`。

两处均为"参数签名扩展"，无行为变更，纯兜底防崩。

### 2. 门禁工具（新增，纯增量）
- `tools/gate_check.sh` — ERROR 感知的三闸门：
  - [1] `--quit` 零 `SCRIPT/PARSE/COMPILE` 错误；
  - [2] `run_all` 失败数=0 **且** `ERROR:` 行全部命中白名单（负向测试预期错误不算）；
  - [3] `inventory_smoke` 输出含 `ALL_INV_OK`。
  - 注：Godot headless 输出**不能直接 `> file` 或 `$(...)` 捕获**（会丢），必须走管道；脚本已全程用管道。
- `tools/gate_allowlist.txt` — gate 的"预期 ERROR"白名单（6 条负向用例特征串）。
- `tools/wip_check.sh` — 在途 WIP 守卫：列出未提交且触碰共享/跨窗口配置（autoload/core/data/configs/services）的文件，提交前预警并发编辑踩踏。
- `tools/signal_audit.py`（v4）— 信号连接 vs 处理器参数个数全量扫描器。已修三处扫描器自身 bug：
  默认参判定（`=` 不在 `:` 前段）、跨文件同名方法碰撞（优先本文件解析）、`.bind()` 括号截断（改括号配对读取）。
  当前扫描结果：**仅 1 个真崩（跨窗口，见下）**，其余均为扫描器早期版本的误报（已归零）。

这正是审查里标 🔴 的"多窗口并发改同一文件 / WIP 长期不提交"隐患的实时发生。
**修复（背包窗口主权，交背包窗口执行）**：在 `bond_service.gd` 第 20 行那个空函数体加 `pass`（或补实现）。
