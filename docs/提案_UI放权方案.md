# 提案：UI 模块「放权给工作室平台」方案（小白零代码开发）

> 窗口：UI ｜ 日期：2026-09-02 ｜ 状态：方案已整理，待分阶段落地
> 定位：本提案只解决"哪些 UI 外观/布局可安全地交给非技术用户在工作室平台改"，不涉及任何游戏逻辑改动。

---

## 一、背景与定位

用户希望小白在工作室软件里实现**真正的一键拖拽、0 成本、无代码开发**：从改图标、菜单框/弹窗大小、背景替换，到后续 UI 分层视觉（骨骼动画、视频、流动烟雾、水面流动等）。

关键事实：**游戏侧早已是「读 JSON 配置 → 应用 → 缺省回退」模式**（实证于 `scenes/ui/screens/main_menu/MainMenu.gd`）：

- `main_menu_assets.json`：标题图/按钮图/5 图标路径，上传即生效；
- `main_menu_layout.json`：主菜单各元素 anchor + offset，工作室拖拽写入；
- `login_bg_layout.json` + `UIBackground`（含 `leaves_enabled` / `scrim_alpha`）：背景参数外置；
- `ui_sfx.json`：音效 path 替换，零代码；
- `tscn_assets.py`：UI 贴图直写 `.tscn`（不写 uid、不预生成 .import）；
- MainMenu.gd 已含 `CPUParticles2D` 飘叶 + 云/水/船补间 —— **特效代码已存在，只差把写死数值外置成可配参数**。

所以"放权"不是从零造，而是**把主菜单已验证的通道推广到所有 UI 屏 + 把硬编码参数外置成"预设库"**。

---

## 二、放权总原则

1. **平台=连接器非容器**（`wuxia_game.yaml` 已拍板）：小白只改**数据**（JSON / 资源文件），绝不碰**代码**（`.gd` 逻辑）。
2. **游戏侧只做"装载"**：每个屏构建时读一份 skin 配置并应用；读不到就用内置默认 → **永不崩溃**。
3. **开发者只维护"预设库"**：特效/动画做成预授权资产，小白挑强度/颜色/开关，不写 shader、不编骨骼。

---

## 三、可放权功能分级矩阵

| 功能 | 等级 | 放权方式（零代码） | 风险 | 护栏 |
|---|---|---|---|---|
| 图标/贴图替换 | ✅ 已可 | 上传 png → 写 `assets.json` path（`tscn_assets.py` 直写 .tscn） | 零 | 缺图回退默认 |
| 背景图替换 | ✅ 已可 | 换 `main_menu_bg.png` / 写 `login_bg_layout.json` | 零 | 缺图回退程序化水墨 |
| 音乐音效 | ✅ 已可 | 上传 → 改 `ui_sfx.json` path | 零 | 缺文件跳过 |
| 菜单框/弹窗/HUD 尺寸位置 | ✅ 模式已可→**推广** | 拖拽写 `<屏>.layout.json`（推广 `main_menu_layout.json`） | 零 | 越界 clamp |
| 主题配色 | 🟢 可（新增） | 写 `theme.json` 覆盖 `UIPalette` token | 零 | 非法色回退默认 |
| 流动烟雾·飘叶·水面 | 🟡 可但需护栏 | **参数化现有粒子/补间**，预设库挑 强度/颜色/开关 | 中（overdraw/粒子数） | 粒子数上限 + 层上限 + 安卓降级 |
| 视频层 | 🟡 可但重 | 写 video path → `VideoStreamPlayer` | 高（解码/内存） | 低端点/安卓自动关 |
| 骨骼动画 | 🟠 有限放权 | 换动画资产 + 混合参数，**不编骨骼** | 中 | 资产白名单 + 时长校验 |
| 自定义 shader/新交互逻辑 | 🔴 不可 | 属 `.gd` 代码，锁死 | — | 必须开发者提交 |

## 四、架构边界与性能护栏

### 放权区（小白只碰这些，留在 git 仓库、平台不复制）

```
data/configs/ui/skin/
  screens/<屏id>.layout.json   # 位置/尺寸/锚点（推广 main_menu_layout.json）
  assets/<屏id>.assets.json     # 贴图路径（推广 main_menu_assets.json）
  theme.json                    # 配色 token
  vfx/<屏id>.json               # 特效层 [{id, prefab, enabled, params:{强度,颜色}}]
  audio/<屏id>.json             # 音效映射
assets/ui/  resources/audio/    # 实际资源文件
```

### 游戏侧（开发者维护，小白不碰）

- `UISkinLoader`（通用装载器）：屏构建时读 `skin/` 并应用 —— 替代现在 MainMenu 里散落的 `_load_assets_config`。
- `resources/ui/vfx/registry.json`：**开发者登记的特效预设库**（飘叶/流烟/水面/视频/骨骼），每条带预算标注（粒子数、是否吃安卓）。
- **预算守卫**：每屏 VFX 层数 ≤ 3；`CPUParticles2D.amount` 桌面 ≤ 60 / 安卓 ≤ 24；Video 在低端/安卓自动关。
- **缺省回退**：每个读都 `ResourceLoader.exists` + 默认。

### 锁定区（绝不放权）

任何 `.gd` 业务逻辑、`EventBus` 契约、`screens.json`、`core/services/autoload`、共享地基（EventBus / ConfigManager / `core/enums/*` / `strings.csv` / GameManager / GameState）。

## 五、工作室 UI 模块重构方案（让小白一眼懂）

把分类从"按文件"改成**"按改什么"**，分三类 + 顶部屏选择器 + 底部统一三步流（见对话内架构图）：

```
工作室 · UI 模块
├─ 屏选择器：[主菜单][设置][读档][确认框][HUD]  ← 选要改哪个界面
├─ 换皮替换 · 零风险        → 图标/贴图替换 · 背景图替换 · 音乐音效
├─ 布局尺寸 · 低风险        → 尺寸/位置 · 主题配色
└─ 视觉特效 · 需护栏        → 流动烟雾·水面 · 视频层 · 骨骼动画
        底部：① 选目标 → ② 改参数/传图 → ③ 预览并应用  | 每模块「复原默认」
```

**1. 分类原则**：小白心智是"我想改图标/改大小/换背景"，不是"我要改哪个 json"。按**改什么**分，不按文件分。

**2. 每模块统一三段式**（降低学习成本，学会一个就会全部）：
> ① 选目标（哪个界面/哪个元素） → ② 改参数/传图（滑块/上传） → ③ 预览并应用
> 每个模块都有 **「复原默认」** 按钮（一键回到开发者出厂值，零恐惧）。

**3. 每模块加"小白引导"三行**（复用待办清单六问思路，精简为三行）：
- 这是干嘛的
- 改了有啥用
- 怎么改（拖拽/上传/选预设）

**4. 全局"实时预览"**：在游戏同款分辨率下沙盒预览，**不动真工程**直到点"应用"——避免误操作污染仓库。

**5. 风险用颜色区分**：绿=零风险换皮、橙=需护栏特效，让小白知道"橙色那块别乱拉满"。

## 六、落地路线图（分 Phase，低风险先上）

- **Phase 1（低风险，立刻可做）**：推广 `main_menu_layout.json` / `main_menu_assets.json` 模式到 设置/读档/确认框/HUD + 新增 `theme.json` 配色。零风险，全在 UI 主权内（改 `studio/index.html` + 游戏侧装载器）。
- **Phase 2（中风险）**：VFX 预设库 + 参数外置（飘叶/流烟/水面先从现有代码抽参数）。
- **Phase 3（重，谨慎）**：视频层、骨骼动画资产白名单。

---

## 七、回滚与追溯

- 每个放权改动都落在 git 仓库的 `data/configs/ui/skin/` 与资源目录，可 `git revert` 复原；
- 待办清单「已完成执行」已具备 完成人/日期/时间/commit/`git show`+`git revert` 追溯链（见 `docs/待办清单.md`）；
- 平台侧任何"应用"操作均建议先写预览、确认后再落盘，且保留「复原默认」。
