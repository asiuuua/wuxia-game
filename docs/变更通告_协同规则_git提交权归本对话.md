# 变更通告 · 协同规则 · git 提交权归本对话（AI）

> 类型：协同流程铁律变更（用户 2026-08-29 最新拍板）
> 生效：即时（本通告发出后所有窗口遵守）
> 取代：前一份「变更通告_协同规则_git统一由UI窗口提交.md」（已作废，不执行）

## 新规
**git 提交统一由本对话（AI / 背包窗口）收口，背包 / 战斗 / UI 等窗口不再自行 `git commit`。**

## 各窗口新动作

### 背包 / 战斗 / UI 窗口（产出方）
收尾只做四件事，**不碰 git**：
1. 改本窗口主权代码；
2. 跑双闸门（`--quit` 零错误 + `run_all` 零失败）；
3. 写本窗口《变更通告》（含「改动文件清单」）；
4. 若动了接口/信号，重跑 `gen_contract.gd` 并把新 `契约总表.md` 一并列入清单。
→ 把**改动文件清单**交给本对话(AI)，由其统一收口。

### 本对话（AI / 背包窗口，git 中枢）
1. 收集各窗口当轮改动文件清单；
2. **逐个 `git add <文件>` 精确入库**（仍严禁 `git add -A` / `git add .`）；
3. 提交信息用 `[窗口名] 改动；影响：xxx；不影响：xxx` 前缀；
4. 收口前跑一次双闸门确认合入无误。

## 为什么是这条（而非「UI 模块统一」）
- 用户先拍板「git 由 UI 模块统一」，随即改为「你（本对话/AI）负责 git 提交」。最终以本通告为准。
- 本对话已建立完整收口 SOP（精确 add 铁律 + 双闸门验证 + 变更通告留痕），由它收口与其他窗口解耦，避免多窗口并发操作 git 互相踩踏（此前 `.git` 被沙箱整目录带走的事故即源于此）。

## 新增铁律 · 并发上传互斥（2026-09-02 用户拍板）

> 背景：本对话（背包窗口 / AI）与另一工程（窗口）在 git 仓库提交时冲撞，导致 `.git` 被踩坏。
> 为避免重演，新增一条**硬性条件**：检测到他人正在向仓库上传，则放弃本次提交 / 推送，改到下次。

### 硬性条件（不可绕过）
任何窗口 / Agent 在执行 `git commit` 或 `git push`（含 `commit_queue.py flush` 真正出队提交）**之前**，必须先做「并发上传检测」：
- **检测到有人正在上传 → 本次不提交、不推送**，把本批改动留在队列 / 本地，**等下一次再提交**。
- 严禁在检测到他人上传时强行 `git add` / `commit` / `push`（这正是上一轮 `.git` 被踩坏的根因）。

### 检测手段（满足任一即视为「有人在上传」）
1. **推送锁（优先，实时）**：仓库 `.workbuddy/commits/_push_lock` 存在且持有者不是本会话 → 视为另一窗口正在上传 → 跳过。
   - 任何做 git 写操作（commit / push / stash / reset）的窗口都必须先抢这把锁；flush 开始前抢锁，结束（含失败）`finally` 删锁；锁超过 30 分钟视为失效（防卡死）。
2. **远端漂移（兜底，抓已落地的推送）**：`git fetch` 后若 `origin/<分支>` 领先本地（有人已先 push）→ 跳过，并提示先 `pull` / `rebase`。
3. **进程（人工补充）**：本机存在其他 `git push` / `git commit` 进程 → 跳过。

### 处置（统一）
一旦命中上述任一，本次 flush / 提交**整体跳过**，返回非 0（4 = 锁冲突 / 5 = 远端领先），本批记录留在 `pending_*.jsonl` 不动，下一轮 flush（含定时 automation）自然会再试。

### 与既有铁律关系
在「严禁 `git add -A`」「双闸门验证」「提交权收口」之上**叠加加严**，不替代、只补强。已由 `tools/commit_queue.py` 的 `flush` 实现（concurrency guard），规则与代码一致。

## 铁律不变项
- 仍严禁 `git add -A` / `git add .`，必须逐窗口 `git add <本窗口文件>`；
- 提交信息 `[窗口名]` 前缀 + 影响/不影响范围；
- Godot 验证串行；共享地基只增不改 + 当轮通告。
