## 一、P2-7 飘字池化（battle_entity.gd / unit_hud.gd）

**问题（审计）**：`pop_text` 每次 `Label.new()` + 动画结束 `queue_free()`，高频伤害/治疗飘字造成持续的 new/free 抖动与 GC 压力。

**修复**：
- 两文件各新增 `_pop_pool: Array[Label]`（已在上一轮 `_clear_pops` 改为遍历池释放，本轮补齐生产端）。
- 新增 `_acquire_pop()`：优先复用池中 `visible == false` 的 Label，无则 `Label.new()` 并登记入池。
- 新增 `_release_pop(l)`：动画结束回调里仅 `l.visible = false` 归还池（不再 `queue_free`）。
- 跳过模式（`_instant`，unit_hud 自带）：`pop_text` 直接 return，不创建也不飘字（与 CombatEventRenderer 的 instant 跳过一致）。
- `_clear_pops()`：遍历 `_pop_pool` 释放全部并清空——现能正确回收空闲与在途（池已含二者）飘字，杜绝回收复用残留。

**不变量**：实体对象池 `reset()` 时 `_clear_pops()` 释放本场飘字、池随之清空，下一场重建；无跨场泄漏。

## 二、P2-8 敌人射程兜底（combat_core.gd）

**问题（审计，部分成立）**：战术战棋中 `enemy_tactical_plan` 已按射程选招，但 `enemy_act` 内部 `_pick_enemy_ability` **重选招且无网格距离校验**，可能选出"够不到仍出手"的越界招式。

**修复**：
- `_pick_enemy_ability(enemy, respect_range: bool = false)` 新增 `respect_range` 形参。
- `respect_range == true` 时，候选过滤追加 `is_target_in_range(enemy.character_id, state.player.character_id, id)`。
- `enemy_act` 调用改为 `_pick_enemy_ability(enemy, grid != null)`：
  - 经典模式（`grid == null`）：`respect_range=false`，与原逻辑完全一致。
  - 战术模式（`grid != null`）：仅保留射程内可命中玩家的招式；无候选则普攻兜底（ACTION_BASIC+DAMAGE）。
- 战术场景 `_enemy_phase_impl` 先 `move_unit` 走位到最近可达格，再 `enemy_act_events` 结算——走位后射程判定基于更新后的 `grid_pos`，与计划一致。

**未改范围（说明）**：普攻兜底本身不另做射程门控（属更低优先级的战术一致性项，非本审计缺陷），本修复聚焦"技能越界施法"这一登记问题。

## 三、P0-2 渲染器确定性加固（battle_view.gd / tactical_battle_scene.gd）

**根因**：`CombatEventRenderer`（`core/combat_event_renderer.gd`，class_name 全局类）由上一轮 P0-2 新建。
headless 验证不会刷新编辑器生成的 `.godot/global_script_class_cache.cfg`，导致新脚本的全局类名未注册，
`battle_view.gd:29` / `tactical_battle_scene.gd` 引用 `CombatEventRenderer.render(...)` 报
`Identifier "CombatEventRenderer" not declared`，并级联拖垮 `battle_director.gd` / `BattleScene.gd` 及
`test_battle_scene_icons.gd`。GATE1（`--quit`）因不编译非 autoload 脚本而漏检。

**修复**：在两个消费脚本顶部显式 `const CombatEventRenderer = preload("res://core/combat_event_renderer.gd")`，
使其绕开全局类缓存、确定性解析（编辑器运行与 headless 验证行为一致）。无全局类冲突（本地 const 遮蔽同名全局，属正常）。

**效果**：双闸门彻底绿（此前 GATE2 因该级联缺陷出现 1 个 ✗ + 编译错误）。
