## 一、项目全局拆解

### 1.1 功能模块总览（结论：七大业务域，依赖方向单向收敛）

| 一级模块 | 二级子功能 | 职责边界 | 模块间依赖 |
|---------|-----------|---------|-----------|
| 世界/场景 | 区域枢纽、主菜单、加载、天气时间 | 装配与切换场景 | → GameManager → UIManager |
| 战斗 | 回合制+自动、战棋网格、技能 AI、演出编排 | 战斗逻辑与视图分离 | → CombatCore/CombatService（RefCounted）→ EventBus |
| 经济/背包 | 物品、商店、锻造、炼药、负重、锁定 | 资产守恒单一真源 | → InventoryTransaction（事务化）→ EventBus |
| 结缘 | 好感/姻缘/结义/师徒、关系网 | 关系数据中枢 | → 背包（聘礼/休息天数，当前 2 处未连通） |
| 对话/剧情 | 图模型、分片索引、事件执行器 | 叙事驱动 | → EventBus → 结缘/战斗 |
| NPC/美术 | 立绘、图标、UI 贴图、皮肤 | 资源与外观 | → ResourceManager/portrait_cache |
| 平台/工具 | 工作室桌面版、双闸门、经验库、协同 | 连接器（不持有工程数据） | → manifest Adapter → 工程文件 |

**依赖铁律**：`autoload → core → data → services(RefCounted) → scenes → resources/tests/tools`；跨模块**只走 EventBus**；数值**全进 JSON**；命名见名知意。

### 1.2 技术架构（结论：分层单体 + 事件驱动，无后端服务）

- **架构风格**：分层单体（Godot 场景树 + autoload 单例 + RefCounted 服务实例），非微服务；扩展靠 `manifest.yaml` 的 **Domain Module × Project Adapter** 二维解耦。
- **数据架构**：单机无数据库；配置在 `data/configs/*.json`，运行时态在 `data/runtime`，契约在 `data/schemas`；全局状态由 autoload 单例持有；存档由 `SaveManager` 读写并带解析失败回退。
- **接口规范**：模块间通过 `EventBus` 信号 + 服务方法调用；UI 通过 `UIManager` 屏幕栈切换；工作室侧用 `fetch` 封装 `A()`。
- **非功能性**：双闸门质量门禁（GATE1 零编译错误 / GATE2 55 套件零失败）、纹理压缩（mode=2 双保险）控体积、对象池（立绘 LRU / 音频 / 战斗实体）控内存。

### 1.3 实现路径图（核心调用链）

```
[启动] project.godot
  → autoload 注册（GameManager/EventBus/SaveManager/UImanager…）
  → GameManager 装配主场景
  → 玩家操作
      ├─ 进入战斗 → CombatService.tick() → CombatCore 状态机 → 渲染器绘制 → EventBus 广播结果
      ├─ 打开背包 → InventoryTransaction.try_consume() 单一真源 → 广播 inventory_changed
      ├─ 触发对话 → 对话图模型执行器 → EventBus → 结缘/战斗联动
      └─ 换皮/贴图 → UISkin/UIVFX + tscn_assets 直写 .tscn
[质量门禁] git commit → pre-commit(lint_mouse_filter) → 双闸门按钮(GATE1+GATE2) → push Gitee
[平台] 工作室 SPA → /api/* → studio_core(白名单/备份/回收站) → 工程文件
```

### 1.4 关键难点与亮点

| 模块 | 技术难点 | 当前方案 | 可优化点 |
|------|---------|---------|---------|
| 战斗 | 逻辑/视图耦合、确定性 | 逻辑层+战术视图层分离、渲染器确定性加固 | 自动战斗 AI 权重（M3 已设计待落地） |
| 经济 | 资产 P0 丢失（扣钱不发货） | `InventoryTransaction` 事务化（try_consume 单一真源） | 跨场景原子性边界再收紧 |
| UI 鼠标穿透 | `mouse_filter` 枚举反直觉（STOP=0 拦截 / IGNORE=2 穿透） | 四层守卫：记忆→skill→启动卡→机器(lint+运行时断言) | 守卫接成「提交前自检」常驻 |
| 纹理体积 | 出厂 mode=0 未压缩 | `compress_textures.py` + `tscn_assets.py` 写死 mode=2 双保险 | 流水线自动化 |
| 多 AI 协同 | 并行改同一仓库冲突 | 主权边界 + 提交队列 + 隐患传递板 + 窗口署名 | 合进平台闭环 |

**亮点（加粗）**：**事件总线 + 单向依赖铁律**使 7 大业务域零循环依赖；**双闸门门禁**让零 Godot 经验的 PM 也能卡质量；**工作室连接器范式**使换皮/reskin 趋近于零成本。

### 3.1 EventBus 跨模块解耦

| 维度 | 内容 |
|------|------|
| 业务目的 | 跨模块通信，避免直接依赖 |
| 输入/输出 | 信号名 + 参数 → 订阅者回调 |
| 前置/后置条件 | autoload 注册；订阅者在场景树存在 |
| 主流程 | 1. 定义信号 → 2. 发射 → 3. 订阅者执行 → 4. 解耦返回 |
| 异常流程 | 订阅者不存在/已 free → 静默跳过（需防悬空引用） |
| 涉及数据表/缓存 | 无（信号参数即载荷） |
| 涉及接口/组件 | `autoload/EventBus.gd` |
| 技术难点 | 防上帝对象退化、信号命名规范 |
| 当前实现缺点 | 信号过多时可读性下降 |
| 优化方向 | 信号命名空间 + 文档化清单 |
| 可复用点 | 任何 Godot 项目的通信底座 |
| 可扩展点 | 跨进程（未来远程访问 Phase 4） |
| 隐患 | 重入导致状态错乱 |
| 审查重点 | 单向依赖、无循环 |

### 3.4 纹理压缩 / UI 贴图直写（tscn_assets + compress_textures）

|------|------|

| 可复用点 | 美术工具链（任何 Godot 项目） |
| 可扩展点 | 批量换皮 |
| 隐患 | 未压缩导致包体膨胀 |
| 审查重点 | mode 必为 2、取像素走解码 |

### 3.5 双闸门门禁（GATE1 + GATE2）

| 维度 | 内容 |
|------|------|
| 业务目的 | 提交前质量卡点，零 Godot 经验也能卡质量 |
| 输入/输出 | 工程路径 → green/red 报告 |
| 前置/后置条件 | Godot 4.7.2 console 可用 |
| 主流程 | 1. GATE1 headless --quit 抓 SCRIPT/PARSE/COMPILE ERROR → 2. GATE2 run_all.tscn 抓 ✗/失败 → 3. green 判定 |
| 异常流程 | Godot 未找到 → 报错提示 |
| 涉及数据表/缓存 | 无 |
| 涉及接口/组件 | `studio_server._run_gate` + `/api/gate/run` + `🔧 双闸门` tab |
| 技术难点 | 正则解析 Godot 输出、超时控制 |
| 当前实现缺点 | 手动按钮触发，非强制 pre-commit |
| 优化方向 | 接成 pre-commit 强制 + 提交前自检面板 |
| 可复用点 | 通用 CI 质量片段 |
| 可扩展点 | 多工程/多引擎 |
| 隐患 | 误用 4.3 验证（已纠正为 4.7.2） |
| 审查重点 | 必须 4.7.2、GATE2 需 ✗==0 且 失败==0 |

### 5.2 可下沉为平台能力的清单（优先级排序）

1. **文件安全读写中间件**（P0）：`_is_valid_id` + `realpath` + ZIP 校验，已是平台核心，抽成独立库供任何项目复用。
2. **质量门禁片段**（P0）：双闸门 + `lint_mouse_filter`，作为通用 CI 模板。
3. **对象池模式**（P1）：立绘 LRU / 音频 / 战斗实体，沉淀为通用组件。
4. **事务化资产 API**（P1）：`InventoryTransaction` 模式，作为资源模式模板。
5. **纹理压缩流水线**（P1）：`compress_textures` + `tscn_assets`，美术工具链。
6. **回收站/备份中间件**（P2）：`trash_*` 通用删除与恢复。

### 5.4 交互优化建议（从项目反推）

- **一键生成**：新 NPC / 对话 / 模块脚手架按钮（减少重复建文件）。
- **模板化**：战斗 preset、UI 皮肤、立绘规格用模板，避免从零填。
- **可视化配置**：对话图、战棋布局已可视化；扩展至关系网、技能权重。
- **启动前自动杀同端口旧进程**：避免 8765 占用冲突（已在端口顺延基础上补强）。
- **经验库「显示变更通告」开关**：默认隐藏 79 篇避免淹没（已落地）。

### 5.5 经验调用机制（结论：三层 + 自动推荐演进）

- 现有三层：**记忆/文档**（人读）→ **skill/启动卡**（机器口令）→ **经验库分面检索**（角色/模块/BUG 过滤，搜「点不了」直接命中 mouse_filter 铁律）。
- 演进：基于「当前打开文件 / 当前角色」自动推荐相关经验条目，把被动检索变主动推送。
- 让美工/程序/前端/后端通过平台快速获取最佳实践：经验库分面已是入口；下一步把「某工位专属 SOP」固化为可点开的步骤卡。

### 5.6 0 成本迭代路径（结论：重复→模板，审查→自动，经验→提示词）

- **重复工作 → 模板/脚手架/插件**：NPC/对话/战棋/皮肤全有模板，新建即零成本。
- **人工审查点 → 自动化检查**：mouse_filter 守卫 + 双闸门 + 纹理契约，全部机器兜底。
- **通用经验 → AI 提示词库**：本文件即是沉淀；续篇 + 经验库子文档即提示词燃料。
- 目标：各工位无限趋近 0 成本推到本职——美工换皮（reskin）、程序事务化资产模板、前端鼠标穿透守卫、架构 EventBus 底座、后端对象池、运维安全自检。
