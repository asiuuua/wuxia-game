# 开发规划与里程碑（参考规范第五部分）

> 原规范以"20 人团队 / 18 个月"为基准。本项目为**单人开发**，时间轴按比例压缩、且以"垂直切片优先"为铁律。
> 本文件作为**规划参照**，实际节奏以 Phase 0–4 路线图（`docs/GDD与架构设计.md`）为准。

## 阶段总览（团队基准 → 单人适配）

| 阶段 | 团队周期 | 单人目标 | 核心交付 |
|---|---|---|---|
| 预制作 M0–M2 | 1–2 月 | 已完成 | 架构骨架、核心玩法原型 |
| 垂直切片 M3–M4 | 3–4 月 | **Phase 1 已完成** | 1 城镇 + 1 战斗全流程 |
| 核心开发 M5–M12 | 5–12 月 | Phase 2–3 | 各系统填充 |
| 内容填充 M10–M14 | 10–14 月 | Phase 3 | 任务/场景/武功/物品 |
| 优化打磨 M13–M16 | 13–16 月 | Phase 4 | 性能/手感/平衡 |
| 测试发布 M17–M18 | 17–18 月 | 发布准备 | 全平台适配 |

## 风险管控（摘录）

| 风险 | 应对 |
|---|---|
| 范围蔓延 | 垂直切片锁定核心；需求变更走评审 |
| 性能不达标 | 早期建性能基线（PerformanceMonitor），每里程碑测 |
| 存档兼容 | 版本迁移机制从 M1 建立；本次 SaveManager 已带 SAVE_VERSION |
| Godot 引擎 Bug | 锁定引擎版本（当前 4.3 校验，目标 4.7）；关键功能有备选 |

## 质量保障（摘录）

- 测试分层：单元（开发每次提交）/ 集成（每周）/ 功能（每里程碑）/ 回归 / 性能 / 兼容。
- Bug 分级：P0 致命 24h / P1 严重 3 天 / P2 一般本里程碑 / P3 轻微下里程碑。
- 代码审查八条（见 `docs/开发规范.md`）：审批、测试、静态检查、无硬编码、EventBus 通信、存档迁移、配置校验、PR 描述。
