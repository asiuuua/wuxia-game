## 一、总对照表：世界框架 → 项目里的实际文件

### 内容系统（Definition 定义层：你写的内容，**不进存档**）

| 世界框架位置 | 表 | 文件位置 | 作用域 |
|---|---|---|---|
| 任务 | 任务定义 | `data/configs/quests/quests.json`（全局任务）＋ `data/configs/regions/<区域>/quests.json`（剧情任务） | 全局 / 区域 |
| NPC | NPC 定义 | `data/configs/regions/<区域>/npcs.json` | 区域 |
| NPC 台词 | 对话分片 | `data/configs/regions/<区域>/dialogs/*.json` ＋ 全局 `npcs/dialogs/shards/` | 区域 / 全局 |
| 物品·丹药 | 丹药定义 | `data/configs/items/pills.json` | 全局 |
| 物品·装备 | 装备定义 | `data/configs/items/equipment.json` | 全局 |
| 物品·材料 | 材料定义 | `data/configs/items/materials.json` | 全局 |
| 物品·剧情物 | 剧情物品 | `data/configs/regions/<区域>/items.json`（如玉簪） | 区域 |
| 战斗 | 战斗配置 | `data/configs/regions/<区域>/battles.json` ＋ 全局 `scenes/battles.json` | 区域 / 全局 |
| 敌人 | 敌人定义 | `data/configs/regions/<区域>/enemies.json` ＋ 全局 `npcs/enemies.json` | 区域 / 全局 |
| 武学 | 技能定义 | `data/configs/abilities/skills.json` | 全局 |
| 区域本身 | **唯一注册表** | `data/configs/regions/_map_index.json` | 全局 |
| 商店 | 商店货架 | `data/configs/shop/` | 全局 |
| 结缘 | 好感事件/庆典 | `data/configs/bond/` | 全局 |

### 世界系统（世界状态：全局共享，进存档）

| 框架位置 | 实际承载 |
|---|---|
| 世界时间/天气 | WeatherTimeService（运行时）＋ GameState 存档 |
| 区域传送图 | 注册表的 `connections` 字段（P1 统一真源） |

### 玩家系统（State 状态层：**进存档**）

| 框架位置 | 实际承载 |
|---|---|
| 玩家属性/等级 | `player.json` 定义 ＋ player_state 运行态 |
| 背包/装备 | InventoryService（物品实例，含实例 ID） |
| 关系/姻缘 | BondService（好感唯一真源） |
| 任务进度 | QuestService（QuestState）＋ 旗标 `progress:<任务id>` |

### 存档系统（Save 层）

存档 = `global_flags`（剧情旗标/好感/进度）＋ 各服务状态 ＋ `last_region_id`（所在区域，1.1.0+）。
**核心纪律：定义层永不进存档；存档里只存"玩家把世界玩成了什么样"。**

## 二、引用方向（谁指向谁，箭头永远单向）

```
NPC ──dialog_id──→ 对话分片          对话 ──quest_accept:──→ 任务
NPC ──quest_id───→ 任务              对话 ──set_flag:────→ 剧情旗标
NPC ──battle_id──→ 战斗              任务 ──prerequisites──→ 前置旗标
任务 ──target_battle──→ 战斗          任务 ──then_set────→ 完成旗标
任务 ──need_item───→ 物品            任务 ──rewards────→ 物品/经验/银两/武学
战斗 ──enemy_ids──→ 敌人             战斗 ──rewards───→ 物品/经验
```

**悬空引用（指向不存在的东西）会被 GATE6 自动拦截**——你填错 ID 提交时就会被抓住，不用等游戏崩。

## 三、每张表的字段模板（照抄格式）

### ① 任务（quests）——主线/支线/剧情任务同一格式

```json
{
  "id": "nv_quest_guard",              // 唯一ID。规范：<区域前缀>_quest_<名字>
  "name": "守村御敌",                   // 显示名
  "type": "main",                      // main=主线 / side=支线 / quest_graph=流程图剧情
  "objectives": [                      // 目标列表（要全部完成才算任务完成）
    { "id": "defend", "desc": "击退夜袭的山贼",
      "target_battle": "nv_battle_bandit", "need": 1 },        // 打仗型目标
    { "id": "deliver", "desc": "把玉簪送到金记铺",
      "need_item": "nv_item_hairpin", "need_count": 1 }        // 送物型目标
  ],
  "prerequisites": { "nv_flag_guard_done": true },  // 可选：前置条件（旗标键值对），不满足接不了
  "then_set": { "nv_flag_guard_done": true },       // 可选：完成时写回的旗标（驱动任务链）
  "rewards": { "exp": 120, "silver": 60,            // 奖励：经验/银两/物品/武学，键值随意组合
               "items": [{"item_id": "nv_item_wine", "count": 2}] }
}
```
> **主线/支线组织方式**：不放一张大表里排队——主线=跨区域旗标链（A 区 then_set 的旗标做 B 区任务的 prerequisites），支线=独立旗标链。任务多了也不乱，因为**每条链的旗标都带区域前缀**（nv_/mt_），一眼认亲。

### ② NPC（npcs）——住在哪个区域就写哪个区域的表

```json
{
  "id": "nv_npc_elder",               // <区域前缀>_npc_<名字>
  "name": "赵老爹",
  "scene": "newbie_village",          // 必填！所属区域（TownScene 靠它过滤生成）
  "pos_x": 480, "pos_y": 320,         // 场景坐标
  "dialog_id": "nv_dialog_elder",     // 绑定的对话分片（可空）
  "quest_id": "", "battle_id": "",    // 可选交互入口
  "sprite": "res://resources/icons/npc/xxx.png", "portrait": "..."
}
```

### ③ 对话分片（dialogs）——新协议（P2 统一后）

```json
{
  "version": "1.0.0", "id": "nv_dialog_elder",
  "lines": [
    { "id": "l1",                                   // 行ID，选项跳转用
      "speaker_id": "nv_npc_elder",                 // 说话人（NPC id）
      "text": "台词……",
      "next_id": "l2",                              // 无选项时往下走；空=说完结束
      "effects": ["set_flag:nv_flag_x", "quest_accept:nv_quest_y"] },  // 行内命令
    { "id": "l1_choice", "speaker_id": "nv_npc_elder", "text": "回应……",
      "options": [
        { "text": "选项一", "jump_id": "l2", "effects": ["quest_accept:nv_quest_y"] },
        { "text": "选项二", "jump_id": "l3", "effects": [] } ] }
  ]
}
```
> 可用命令（CommandDispatcher 注册表，加新命令=注册 handler）：`set_flag:键[=值]`、`quest_accept:任务id`、`quest_complete:任务id`、`sfx:路径`。

### ④ 物品（三类定义表 + 区域剧情物）

```json
// pills.json（丹药）/ equipment.json（装备）/ materials.json（材料）——全局复用类
{ "id": "pill_heal_xiaohuan_001", "name": "小还丹", "type": "pill",
  "rarity": "common", "max_stack": 10, "weight": 0.1, "price": 20,
  "heal_hp": 50, "heal_mp": 0, "flags": [] }
// regions/<区域>/items.json——剧情专属物品（一次性，不必进全局商店）
{ "id": "nv_item_hairpin", "name": "祖传玉簪", "type": "key", "desc": "……" }
```

### ⑤ 敌人 + 战斗

```json
// enemies.json
{ "id": "nv_enemy_bandit_001", "name": "山贼喽啰", "lvl": 2,
  "max_hp": 40, "attack": 8, "defense": 3, "speed": 6 }
// battles.json
{ "id": "nv_battle_bandit", "name": "山贼夜袭", "turn_mode": "atb",
  "enemy_ids": ["nv_enemy_bandit_001", "nv_enemy_bandit_002"],
  "rewards": { "exp": 120, "items": [{"item_id": "nv_item_wine", "count": 2}] } }
```

### ⑥ 区域注册表（新区域入口）

```json
{ "region_id": "新区域id", "name": "显示名", "type": "hub",
  "scene_path": "res://scenes/.../xxx.tscn",      // 空=暂无场景，可传送会提示
  "connections": ["newbie_village"],              // 相邻区域
  "index_file": "res://data/configs/regions/新区域id/index.json" }  // 无内容分片可省略
```

## 四、加内容 SOP（照步骤做，不用动任何代码）

| 想加什么 | 步骤 | 完成后自检 |
|---|---|---|
| **一件新丹药/装备** | ① `items/pills.json`（或对应类）加一条定义 ② 商店要卖→ `shop/` 货架加 id ③ 任务奖励要给→ 任务 `rewards.items` 引用 id | `python tools/verify_all.py`（GATE6 抓引用错误） |
| **一条支线任务** | ① 该区域 `quests.json` 加一条（type:"side"）② 该区域 `index.json` 的 quests 数组登记 id ③ 触发方式二选一：NPC `dialog_id` 对话里 `quest_accept:` / 前置任务 `then_set` 解锁 | 同上 |
| **一个新 NPC** | ① 区域 `npcs.json` 加一条（scene 必填！）② 有台词→建对话分片 + `index.json` dialogs 登记 + NPC 绑 dialog_id | 同上 |
| **一场战斗** | ① 区域 `enemies.json` 加敌人 ② 区域 `battles.json` 配 enemy_ids+奖励 ③ 任务目标或 NPC battle_id 引用 | 同上 |
| **一个新区域** | ① `_map_index.json` 登记一行（P1 后的零代码入口）② 建区域目录+各分片（可只登记不建分片=纯传送点）③ 场景做好后填 scene_path | 同上 |
| **主线推进到新区域** | 上一区最终任务 `then_set` 写旗标 → 下一区首个任务 `prerequisites` 用同一旗标 → 自然成链 | 同上 |

## 五、规范约定（防止巨量内容后眼花）

1. **ID 前缀 = 区域前缀**：nv_ / mt_ / 下一区的前缀。全局复用物用类型前缀（pill_/equip_/mat_）。
2. **旗标命名**：`<区域前缀>_flag_<语义>`（如 nv_flag_guard_done）；跨区剧情旗标用 `plot_` 前缀。
3. **作用域判断口诀**：全游戏复用→全局表；这条剧情线专属→区域分片；拿不准→先放区域分片（以后提升到全局只是挪文件）。
4. **改表铁律**：改完必跑 `python tools/verify_all.py`——九道门禁帮你抓悬空引用/坏 JSON/重名，**你不需要肉眼查**。
5. **禁止**：手写 ID 引用前先在定义表里确认存在（或用 `python tools/ref_index.py --who <id>` 反查）；绝对不要往 `town_npcs.json`、`world/regions.json` 写东西（已退役只读）。
