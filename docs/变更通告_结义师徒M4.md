## 一、本次做了什么（你"继续扩展"的需求落地）
在 M1–M3 地基上长出两块真实服务，并把它们自动并入关系网数据中枢，UI 零改即可看到结义/师徒关系：

1. **结义服务 `SwornService`**（`services/bond/sworn_service.gd`，存档键 `sworn`）
   - 好感满 `sworn_affection`（默认 80，relations.json 可配）且 `is_swornable` 时可 `sworn()`；
   - 结义兄弟以 `npc_id` 为键存 `Dictionary`，**天然无限**（可同时与多人结义）；
   - 达成广播 `bond_sworn_formed(npc_id, stage=1)`。
2. **师徒服务 `MasterService`**（`services/bond/master_service.gd`，存档键 `master`）
   - **双向模型**：`masters`（NPC 是你的师父，`become_apprentice`，门槛 `master_affection` 默认 60）+ `apprentices`（NPC 是你徒弟，`take_apprentice`，前向兼容）；
   - 读取 `teachable_abilities` / `graduation_level`；`advance_grade()` 提升阶位；
   - 达成广播 `bond_master_set(npc_id, role)` +（收徒时）`bond_apprentice_taken(npc_id)`。
3. **关系网数据中枢自动纳入**（M3 预留口子生效）
   - `_node_of()` 新增 `is_sworn` / `is_master` / `can_sworn` / `can_apprentice` / `relation_kinds`（["ROMANCE"]/["SWORN"]/["MASTER"] 组合）；
   - `get_relationship_graph()` 新增 `sworn` / `masters` / `apprentices` 三个 enriched 数组；`get_summary()` 新增 `sworn_count` / `master_count`；
   - 新增 `get_sworn_enriched()` / `get_masters_enriched()` 供面板直接渲染。**UI 零改动**即获得三类关系数据。
4. **婚礼演出信号补位**：`RomanceService.propose()` 成功后追加 `bond_wedding_started(npc_id, wedding_type, scene_path)`，消费地基早已预声明、此前未接线的 `bond_wedding_started`（婚礼场景路径取自 relations.json `wedding_scene`）。

## 三、小白如何配（以后加可结义/可拜师 NPC）
只改 `data/configs/bond/relations.json` 数组里的一段，**不碰代码**：
```json
{
  "id": "npc_x_new",
  "name": "新角色",
  "is_swornable": true,            // 可结义
  "sworn_affection": 80,           // 结义所需好感（可选，默认80）
  "sworn_ability": "",             // 结义奖励能力（可选）
  "is_masterable": true,           // 可拜师
  "master_affection": 60,          // 拜师所需好感（可选，默认60）
  "teachable_abilities": [],       // 可授武学（可选）
  "graduation_level": 10           // 出师阶位（可选）
}
```
好感满阈值即开放对应动作；关系网面板自动显示，无需改 UI。
