# 跨窗口变更通告 · 2026-08-29 · 背包窗口（测试基建补齐）

> 给其他 AI 窗口的通告：背包窗口补齐了 3 个被 run_all 静默跳过的测试套件，并修复 1 处误导性错误码。
> **动手前请先读本文件**。

## 一、共享地基增量改动

无接口变更（`shop_service.buy()` 签名未动，仅失败 reason 细化），无需重跑 gen_contract。

## 二、本轮改动清单

### A. 测试套件收录（背包窗口主权：tests/unit/test_inventory_service / test_phase2_pilot / test_phaseA_world）
三个套件此前因未继承 `TestBase` 被 `run_all.tscn` **静默跳过**（跑与不跑无区别），本轮全部改造收录：

- `test_inventory_service.gd`：3 用例 → **12 用例**，新增 P0 回归保护：
  - 满包 add 失败 + `inventory_add_overflow` 事件断言
  - `query_add` 堆叠数学 / 满包 `can_add`=false
  - `try_consume` 两遍式**原子性**（任一不足整体不扣）
  - **instance_id 批量唯一性**（30 件无重复、`#N` 发号器格式）
  - **next_iid 存读往返**（读档后新发号不与旧 id 冲突）
  - `use_item`（丹药回血 50 + 扣件）/ 不可用物品拒绝 / `consume_instance` 耗尽回收格子
- `test_phase2_pilot.gd`：4 → 7 用例，改造为自包含（before_each reset），新增：
  - **满包卸下装备：失败且装备留在槽上**（P0-3 回归）
  - **满包换装：旧装备总数守恒不蒸发**（P0-3 回归，用守恒断言而非差值——填包武器与旧装备同 id）
  - **满包炼药：材料分文不动**（P0-2 回归）
- `test_phaseA_world.gd`：_init 自跑式 → TestBase 模式 7 用例；删除场景模式下多余的 preload 常量（避免 shadowed_global_identifier）。

### B. 服务微调（shop_service.gd）
`buy()` 对**不存在的物品**现在返回 `FAIL_INVALID`（reason=`NO_SUCH_ITEM`），不再被 `can_add` 预检误报成 `FAIL_BAG_FULL`。

- 闸门① `--headless --quit`：SCRIPT ERROR / Parse Error = **0**
- 闸门② `res://tests/unit/run_all.tscn`：**5 套件 · 47 用例 · 失败 0 · 跳过 0**（改造前仅 2 套件 18 项在跑）
- 首轮跑出 2 个失败均为测试断言自身写错（roundtrip 冲突判定逻辑、换装守恒基数），已修正——产品代码零改动。

## 四、给其他窗口的约定

1. **新增测试必须继承 `TestBase`**（`extends TestBase` + `test_*` 方法），否则 run_all 静默跳过——静默跳过 = 假绿灯。
2. 测试断言涉及"同 id 物品"计数时用**总数守恒**断言，不要用差值。
3. run_all 各套件共用 autoload 单例（GameManager 等），before_each 必须 reset 自用服务，保证用例自包含。
4. 下一轮背包窗口预告：负重真化（max_weight 挂 strength、系数进 JSON）——会动 `PlayerState` 与 `InventoryService` 公开方法（新增 `get_max_weight()`），届时按 SOP 重跑 gen_contract 并知会 UI 窗口（负重显示常量将废弃）。
