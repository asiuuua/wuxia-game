# 变更通告 · 背包窗口 · 物品锁定保护 + 容量查询 API（P2-3）

> 窗口：背包（InventoryService 主权）　日期：2026-08-29
> 性质：背包主权内功能增强，零共享地基改动（未改 EventBus / *_enums / ConfigManager / screens.json）

## 一、共享地基增量
**无。** 本次只在 `inventory_service.gd` / `item_instance.gd` 内新增公开方法与字段，属背包主权。
契约总表已重跑（`gen_contract.gd`），收录 8 个新方法，与代码零漂移。

## 二、主权内改动清单

### 1. 物品锁定（保护关键物，防被动移除）
- `data/runtime/item_instance.gd`：新增 `var locked: bool = false`；`serialize()` 增加 `"lock"` 字段；`deserialize()` 读 `"lock"`（旧档无此字段默认 `false`，**向后兼容**）。
- `services/inventory/inventory_service.gd` 新增：
  - `get_unlocked_count(item_id)` / `get_locked_count(item_id)`：非锁定/已锁定的数量
  - `set_item_locked(iid, locked) -> bool` / `is_item_locked(iid) -> bool`：单实例锁定设置与查询
- **被动移除拦截锁定物**（三处）：
  - `remove_item_by_id`：遍历时跳过 `locked` 实例（售卖/分解/丢弃走此路径）
  - `try_consume`：第一遍校验改用 `get_unlocked_count`（批量扣料：锁定物被排除，且保持原子性——任一不足整体不扣）
  - `lose_some_non_rare_items`：团灭丢物跳过锁定实例（关键物不丢）
- **主动吃药不受影响**：`use_item` / `consume_instance`（城镇/战斗用药）**不**检查 `locked`——玩家主动吃自己锁的丹药仍允许。

### 2. 容量查询 API（P2-3）
- 新增 `get_total_slots()`（主30+材料200+任务50=280）/ `get_used_slots()` / `get_free_slots()` / `is_any_bag_full()`。
- 原 `is_full()` 保留主栏语义（供旧调用方），新增 `is_any_bag_full()` 覆盖三栏。

## 三、配合约定（供 UI / Shop / Forge 窗口）
- **锁图标交互**：UI 窗口做"锁定/解锁"操作时调 `set_item_locked(iid, locked)`，之后自行 `_refresh` 即可（背包未发事件，避免加剧 P2-6 信号冗余）。
  - 若 UI 需要"锁定后即时高亮"的事件驱动刷新，可后续在 `EventBus` 加 `inventory_item_locked(iid, locked)` 信号——**属共享地基增量，须走 SOP 知会背包窗口并重跑契约总表**。
- **容量预检**：Shop/Forge 的"能否放入"已用 `can_add`/`query_add`；HUD 背包占用提示可直接用 `get_used_slots()` / `get_free_slots()` / `get_total_slots()`。
