# 图标替换与美术接入规范（2026-08-29）

> **问题**：后期会有美工加入，给物品 / 技能 / NPC / 状态 / 界面按钮等设计图标，要求"替换图标让游戏更美观"，且**美术不碰代码**。
> **结论**：项目当前（2026-08-29）**零图标资源**（resources 下无 png/svg/webp），UI 全靠代码绘制——正是预留接口的最佳时机。本规范定义一套"美术只丢文件、不碰代码"的图标体系，与 `docs/UI构造统一路线规范_2026-08-29.md` 配套。

---

## 1. 核心原则

1. **单一来源**：所有图标资源只放 `resources/icons/`，不散落到各处。
2. **按 id 引用，不按路径**：代码与配置里只写图标 `id`（如 `skills/fire_sword`），**严禁**在 `.gd` 里 `load("res://...png")` 写死路径。
3. **统一入口**：取图标只走 `UIManager.get_icon(id)`（底层 `scenes/ui/icon_registry.gd`）。
4. **缺失不崩**：找不到图标返回统一占位图（品红棋盘），绝不返回 `null`（防止 `.texture = null` 运行期崩溃）。
5. **美术零代码**：本工程默认采用「图标 id 直接派生自实体 id」约定——物品=`items/<item_id>`、技能=`skills/<id>`、NPC=`npc/<npc_id>`、敌人=`enemies/<id>`。**美术按此命名把 PNG 丢进对应子目录即可，数据层无需新增 `icon` 字段、代码无需改动**。若未来某实体图标名必须与 id 不一致，再在配置里加 `"icon"` 字段覆盖（可选，见 §4）。

---

## 2. 目录与命名

```
resources/icons/
├─ items/      物品（丹药/武器/材料/任务品）         ✅ 已接线（背包 ItemSlot）
├─ skills/     武学、技能                           ✅ 已接线（武学屏）
├─ npc/        NPC 头像 / 立绘缩略 / 玩家头像         ✅ 已接线（结缘屏 + 对话立绘 + HUD 头像）
├─ enemies/    敌人头像 / 血条                        ✅ 已接线（BattleScene 单位头像）
├─ status/     状态图标（增益 / 减益）               ⏳ 待接
├─ menu/       菜单按钮图标（主菜单 / ESC 菜单）      ✅ 已接线（MenuItem 组件）
├─ ui/         其它界面按钮图标                      ⏳ 待接
└─ _sample/    示例（可删）
```

- 文件名：英文、见名知意、下划线分隔（`heal_pill`、`fire_sword`）。
- 扩展名：`png`（首选，透明）/ `webp` / `svg` / `jpg` / `avif`。解析按 `png→webp→svg→jpg→avif` 顺序尝试。
- 图标 `id` = **相对于 `resources/icons/` 的路径，不带扩展名**，含子文件夹：`skills/fire_sword`。

## 3. 解析接口（代码侧）

`scenes/ui/icon_registry.gd`（UI 窗口主权，纯工具脚本、无 `class_name`）：

| 方法 | 返回 | 说明 |
|---|---|---|
| `IconRegistry.get_icon(id: String) -> Texture2D` | 纹理或占位图 | 主入口；找不到返回占位图，**永不返回 null** |
| `IconRegistry.has_icon(id: String) -> bool` | bool | 是否存在该图标文件（用于判断是否画图标框） |

便捷入口（其它窗口统一用这个，不必 preload 引擎）：

```gdscript
# 在任意窗口脚本中
var tex: Texture2D = UIManager.get_icon("skills/fire_sword")
some_texture_rect.texture = tex          # 永不为 null，安全
if UIManager.has_icon("items/heal_pill"):
    _icon_frame.show()                   # 有图标才显示外框
```

**禁止**：`load("res://resources/icons/xxx.png")`、`preload(...png)` 写死在业务/界面脚本里。

---

## 4. 数据配置接入（配置侧）

每个数据条目**可**携带 `"icon"` 字段（字符串 id），由各窗口主权文件自行决定何时渲染：

| 数据类型 | 配置文件（主权窗口） | 示例 |
|---|---|---|
| 物品 | `data/configs/items/*.json`（背包窗） | `"icon": "items/heal_pill"` |
| 武学/技能 | `data/configs/abilities/skills.json`（战斗窗） | `"icon": "skills/fire_sword"` |
| NPC | `data/configs/bond/relations.json`（结缘窗） | `"icon": "npc/su_waner"` |
| 状态 | `data/configs/.../status_effects.json`（战斗窗） | `"icon": "status/burn"` |

> 约定：字段名固定为 `icon`，值为**不含扩展名的 id**。美术加图后，程序/策划只需在配置里补这一行字符串。
>
> **本项目默认做法（推荐、已落地）**：图标 id 直接派生自实体 id（见 §1 原则 5），**数据层不加 `icon` 字段**，美术按 `<类别>/<实体id>` 命名丢图即可。仅当图标文件名必须与实体 id 不同时，才用此 `icon` 字段做覆盖。

## 5. 各界面接线点

| 位置 | 主权窗口 | 接线方式 | 状态 |
|---|---|---|---|
| 背包物品格 `ItemSlot` | **UI 窗** | `_icon.texture = UIManager.get_icon("items/" + inst.item_id)`（空槽置 `null`） | ✅ 已接（2026-08-29） |
| 武学屏技能行 `AbilitiesScreen` | **UI 窗** | `icon.texture = UIManager.get_icon("skills/" + id)` | ✅ 已接（2026-08-29） |
| 结缘屏 NPC 行 `BondRomanceScreen` | **UI 窗** | `icon.texture = UIManager.get_icon("npc/" + npc_id)` | ✅ 已接（2026-08-29） |
| 菜单按钮 `MenuItem`（主菜单 + ESC 菜单） | **UI 窗** | 消费方 `set_icon("menu/" + key)`，组件 `_build` 走 `UIManager.get_icon`；不设则不显示（向后兼容） | ✅ 已接（2026-08-29） |
| 对话立绘 `DialogOverlay` | **UI 窗** | 新通道 `npc/<id>`（`has_icon` 判断）优先，旧 `portrait` 资源路径作兼容兜底（修硬编码 `load` 违规） | ✅ 已接（2026-08-29） |
| HUD 玩家头像 `Hud` | **UI 窗** | `npc/player` 有真实图显图、否则显首字（`has_icon` 双通道） | ✅ 已接（2026-08-29） |
| 战斗技能栏 / 敌人图标 `BattleScene` | 战斗窗（UI 窗口代为接线） | 技能按钮 `b.icon = UIManager.get_icon("skills/"+ability_id)`；单位头像 `UnitHud.set_portrait("enemies/"+enemy_id)` / `("npc/player")` | ✅ 已接（2026-08-29，派单 f11a954808c2 已 done） |
| HUD 技能栏格子 | UI 窗（v2 方案） | `UIManager.get_icon(skill_id 对应 icon)` | ⏳ 待 v2 HUD 落地 |
| 状态卡 / 战斗 buff 条 | 战斗窗 / UI 窗 | 状态图标 `UIManager.get_icon(status.icon)` | ⏳ 待接 |

UI 窗共 6 处图标接线（背包/武学/结缘/菜单/对话立绘/HUD头像）均**零数据改动**（id 派生自实体 id），美术按约定命名丢图即生效；战斗窗 `BattleScene` 技能/敌人图标由 UI 窗口按授权直接接线（派单 f11a954808c2 已 done），HUD 技能栏待 v2 HUD 落地。

## 6. 美术资源导入设置（重要）

Godot 导入图片默认即可，但为清晰缩放建议：
- `import` → `Texture` → `Compress > Mode = VRAM Compressed`；
- 勾选 `Mipmaps`（小图标缩小时更干净）；
- `Filter` 开启（默认开）。
- 项目级 `default_texture_filter=3`（已设）已全局生效。

换图后 Godot 会自动重新导入（编辑器打开即导入；headless 门禁 `--quit` 也会触发导入）。

## 7. 占位与校验

- **缺图标**：显示品红棋盘占位图（`PlaceholderTexture2D`，64×64），一眼可辨"这里缺图"，且不崩。
- **静态校验**：门禁 `--quit` 会导入全部新图标；新增图标若扩展名不在支持列表会导入失败并在日志告警。
- **单元测试**：`tests/unit/test_icon_registry.gd`（6 项，解析引擎层）+ `tests/unit/test_icon_wiring.gd`（6 项，显示链路冒烟，在 autoload + GameManager 全加载环境下真实编译并跑通 ItemSlot / AbilitiesScreen / BondRomanceScreen / MenuItem / DialogOverlay / Hud 六处图标接线）。

---

## 8. 多 AI 主权

- **`scenes/ui/icon_registry.gd` + `UIManager.get_icon` 属 UI 窗口主权**：解析逻辑只由 UI 窗维护。
- 其它窗口**可使用** `UIManager.get_icon(id)`（只读调用），**不可修改**解析引擎或 `resources/icons/` 下的引擎文件。
- 美术新增/替换图标文件本身**不属任何代码窗口主权**，由美术直接管理 `resources/icons/`。
