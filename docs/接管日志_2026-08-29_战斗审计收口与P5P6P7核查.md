### 3.2 ⚠️ 陈旧全局类缓存陷阱（最高频假阳性根因，本项目头号坑）

- **现象**：GATE1/GATE2 突然全红，报 `Identifier "XxxGlobal" not declared` / `Could not parse script from res://...` 级联，**但 `--check-only` 单文件编译又说该全局类 OK**。
- **真因**：`.godot/global_script_class_cache.cfg` 陈旧或缺失。其他窗口 WIP 新增 `class_name` 全局类（如 `GameLogger` / `CombatEnums` / `JSONUtil` / `world_time_state`）未进缓存；或缓存被**并发 Godot 进程抢坏**（多 Godot 同时跑会损坏 .godot 类缓存，见 §1 用户日志「GATE2 flaky 真因=并发 Godot 抢坏 .godot 类缓存」）。`--quit` 与 `--check-only` **均不刷新**该编辑器生成缓存。
- **修复（务必串行，勿同时跑多个 Godot）**：
  ```bash
  rm -f "D:/武侠游戏/.godot/global_script_class_cache.cfg"
  "<godot_console>" --headless --editor --quit --path "D:/武侠游戏"
  ```
  重建后重跑 GATE1/GATE2 确认真实全绿。**切勿把缓存假阳性当成代码缺陷去改。**
- **`--check-only` 单脚本陷阱**：单脚本模式**不加载 autoload**，引用单例（`EventBus` / `ConfigManager` / `GameManager` 等）会报 `Identifier not found` 假阳性。须以 `--quit` 全量判定为准。

### 3.3 Gitee 推送（令牌擦洗铁律）

- 令牌由用户提供（或双击桌面 `wuxia-git-sync.bat`，由凭据管理器接管认证更省事）。
- **流程**：临时 push URL `https://<owner>:<token>@gitee.com/<owner>/<repo>.git` → `git push` → **立即** `git remote set-url origin https://gitee.com/<owner>/<repo>.git` 抹除令牌 → `git fetch` 校验 `FETCH_HEAD == HEAD`。
- **铁律**：令牌**不得写入任何文件、不得留在 `remote.origin.url`**。推送完必擦洗。
- **精确提交**：`git add <具体文件>`（项目铁律**禁 `-A`**）；提交信息按窗口前缀（`[战斗]`/`[UI模块]`/`[背包窗口]` 等）。
