# 变更通告 · 背包窗口 P2-9 槽位顺序保真（#163）

- **日期**：2026-08-29
- **窗口**：背包窗口（代码主权 `services/inventory/inventory_service.gd`）
- **归属/协调**：#163 P2-9 名义归 **UI 窗口**（序列化代码在背包主权文件，需跨窗口协调）。本通告为背包侧实现支撑，改动写入背包窗口《变更通告》，并知会 UI 窗口：其 P2-1 拖拽 `move_instance` 的结果现已可持久化。
- **提交**：`待提交`（本对话 git 收口）

## 一、背景（UI 窗口点名的协作项）
UI 窗口 P2-1 已落地拖拽：`InventoryService.move_instance(iid, target_bag, target_index)` 运行时按索引精确放置、占用则交换（代码在背包主权文件，注释标明跨窗口协调）。但旧序列化：
- `_serialize_bag` 跳空槽，只记非空实例；
- `_deserialize_bag` 用 `bag.find(null)` 按序塞回。
→ 拖拽后存读档，槽位顺序被重排，**拖拽结果丢失**（P2-9 原罪）。

## 二、改动（仅背包主权文件，零接口签名变化）
`services/inventory/inventory_service.gd`：
1. `_serialize_bag(bag)`：每个非空实例存 `{idx: i, data: inst.serialize()}`（idx = 原槽位下标），保真顺序。
2. `_deserialize_bag(arr, bag)`：
   - 新格式 `{idx, data}`：按 `entry.idx` 直接放入 `bag[idx]`；idx 越界则兜底 `find(null)`，避免坏档崩存档。
   - 旧格式（裸 ItemInstance 字典、无 `idx` 键）：按 `find(null)` 顺序塞回，**兼容已发布旧档**。

## 三、契约影响
- `save()` / `load()` 公开签名不变；`move_instance` / `split_instance` 不变。
- 存档 JSON 结构：单栏由 `[inst_dict, ...]` 变为 `[{idx, data}, ...]`（旧档无 idx 仍兼容）。
- EventBus / enums / ConfigManager / screens.json / strings.csv 零改动。

## 四、测试

- `test_load_legacy_save_without_idx_compat`：构造无 `idx` 旧格式 → load 不崩、物品数不变。

## 六、给 UI 窗口的对接说明
- 无需改 `move_instance` 调用；拖拽结果现在自动持久化。
- 旧玩家存档读入时按 `find(null)` 兼容，不强制迁移；新存档自动带 `idx`。
- 若 UI 窗口后续要做"按 idx 精确渲染格子"，`load` 后 `main_slots[i]` 即为保真后的实例（含 null 空位），可直接映射。
