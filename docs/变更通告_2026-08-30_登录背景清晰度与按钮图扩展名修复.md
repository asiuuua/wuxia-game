## 〇、起因：一次体检揪出的三个真问题

做 #47 时顺手量了现有素材，结果先撞上两个既有 BUG（都不是 #47 本身，但更紧急）：

| # | 问题 | 现象 | 根因 |
|---|------|------|------|
| 1 | 主背景图分辨率不足 | 仅 **1589×928**；2K 屏放大 1.61×、4K 屏放大 2.42× | 素材本身就不够大（#47 本体） |
| 2 | 「继续江湖路」按钮背景**静默消失** | 游戏里没背景图，但不报错 | `menu_continue.png` 实际是**带 Exif 的 JPEG**（头字节 `FF D8 FF E1`），被存成 `.png` → Godot 按 PNG 解码失败 → 生成不出 `.ctex` → 游戏侧 `ResourceLoader.exists()` 判假，直接跳过 |
| 3 | 按钮背景图**预览缩略图全 404** | 工具里看不到已上传的图 | 前端写了 `/api/login/btn_bg/file`，但服务端**根本没有这条路由** |

外加一个连带问题：修完 #2 后 Godot 又去扫描 `tools/desktop_studio/safety_data/backups/` 里的历史备份图，刷屏 `ERR_FILE_CORRUPT`（见第四节）。

## 一、#47 清晰度方案：多分辨率变体（游戏侧）

### 方案选型
| 方案 | 结论 |
|------|------|
| ① 直接换更高分辨率源 | **采纳，但不够**——4K 图在 1080p / 手机上白占内存 |
| ② 多分辨率变体按视口选 | **采纳为主方案**，与 ① 组合 |
| ③ 9-slice / 矢量 | 不采纳：背景是写实竹林图，无法矢量化 |
| ④ mipmap + 压缩 | 部分采纳：导入参数保持 `compress/mode=0`(lossless)、`mipmaps/generate=false`（UI 原尺寸显示，开 mipmap 反而更糊） |

### 实现
- `UIBackground.pick_bg_path(viewport_width, fallback, variants_path)` **静态**方法：
  - 取 `min_width` **最大且不超过视口宽**的那一档；
  - 视口比所有档位都小 → 兜底取最小的一档（而非回退主图，避免小屏反而用上大图）；
  - 路径不存在（`ResourceLoader.exists()` 为假）的档位**跳过**——这条正是问题 #2 的兜底，保证坏图不会让整个背景消失；
  - 配置缺失 / 空数组 / 坏 JSON / 结构不对 → **一律原样返回 fallback**，零破坏。
- 接入点：`UIBackground._build_image()`（覆盖主菜单 + 读档界面）、`LoadingScreen._add_image_background()`（加载页）。
- 新配置 `data/configs/ui/login_bg_variants.json`（文件不存在即回退老行为，**老项目零影响**）：
  ```json
  {"variants":[
    {"path":"res://assets/ui/main_menu_bg_1080p.png","min_width":0},
    {"path":"res://assets/ui/main_menu_bg_2k.png","min_width":1921},
    {"path":"res://assets/ui/main_menu_bg_4k.png","min_width":3000}
  ]}
  ```

## 二、#47 工具侧：清晰度诊断 + 变体管理

- **🔍 清晰度诊断面板**：显示主图真实像素尺寸 / 体积，并列出 1080p / 2K / 4K 三档下的**放大倍率与判定**（>1.25 判模糊）。
  当前实测：1589×928 → 1080p 1.21× 轻微发虚、2K 1.61× 模糊、4K 2.42× 模糊。
- **📐 多分辨率变体管理**：填档位名 + 生效宽度 + 选图 → 上传；表格列出每档的生效宽度 / 路径 / 尺寸 / 体积，可单独删除。
- 图片尺寸读取用**纯 Python 实现**（PNG IHDR / JPEG SOF 扫描 / WEBP VP8·VP8L·VP8X），**刻意不依赖 Pillow** —— 打包 exe 的精简解释器装不上第三方库。

## 三、问题 #2 / #3 的修复

### #2 扩展名错配（根因 + 两层防护）
- **根因**：`login_btn_bg_set()` 原本**硬编码 `dst = %s.png`** 且未做格式校验。同一份代码里，大背景图那条路径是有 `_detect_image_ext()` 校验的，**按钮这条漏了**。
- **防护一（写入时）**：`login_btn_bg_set()` 改为先按文件头判真实格式，按真实扩展名落盘（`png/jpg/webp`），映射表写真实路径；顺带清掉同名其它扩展名的残留。上传后回报尺寸，并对**竖图**（宽高比 < 1.2）给出警告（按钮是 280×44 横条，竖图会被 cover 裁得只剩中间一条）。
- **防护二（存量体检）**：新增 `login_btn_bg_scan_fix()` → 一键扫描所有按钮背景图，发现「内容格式 ≠ 扩展名」就**自动改名 + 更新映射表**（图片数据不丢）。工具界面加了「🔧 体检：修复扩展名错配」按钮。
  - 本次已用它把 `menu_continue.png` → `menu_continue.jpg`，映射表同步更新，Godot 成功生成 `.ctex`（276 B），**按钮背景恢复**。
- `_detect_image_ext()` 的行为**收紧**：无法识别时返回 `None` 而不是兜底成 `jpg`——正是原来的兜底让错配文件一路混进工程。调用方（`login_bg_replace` / `login_btn_bg_set` / `login_bg_variant_set`）统一改成拒绝并给出人话提示（"Godot 只支持 PNG / JPG / WEBP，请把 TIFF、BMP、HEIC 转成 PNG"）。

### #3 缺失的预览路由
- 补上 `GET /api/login/btn_bg/file?btn_id=xxx`：按映射表里的**真实路径**回图（而非拼 `.png`），并按扩展名返回正确 MIME。
- 顺带修 `GET /api/login/bg/file`：原来硬编码 `Content-Type: image/jpeg`，改由扩展名推导。

## 四、连带修复：Godot 误扫工具备份目录

- 现象：修完 #2 后，`--editor` 启动刷屏 `Error importing '.../safety_data/backups/20260830_232805_menu_continue.png' · ERR_FILE_CORRUPT`。
- 原因：工具的安全备份区在工程目录内，里面的历史坏图被 Godot 当资源导入。
- 修复：新增 `tools/desktop_studio/.gdignore`，让 Godot 完全忽略工具目录（不影响 `tools/` 下其它 `.gd` 脚本，也不影响 `addons/content_studio` 插件）；并在 `studio_core.py` 启动时自动补写该文件，防止新检出环境复发。
