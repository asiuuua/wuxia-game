# 《多AI协同开发方案》评审报告 + 本项目落地版

> 评审角色：项目经理 × 架构师 × 程序员 × 前端(UI) × 美工(资产管线)
> 评审对象：用户提供的《多AI协同开发Godot项目：模块隔离、信息同步、冲突规避方案》
> 结论先行：**原则全对，照抄会翻车**。方案按"数十个AI + 人肉搬运飞书/Git"设计，与本项目实际环境（同一台机器、几个 AI 窗口直接读写同一磁盘、可跑 Godot 无头验证）严重错配。下面给逐条审核与裁剪后的可执行版。

---

## 一、逐条审核表

### ✅ 采纳（写进本项目规范）

| 方案条款 | 审核意见 |
|---|---|
| 接口契约优先，实现隔离 | **完全正确**，本项目已在执行（模块主权表/共享地基清单）。补强：契约文档应由脚本从代码**自动生成**，杜绝"文档说一套代码一套"（见 §三.2） |
| 事件总线是唯一跨模块消息通道 | **方向对，但要加例外**：读操作允许调服务层公开方法（如 `GameManager.inventory_service.get_item_count()`），写操作走公开方法 + 广播事实信号。教条化"一切 emit"会让总线膨胀成几百个信号的大泥球 |
| 传数据结构/ID，不传节点引用 | **正确**，防止野引用。本项目 EventBus 信号全部值类型参数，保持住 |
| 公开/私有命名（`_` 前缀外部禁调） | **正确**且符合 GDScript 习惯。补一条：autoload 单例之间调用的必须是公开方法；`_recalculate_weight` 这类内部函数外部禁调 |
| 每次改动写变更记录（内容/影响/不影响） | **正确**，即本项目已落地的《变更通告_YYYY-MM-DD_窗口.md》机制，三段式格式直接沿用 |
| 全局文件专人维护，他人提需求 | **正确且关键**。本项目对应：共享地基（EventBus/枚举/ConfigManager/screens.json/strings.csv）改动必须走变更通告知会 |
| 每模块自带自测 | **正确**。补硬规：测试必须继承 `TestBase` 才会被 run_all 收录（本项目已有 3 个套件因没继承被静默跳过，教训在此） |
| "内部随便重构，对外契约不变就不影响别人" | **方案里最有价值的一句话**，作为所有 AI 的共识写死 |

### ⚠️ 修正（原则对、细节错）

| 方案条款 | 问题 | 修正 |
|---|---|---|
| "Autoload 只保存数据、ID，不保存节点" | 太绝对：AudioManager/UIManager 天然要持有自己创建的播放器/CanvasLayer | 改为：**不持有其他模块的场景节点引用**；自己创建并管理生命周期的子节点可以 |
| "AI 不能操作 Git/飞书，人做合并搬运中枢" | **最大错配**。人会累死、搬错、漏发；且本机 AI 能直接读写文件、跑命令 | 人只做三件事：**拍板需求、试玩验收、看变更通告汇总**。Git 提交/文档更新/语法验证全部由 AI 代劳 |
| "每个模块一个 AI，共 8 个" | 协调成本爆炸；AI-Service/AI-Popup/AI-Base 职责互相重叠（三个都在管 UI 事件流转） | 收敛为 **3~4 个窗口**：战斗窗口、UI 窗口、背包/物品窗口、基础设施窗口。窗口数 = 可并行度，不是越多越快 |
| "合并前人做初步语法校验" | 人是零基础，校验不了 GDScript | 改为**机械闸门**：合并前必须过 `--headless --quit` 零错误 + `run_all.tscn` 单测 0 失败。这比任何人工校验强 |
| "UIService 监听全部事件总线信号，执行所有场景切换" | 单点过重，会成为瓶颈和冲突热点 | 本项目已有更优解：GameManager 负责场景切换、UIManager 负责屏幕栈，职责已分好，不要合并成一个上帝服务 |
| feature 分支策略 | 对小白用户门槛高；且本项目验证必须串行（.godot 缓存冲突），多分支并行构建会玄学报错 | 降级为：**main 单分支 + 每轮改动一个 git commit**（AI 代跑），出错回滚到上一个 commit 即可。等真出过一次冲突再上分支 |

### ❌ 否决（不适用于本项目）

| 条款 | 否决理由 |
|---|---|
| 飞书文档作为唯一信息源 | 本项目 AI 可直接读写 `docs/`，本地文档更快且可被工具脚本消费；飞书加一层人工搬运只会增加漂移点。若需要对外分享，再由人导出 |
| "数十个 AI 并行" | 本项目体量下是负收益：Godot 验证必须串行，并行度瓶颈在 `.godot` 缓存锁，不在 AI 数量 |
| 新增信号"先改飞书契约，AI-Base 审核后再写代码" | 流程太重，一个信号要跨三个角色。改为：**改信号的一方直接加（只增不改），同轮写变更通告**，其他窗口开工前先读通告——已在本项目验证可行 |

## 二、方案没写、但必须补的四块（各角色视角）

### 架构师：契约即代码，零漂移
- 写 `tools/gen_contract.gd`：扫描 `EventBus.gd` 信号定义 + 各 Service 的公开方法签名，自动生成 `docs/契约总表.md`（含参数与用途，用途取自信号上方注释）。
- 规矩改为：**代码是唯一真源，契约文档是构建产物**。谁改了接口，跑一次生成脚本，文档自动同步——"忘了更新文档"这类问题从机制上消灭。
- 信号命名继续沿用现有 `notify_*`（事实通知）/ `cmd_*`（指令）前缀，按模块分段注释。

### 程序员：验证闸门前置
- 铁律写死：**任何一轮改动收尾必须跑** `--headless --quit`（零 SCRIPT ERROR）+ `res://tests/unit/run_all.tscn`（0 失败），把结果贴进变更通告。
- 新增测试必须继承 `TestBase`，否则 run_all 静默跳过。
- 多窗口**永远串行**跑 Godot 验证（`.godot` 类缓存抢锁会出玄学报错）。

### 前端(UI)：令牌与屏幕栈
- UI 一律走 UIManager 屏幕栈（`screens.json` 名→脚本），禁止跨模块直接 `new` 别人的 Screen。
- 所有动效时长/缓动/音效走 `ui_anim.json` / `ui_sfx.json` 令牌，颜色走 `UIPalette`，**禁止裸数字裸色值**——这样美工换皮不动代码。
- 新屏幕必须注册进 screens.json 并知会 UI 窗口 owner。

### 美工：资产入库主权区
- 主权区：`assets/` + `resources/fonts|themes`，改前看变更通告。
- 资产管线硬规进契约：JPG→PNG 必须 PIL 真重编码；高清图 LANCZOS 预降采样 + mipmap；改完删 `.godot/imported/*.ctex` 重导；图标命名 `ui_<功能>_<状态>.png`。
- 立绘/图标只增不删，废弃的标记 deprecated 保留一个版本周期（存档/旧界面可能还引用）。

## 三、可执行路径（按成本排序，今天就能动）

### 第 1 步（今天，零工具）
1. 各窗口开工前先读 `docs/` 下**日期最新的变更通告**（机制已在跑）。
2. 共享地基（EventBus/枚举/ConfigManager/screens.json/strings.csv）改动：**只增不改 + 当轮写通告**。
3. 每轮收尾跑双闸门（--quit + run_all），结果写进通告。

### 第 2 步（本周，AI 代劳）
4. 初始化 git（AI 直接跑命令，人不用学）：`main` 单分支，每轮改动一个 commit，格式：
   `[背包窗口] 修复满包钱货两空；影响：商店/锻造/装备；不影响主菜单`
   出问题 `git revert` 一键回滚——这就是"合并冲突"的最低成本解。
5. 写 `tools/gen_contract.gd` 生成契约总表，替代手维护文档。

### 第 3 步（规模化时再做）
6. 新增模块窗口前，先在《项目进度与协同开发框架.md》的主权表登记：可改文件/禁改文件/对外契约，再开工。
7. 出现过一次真实合并冲突后，再考虑按模块分分支；没出过就不上。

## 四、给用户的极简口诀（贴在给每个 AI 的开场白里）

> 1. 开工先读最新《变更通告》，改完必写一份。
> 2. 只改自己主权区文件；共享地基只增不改、改了必通告。
> 3. 跨模块：读走服务公开方法，写完广播事件；不碰 `_` 私有成员，不传节点引用。
> 4. 收尾双闸门：`--quit` 零错误 + `run_all` 零失败，结果贴通告里。
> 5. 契约总表由脚本生成，改接口必须重新生成。
> 6. 内部随便重构，对外信号/API 不动就不牵连别人。
