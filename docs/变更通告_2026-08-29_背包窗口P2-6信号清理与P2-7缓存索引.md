## 一、P2-6 删除 Service 冗余 signal（事件统一走 EventBus）

**问题**：`InventoryService` 内定义了 3 个 signal（`inventory_item_added` / `inventory_item_removed` / `inventory_weight_changed`），与 `EventBus` 的同名信号**完全重复双发**，且全工程无任何代码连接 Service 自有 signal（仅 `InventoryScreen` 连接 `EventBus.*`）。属死代码噪音。

**改动**：
- 删除 `inventory_service.gd` 顶部 3 个 signal 定义及 `@warning_ignore("unused_signal")`。
- `add_item` / `remove_item_by_id` / `consume_instance` / `lose_some_non_rare_items` 内部原 `inventory_xxx.emit(...)` 双发行**删除**，仅保留 `EventBus.inventory_xxx.emit(...)`。
- `_recalculate_weight()` 末尾原 `inventory_weight_changed.emit(...)` 改为 `EventBus.inventory_weight_changed.emit(...)`（**关键**：否则重量变化事件会彻底断发——原仅发 Service 自有 signal）。

**影响**：
- 事件来源从「Service 自有 + EventBus」收敛为「仅 EventBus」，单一通道，符合本工程「EventBus 是唯一跨模块消息通道」铁律。
- UI/`shop`/`forge`/`alchemy` 等连接方**零改动**（它们连的都是 EventBus）。
- 背包公开方法签名未变。

## 二、P2-7 数量缓存索引（get_item_count O(三栏) → O(1)）

**问题**：`get_item_count(item_id)` 每次遍历三栏全扫 O(N)，被 `shop`/`forge`/`alchemy`/`sect`/UI 高频调用（尤其 forge 描述材料时）。当前物品规模小无碍，但属明确优化点。

**改动**：
- 新增实例字段 `var _count_index: Dictionary`（item_id -> 总数量，含锁定）。
- 新增 `_bump_count(item_id, delta)`（增量维护，delta 为负即减，归零删 key）+ `_rebuild_count_index()`（三栏重建）。
- 同步点（确保缓存与实例一致）：`add_item`（+added）、`remove_item_by_id`（-(count-remaining)）、`consume_instance`（-1）、`lose_some_non_rare_items`（-c）、`remove_instance`（-inst.count，**此前漏同步，本次一并补**）、`reset`（clear）、`load`（重建）。
- `get_item_count` 改为 `return int(_count_index.get(item_id, 0))`。
- `get_unlocked_count`（非锁定可用量）因需 per-instance `locked` 判定，**仍遍历**（P2-7 仅优化含锁总数查询）。

**语义保证**：`_count_index` 存 total（锁定不改变总数），与旧实现 `get_item_count` 返回「含锁总数」完全一致，所有调用方（`shop`/`forge`/`alchemy`/`sect`）行为零变化。
