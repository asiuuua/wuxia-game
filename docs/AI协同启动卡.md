# AI 协同启动卡（每次开新窗口复制这一块）

> 用途：你（用户）每开一个 AI 窗口（比如"战斗窗口""UI 窗口""背包窗口"），
> 把下面**「启动口令」**整段复制，粘进新窗口的第一句话。
> 它让 AI 自动遵守多 AI 协同纪律，并决定"这次改动算谁的"（署名/追溯）。
> 不用懂技术，照抄、把 `<窗口名>` 换成这次干啥的窗口即可。

---

## 启动口令（复制下面全部，粘到新窗口）

```
你在本仓库（D:/武侠游戏，Godot 武侠 CRPG）工作，属于多 AI 协同开发的一个窗口。请严格遵守以下纪律，违反会破坏别人/被别人破坏：

1. 先读项目记忆里的协同铁律：.workbuddy/memory/MEMORY.md 的「多 AI 协同」一节（铁律1留痕/铁律2调前先查/铁律3提交节奏/铁律4门禁非绿即阻断）。
2. 任何「改文件 / 提交代码 / 修 BUG」任务，先加载 change-tracking skill（Skill 工具 → change-tracking），按它的命令执行。
3. 改东西前：change_log.py query --module <你的模块> 查近期改动，确认不是别人刚改崩的回归再动手。
4. 改完：change_log.py add 登记一行（共享地基/跨主权改动额外 change_log.py notice 出变更通告）。
5. 提交前：双闸门必须全绿——GATE1（godot --headless --path "D:/武侠游戏" --quit 零错误）、GATE2（godot --headless --path "D:/武侠游戏" res://tests/unit/run_all.tscn 零 ✗ 且失败0）。门禁红了立刻修，禁止带红继续。
6. 提交：精确 git add <文件>（禁 -A），message 带 [模块] 前缀，并设本窗口署名：git config user.name "AI-<窗口名>" user.email "ai-<窗口名>@local"。
7. 别碰别人主权代码（见 MEMORY.md 主权边界）；要改先 handoff 派单。

本次你的窗口名是：<窗口名，如 战斗 / UI / 背包 / 结缘 / 工具>
```

## 给你的使用说明（不用给 AI 看）

**什么时候用**：每开一个**新对话/新窗口**让 AI 干活之前，粘一次上面口令。

**`<窗口名>` 填什么**：这次 AI 主要干哪块的活就填哪块——
- 改战斗逻辑 → `战斗`
- 改界面/tscn → `UI`
- 改背包/道具 → `背包`
- 改剧情/结缘 → `结缘`
- 改工具/脚本 → `工具`

**为什么必须指定窗口名**：它决定 git 提交署名（`AI-<窗口名>`）。以后出 BUG，`git log` 和 `docs/更改日志.md` 一眼看出"这次改动是谁干的"——这就是"追溯到具体 AI"的前提。

**三层保险（你不用管，知道有就行）**：
1. 项目记忆会自动灌进每个 AI 会话（它"天然"知道规矩）。
2. change-tracking skill 给它具体命令（怎么登记、怎么查、怎么跑门禁）。
3. git 提交钩子（pre-commit）在机器层拦——哪怕 AI 忘了，提交时也会自动扫描"静默吞点击"类 BUG 并拦下。钩子已装好（`python tools/install_hooks.py`），无需你操作。

**一句话总结**：开窗口 → 粘口令（填窗口名）→ 让 AI 干活。其余的守卫它自己会跑、机器也会兜底。
