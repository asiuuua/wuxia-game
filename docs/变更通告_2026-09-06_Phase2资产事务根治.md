# 变更通告：Phase2 资产事务根治（09/10/11 三域）+ GameManager 事件连线新增

- 日期：2026-09-06（ACR-0001 Phase2 主战场批次）
- 窗口：AI-架构文档窗口
- 门禁：verify_all 九门禁全绿；单测套件 64 全过 0 失败

## 共享地基改动（其他窗口请注意）

### autoload/GameManager.gd
- **新增一条事件连线**（`_ready` 内，`inventory_item_added` 连线之后）：
  ```gdscript
  EventBus.inventory_item_removed.connect(quest_service.retry_completed_turn_ins)
  ```
- 用途：ACR-0001 Phase2 的「满包交付暂缓 + 腾格自动补交」机制——玩家丢弃/卖出/消耗任何物品
  触发 `inventory_item_removed` 时，QuestService 扫描仍处 COMPLETED 态的任务重试交付
  （`retry_completed_turn_ins(_item_id, _count)` 带默认参数，签名兼容信号）。
- 影响：任何 emit `inventory_item_removed` 的路径（drop_item/remove_item_by_id/lose_items 等）
  现在都会附带一次任务补交扫描；QuestService 内部有 `_retrying` 防重入闸门，无递归风险。

## 已知回归实录（复用价值）

1. **try_consume 空数组返回 false**：调用方构造扣料清单时若可能为空，必须 `not mats.is_empty()
   and not try_consume(...)` 短路放行——romance propose 曾因此致无聘礼 NPC 求婚全挂（36 项测试失败）。
2. **can_add_batch/can_add 空批次语义**：批量预检空数组=true（天然可装入）；add_items 空输入=false
   （无效调用）。两者语义不同，勿混用。
3. **测试套件间背包污染**：使用 autoload inventory 的套件必须在 after_each 清尾（reset）+
   用例自守清头；phase2_pilot 残留 105 重物品 + 力量复位曾把后续 quest 链路测试推入超重状态。
