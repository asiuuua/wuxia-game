剧情示例 · 多支线交织 + 道具获取

「烟雨楼失剑案」 —— 用一张张表格拼出来的故事

一个人物关系盘根错节、要找道具、要打赢架、还分出三种结局的武侠小剧本。每一处"故事桥段"，下面都对应一张表、一笔 flag。看完你就能看懂：剧情不是码出来的，是查表查出来 + 记笔记记出来的。
上一篇的约定（一句话复习）：游戏 = 一本书（表格：每件事写在一"页"）＋ 一支小本子（flag：记录"你做过啥、好感多少、拿过啥"）。走一步翻一页、记一笔；岔路口翻小本子决定往哪页走。

①先把故事梗概读一遍（当小说看）

《烟雨楼失剑案》

"烟雨楼"是本书里泰山北斗级的门派。某个雨夜，镇派宝剑「青釭剑」不翼而飞。你受掌门所托查案。当晚的值夜弟子阿禾说，隐约瞥见一个披黑斗篷的瘦影从后山方向掠走。

顺着这根线，三个线索缠在一起：画师刘三说雨夜见过可疑人、画得出轮廓，但要你给一副「上等狼毫笔」才肯细讲；猎户说伸手不见五指的夜里，那个黑影往城南破庙去了；游方郎中沈雪衣知道接头暗号，但她跟你不熟不开口。

你以为追到城南破庙能一锤定音——却撞上一场硬仗。打赢才知道，这把剑背后藏着一场内鬼夺权的棋。最后是当众揭穿内奸、还是只追回剑、还是被江湖恩怨牵连到别的结局，全看你一路攒下的线索和一次关键抉择。

故事梗概里其实藏着 6 个"桥段"，每个都要「翻某本书的一页 + 记一笔小本子」。下面把它拆开。

②关系脉络图：六张表怎么互相咬合

先看这张关系图——绿色箭头是"拿/给道具"，蓝色箭头是"触发/推进"，红色箭头是"条件不足走另一边"。中间那几行小字就是"flag（小本子上的笔记）"，它们把几条支线拧成一股绳。

(买/小任务得)给了→ 笔记：painter_described ✓

支线B 城南破庙→打一场→ 打赢敌方掉

「要三样都齐」才开条件= got_black_talisman ✓ painter_described ✓ gave_snow_lotus ✓
齐了→识破内鬼→ 关键抉择：当众揭穿？→ 好结局 残缺→只追回剑→ 一般结局 放过黑影→→ 另一结局

注意 NBA 藏在中间的关键：狼毫笔、黑铁令牌、雪莲这三件道具，各自把一条支线往前推，而它们拿到的凭证（flag）又被隐藏线 D 一次性回收——只有三件全凑齐，才开得了通往真凶的门。这就是"多支线交织"的打架方式：不在一条线上铺开，而是几根线凑材料汇到一根暗线上。

③第一张表：任务表 quests.json（这本书的"目录"）

任务表是故事的主目录。每条任务一行，目标、前置、完成后记什么笔记都写在里面。这里故意用咱们项目真实的字段风格（prerequisites / then_set 是给分支链预留的扩展）：

{
  "quests": [
    { "id":"q_capital_invest", "name":"烟雨楼失剑案", "type":"main",   // 主线
      "prerequisites": {"spoken_to_ahoo": true},                            // 先跟阿禾聊过
      "then_set": { "investigation_started": true },                        // 开查 → 记一笔
      "on_start_unlocks": ["q_inkbrush","q_tackle_shadow","q_snow_lotus"] },// 👈 一次张开三条支线
    { "id":"q_inkbrush", "name":"求画师帮忙", "type":"side",
      "objectives":[
        { "id":"get",   "desc":"给刘三弄一支上等狼毫笔",
          "need_item":"item_foxhair_brush", "need_count":1 },                // 目标=拿道具
        { "id":"give",  "desc":"把狼毫笔交给刘三" } ],
      "then_set": { "painter_described": true } },                            // 给了→记"画师开口了"
    { "id":"q_tackle_shadow", "name":"城南破庙黑影", "type":"side",
      "objectives":[
        { "id":"defeat", "desc":"在破庙击退黑衣刺客",
          "target_battle":"battle_old_temple", "need":1 } ],                 // 目标=打一场
      "rewards":{"exp":220,
        "items":[ {"item_id":"item_black_talisman","count":1} ]},            // 打赢掉令牌
      "then_set": { "got_black_talisman": true } },                          // + 记"拿到令牌"
    { "id":"q_snow_lotus", "name":"郎中的心事", "type":"side",
      "prerequisites": {"bond_shenxueyi >= 2": true},                        // 好感不够不开
      "objectives":[
        { "id":"gift", "desc":"赠沈雪衣一朵雪莲",
          "need_item":"item_snow_lotus", "need_count":1 } ],                 // 送道具
      "then_set": { "gave_snow_lotus": true, "bond_shenxueyi+1": true } },   // 送→记 + 好感+1
    { "id":"q_hidden_truth", "name":"雷雨之夜的真凶", "type":"hidden",       // 隐藏线 D
      "prerequisites":{                                                      // 👈 三件全齐才开
        "got_black_talisman": true,
        "painter_described": true,
        "gave_snow_lotus": true } }
  ]
}大白话解读：主线一开「同时张开三条支线」；支线B靠"打赢掉道具"，支线A/C靠"交道具"；而隐藏线D的开关就是"三条支线各记下的那笔 flag"都成立。任务表自己不长剧情，只写目标、前置、和完成要记什么笔记。

④第二张表：物品表（这些道具都是"配料单上的料"）

{
  "items": [
    { "id":"item_foxhair_brush",   "name":"上等狼毫笔", "type":"material",
      "desc":"画师心头好。能在杂货铺买，或帮笔商倒夜壶换得" },
    { "id":"item_black_talisman",  "name":"黑铁令牌 ⬭", "type":"key",
      "desc":"从破庙刺客身上掉的信物，刻着烟雨楼的内门暗记" },   // 👈 key=任务关键道具
    { "id":"item_snow_lotus",      "name":"雪莲", "type":"pill",
      "desc":"天山灵药。沈雪衣遍寻多年，求之不得" }
  ]
}

大白话解读：物品表不写剧情，只写"这是啥、能干嘛"。它和任务表咬合靠的是 quest 里写的 need_item: "item_xxx"——"你要办这事，手上得有这么件东西"。而每件东西从哪来，又是另一条线给的就是它（令牌=打架掉）。这就形成"一条线产道具，另一条线收道具"的拧绳效果。

⑤第三张表：场景NPC表（"谁站在台上"）

{
  "npcs": [
    { "id":"npc_ahoo_pupil",  "name":"值夜弟子阿禾", "scene":"capital_yanyu_lou",
      "dialog_id":"dlg_ahoo", "quest_id":"q_capital_invest" },        // 他→主线
    { "id":"npc_liu_painter", "name":"画师刘三",    "scene":"capital_yanyu_lou",
      "dialog_id":"dlg_liu",  "quest_id":"q_inkbrush" },              // 他→支线A
    { "id":"npc_shen_healer2","name":"郎中沈雪衣",  "scene":"capital_teahouse",
      "dialog_id":"dlg_shen", "quest_id":"q_snow_lotus",              // 她→支线C
      "need_flag":"q_capital_invest.investigation_started" },         // 👈 没开主线这人还不出现
    { "id":"npc_monk_abbot",  "name":"寺门和尚",    "scene":"south_old_temple",
      "dialog_id":"dlg_abbot", "battle_id":"battle_old_temple" }      // 撞他→进支线B战斗
  ]
}

大白话解读：NPC 表只回答两件事——"这人在哪、你碰他能触发哪条线"。它用 scene 决定出现在哪个画面，用 dialog_id 决定说话，用 quest_id/battle_id 钩任务和战斗。甚至有的人要等某条主线开了才出现（need_flag），这就是"剧情没到、人不露脸"。

⑥第四张表：对话表 + 触发事件表（"他开口说什么、选完干嘛"）

// dialogs.json —— 说话 + 给选项
{ "dialogs": { "dlg_liu": { "lines":[
    "刘三：雨夜那背影我见过…",
    { "choices":[            // 👈 对话里的岔路口
      { "text":"我这儿有支上等狼毫笔（交道具）",
        "consume_item":"item_foxhair_brush",        // 收走道具
        "effects":["set_flag:painter_described", "advance:q_inkbrush"] }, // 记一笔+推进
      { "text":"改日再来", "effects":[] } ] } ] } } }

// dialogue_events.json —— 选项背后能触发的小效果
{ "events":{
  "set_flag":        { "type":"flag_set" },        // 往小本子写字
  "advance":         { "type":"quest_advance" },   // 任务推进
  "give_reward":     { "type":"grant_item", "item_id":"item_black_talisman" },
  "gain_bond":       { "type":"bond_up", "target":"shen_xueyi", "delta":1 } } }


大白话解读：对话表写"说什么 + 给几个选项"，触发事件表写"每个选项背后做啥"。选"交笔"= 收道具 + 记一笔 + 推进支线A；沈雪衣那根线的"送雪莲"同理，会给 gain_bond（好感+1）。选项就是扳道岔的手，效果表就是扳完之后小本子上落的那一笔。

大白话解读："破庙刺客战"这张配料单写得很死：敌人是谁、擂台多宽有几堵墙、敌人站哪、打赢掉什么。敌人又去 enemies.json 查数值得多少血多凶。战斗本身不写"这段剧情讲啥"，只写"这场架怎么打、打赢给啥"，剧情是打过之后由信号和 flag 接棒的。

⑧最关键的教学：三个玩家各走一遍，故事就不一样

下面让三个不同玩法的玩家闯同一个剧本——你会发现，游戏从头到尾只做"查表 + 翻小本子 + 记笔记"，但三人的结局完全不同。差别只来自小本子上记的 flag 不一样。

看懂这张对比表，你就算真懂了：三人都玩同一个剧本（同一本书），代码一模一样，处罚区别只是——玩家甲小本子上 三种 flag 都打了勾，隐藏线D的开门条件是"三勾开一格"；乙只勾了一格，丙一格没勾。而结局闸门又进一步，只有"画师✓+令牌✓+雪莲✓ 都满足"才给"揭穿内鬼"的路。所以偷懒≠剧情坏了，而是你凑不齐那把开门的钥匙。

⑨用大白话收个尾：表格到底是怎么把你玩出一个故事的

  • 任务表 = 目录：一件大事分成几小步，每步写"目标、前置、完成记什么"。它管"你在干嘛、下一步去哪"。
  • 物品表 = 道具池：任务要道具，就报它的 id；道具产在别的任务/战斗，就形成"线A产出→线B消费"。
  • NPC表 = 演员表：谁在哪、碰他能勾哪条线；有的人要主线开了才登场（need_flag）。
  • 对话表 + 事件表 = 台词 + 动作：选项就是扳道岔的手，每扳一下就在小本子记一笔、或推进一段、或收走道具、或加好感。
  • 战斗表 + 敌人表 = 硬仗配料单：这一场架怎么摆、打赢给啥；它不生产剧情，剧情由打赢后冒出来的信号/flag 接棒。
  • 那本小本子（flag + 好感）：是所有这些表的"胶水"。每条线做完记个勾，隐藏线和结局闸门靠这些勾开门/定结局。
终极一句话：剧情不是一篇篇写死的文章，而是一张张互相用 "道具 id / 前置 flag / 目标战斗 id" 串起来的表格。游戏运行时 查表 → 演麻雀 × 记一笔 → 下一个岔口读笔记 → 扳道岔，无限循环，直到结局闸门按你笔记上凑齐的勾数开门放结局。你玩出来什么，不取决于游戏写没写那段，只取决于你小本子上的勾够不够、够不够格。
