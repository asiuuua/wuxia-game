## 一、共享地基增量（纯追加，未改既有接口）

### `autoload/ConfigManager.gd`
- 新增 `get_dialog_npc_id(dialog_id) -> String`：从 P1 分片索引读取 npc_id 字段，暴露「对话→NPC」归属绑定，供多 NPC 剧情隔离与归属校验使用。未绑定（通用剧情如 dlg_tutorial）返回空串。

### `services/dialogue/dialogue_service.gd`
- **条件预检缓存（P3 核心优化）**：新增 `COND_TTL_MS=1000` + `_cond_cache: Dictionary`（key=`kind|arg|npc` → {ts,val}）。`_check_condition` 改为先查缓存（1s 内命中直返），未命中才 `_eval_condition` 打任务/背包/好感服务并写回。
  - 收益：数百 NPC、分支/条件密集的对话中，每行推进与每个选项渲染都调 `_check_condition`，缓存避免短时重复求值（对话内条件通常不变）。
  - 隔离性：key 含 `_npc_id`，不同 NPC 的同 kind/arg 条件互不串缓存。
- **会话状态栈隔离**：`start()` 开头若 `_session_active` 为真，先 `_terminate_session()` 干净收尾上一个会话，再开新会话。杜绝「多 NPC 连续/并发开场」时状态串味（上一 NPC 的 `_lines/_index/_current_id` 残留）。
- **缓存清理**：`_terminate_session()` 末清空 `_cond_cache`；新增 `clear_condition_cache()` 与诊断用 `get_condition_cache_size()`。
- 既有 `_parsed_cache`（编译后对话缓存）不变；其本身已按 dialog_id 隔离不同 NPC 的对话，无需改动。

## 二、未涵盖 / 说明
- 「全局对话 ID 唯一」由 P1 `_index.json` 字典键天然保证（重复键加载即告警覆盖），本阶段未额外加运行时强校验（索引层已兜底）。
- 「真正异步/并发剧情推进」属上层玩法，非本扩容的性能/内存范畴；P3 解决的是「不串状态 + 条件求值不重复打服务」两块工业化痛点。
