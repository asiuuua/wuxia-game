## 二、关键设计决策（对照用户文档的修正）
1. **未采用 `.tres` + 内部类 Resource**：Godot 4 检查器不认内部类资源，无法在编辑器增删台词/选项，与「策划不改代码」目标冲突。改用 JSON 图模型，贴合本工程「数值全进 JSON」铁律，且与欢庆插件同款可读写。
2. **未新增 `DialogueManager` Autoload / `GlobalEventBus`**：复用现有 `DialogueService`（RefCounted，GameManager 装配）+ 既有 `EventBus`，不破坏「autoload 不持重逻辑 / 跨模块只走 EventBus」规范。
3. **修复文档递归爆栈**：`process_current_line` 条件失败递归 → 改为 `_present_current` 的 `while` 循环 + 200 次守卫。
4. **事件走 EventBus**：服务只 `emit dialogue_event_triggered`，具体演出（音效/震屏/位移/任务）由订阅 `EventBus` 的现有系统后续实现，对话服务不耦合表现。

## 三、NPC 台词 / 对话框 解耦现状
- NPC（`town_npcs.json`）只持 `dialog_id`，不写台词。
- 台词全在 `dialogs.json`（图模型），改台词只动此表。
- 对话框（`DialogOverlay`）外观/位置固定，只渲染服务推送数据。
- 事件配置 ID 在 `trigger_events[]`，含义由订阅方定义（尚缺具体执行器，后续可加 `DialogueEventExecutor` 订阅 `EventBus`）。
