# 变更通告 · HUD 常驻层挂载修复（屏幕固定位置）

**日期**：2026-08-29
**窗口**：UI 窗口（主权内）
**提交**：本期精确 `git add`，不卷它窗 WIP

## 一、改动背景

原 `TownScene.gd` 把 HUD（`Hud.tscn`，根为 `Control`）用 `add_child(hud)` 挂到场景 `Node2D` 下。
结果：HUD 活在**世界空间**，会被 `Camera2D` 带着滚动，且其坐标 (12,12) 是世界原点而非屏幕左上角——
TownScene 里那行"HUD（CanvasLayer…）"注释是**错误假设**（它其实是 Control，不是 CanvasLayer）。
这正是 v2 HUD 方案第 11 节风险点 #1 指出的架构坑。

本期按 v2 方案轮次 A 的核心修复，把常驻 HUD 改挂进 `UIManager` 的 **HUD 专属层**，实现真正屏幕固定位置。

## 三、共享地基增量

无。`Layer` 枚举仅**插入** `HUD = 5`，已有枚举项的真实层级值保持不变（0/10/20/30/40/50 ×10），
`open_screen`/`get_layer` 所有调用站点（均用 `UIManager.Layer.X`）不受影响。
未新增 EventBus 信号（避免门禁契约一致性检查红，留待轮次 B/C 与对应窗口 emit 点一并做）。

## 四、生命周期与防回归

- HUD 挂在 `UIManager` 的 HUD 层 CanvasLayer（autoload、跨场景常驻）→ 不随场景树释放。
- `TownScene._exit_tree` 调 `UIManager.unmount_hud()` 显式释放，避免切场景后"双 HUD"残留。
- `mount_hud` 内部对旧 `_hud` 先 `queue_free()`，重复挂载安全。
- `Hud._exit_tree` 断开订阅，防退出/切场景时 EventBus 已释放导致 "Trying to cast a freed object"。
- `BattleScene` / `MainMenu` 不调用 `mount_hud` → 战斗/主菜单无 HUD（符合需求）。

## 五、验证
