# 结缘 · 婚育 · 子嗣子系统 —— 详细设计设定参考

> 适用范围：本仓库 Godot 武侠 CRPG 的「结缘/子嗣/婚育」模块（模块18）。
> 定位：这是**设定参考**，不是已排期的实现清单。前端标识「我方现状」的为对照仓库 `services/bond/*` 与 `data/configs/bond/*` 的实际情况；「参考」为市面上可验证的同类系统横向比照；「建议/可落地」为考虑到我方既有架构（`RomanceService.advance_days` 时间源、`relations.json` 数据驱动、EventBus 事件、ISaveable 存档）后的具体设定建议。
> 原则：**改标题/数值走配置，改流程走服务方法+事件，换显示走 UI 层**；一律满足工程约定（服务不持 Node、跨模块只走 EventBus、存档 key 分区）。

***

## 0. 现状速览（已落地 vs 缺口）

### 已落地（可运行）

| 链路    | 现状实现                                                                                                                                    |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 好感度   | `BondService`：0-100，送礼(喜欢/爱/厌恶)，好感事件，互动日志                                                                                               |
| 求婚/结婚 | `RomanceService.propose()`：可结缘 + 性别匹配 + 好感≥`propose_affection` + 聘礼足额，事务式扣聘礼；写配偶记录、发 `bond_wedding_started`/`bond_romance_formed`、播婚礼场景 |
| 婚后互动  | 欢庆/寝欢（每日配额随机 2-3 次，+10 婘眷值）、同游旅行(+5)、一家人出游(+15)                                                                                         |
| 怀孕    | 欢庆时若配偶且未孕 → 受孕；`gestation_days:300` 硬编码，`advance_days(n)` 累加 `progress`，到期 `_birth()`                                                   |
| 子嗣    | `children[child_id] = {mother_id, born_day, name:"子嗣N"}`；发 `bond_child_born`；关系网含子女                                                     |
| 存档    | `RomanceService.save/load`（key="romance"），spouses/children/配额/婘眷值全量                                                                     |

### 主要缺口（对照参考，逐条见 §4）

1. 怀孕 **100% 必中**，无概率 / 生育力 / 年龄 / 冷却 / 上限。
2. 孕期 **300 硬编码**，无配置；无安胎 / 胎教 / 流产 / 难产 / 并发症任何事件。
3. 子嗣 **无成长阶段**（出生即终态）：无婴儿/幼儿/童年/少年/成年，无抓周/教育/培养/成年仪式，无属性天赋血脉遗传，无继承/进族谱。
4. 求婚 **不挡血亲/师徒/结义**（可与结义兄弟/亲传弟子结缘）。
5. 聘礼 `dowry_required` 全空、无「势力禁婚 / 私奔」、`婚礼类型(SIMPLE/GRAND)` 未差异化。
6. 多配偶**天然无限**（`get_spouse_count` 无上限；`allow_multiple=true`）——是否保留为设计取向，需拍板。

## 2. 五段式管线总纲（本次建议的整体骨架）

```
相识/好感 ─▶ 结缘/婚嫁 ─▶ 妊娠 ─▶ 分娩 ─▶ 养育/传承
 (阶段0)    (阶段1)     (阶段2)  (阶段3)  (阶段4)
```

各阶段我方现状 / 参考要点 / 建议承接对象汇总见各小节；每段给「我方现状 → 参考 → 建议数值/字段 → 落地载体」。

## 阶段0：相识与好感（已较完善，小补即可）

**我方现状**：`BondService` 好感 0-100、送礼(喜欢/爱/厌恶)±、好感事件(阈值解锁对话/任务)、互动日志、`affection_decay_rate`(当前全 0)。比较完整。

**参考**：太吾好感→朋友→爱慕→求婚多级判定；三国志10/骑砍以事件+阈值推进；CK3 恋爱对象可多可追踪。

**建议（小补，P1）**：

1. 完善好感分级文案与每级可做互动（stranger→acquaintance→friendly→close→loved→devoted 已存在于 `AffectionLevel`，确认各档解锁的对话/任务齐整即可）。
2. 补「感情阶段」字段 `romance_stage`（倾慕→两情相悦→结缘→已婚），与好感脱钩但由好感推进，作为求婚前置的事件叙事节点——避免「好感满直结」的跳兑感。
3. 可给 `relations.json` 增加 `affection_gain_mult` 事件/性格修正（如泼辣 -%、温婉 +%），让不同角色追法不一。

## 阶段1：结缘/婚嫁（有框架，缺门槛与差异）

**我方现状**：`propose()` 仅校验 可结缘+性别+好感≥`propose_affection`+聘礼足额；聘礼 config 全空；婚礼类型 SIMPLE/GRAND/NORMAL 已定义但未差异化；`bond_wedding_started` 播场景；多配偶无限。
**缺**：血亲/师徒/结义挡板；势力禁婚与私奔；聘礼设定；门当户对之类的门槛；婚礼差异化成本。

**参考**：太吾 血亲/师徒/结义不可婚、门派禁婚可私奔(3-6月奇遇)、正式/简易婚礼成本不同；觅长生 表白总分(正邪/境界/年龄/道侣数/洞府/答题)；CK3 政治联姻与继承绑定；波西亚 好感度+房屋+婴儿床前置。

**建议（防穿帮，优先级最高，P0）**：

1. **关系冲突挡板**（必修防穿帮）：求婚时额外校验「非血亲 / 非亲传弟子(master 关系) / 非结义兄弟(sworn 关系)」。当前 `SwornService`/`MasterService` 已各自管关系，`RomanceService.propose()` 应读它们判定（跨服务只走公开 API，不开子模块私有字段）并返回 `RELATION_CONFLICT`。若设计上允许「义兄妹结缘」，需在 config 显式放行。
2. **聘礼落地**：给可结缘 NPC 在 `relations.json.romance.dowry_required` 填实际物品（如 `["material_silk_raw_001"]`）。我方 `_dowry_satisfied` 已支持重复 item 计数，够了。
3. **婚礼差异化（P1）**：让 `wedding_type` 真正产生差异——正式婚礼需消耗彩礼金/需在特定地格 + `SIMPLE` 无演出只发通知、`GRAND` 有专属场景/宾客/加成。可在 `relations.json` 或独立 wedding.json 配每档成本与场景。
4. **势力禁婚（P2，若我们需要江湖规矩）**：给 `faction` 非空且属禁婚门派的 NPC 加 `allow_marry_outside:false` + elopement 选项（类太吾私奔）。
5. **多配偶是否设上限（待拍板）**：现无限。若想克制，可在 config 加 `max_spouses` 或 `get_spouse_count` 到上限给提示；若想保留「后宫/道侣多线」取向则维持，但需有明确文案。

## 阶段2：妊娠（核心失衡点，建议重点做 P0）

**我方现状**：`begin_celebration` 里「配偶且未孕 → 100% 受孕，`gestation_days=300` 硬编码」，无概率/fertility/冷却/上限，无孕期事件。时间源 `advance_days(n)` 已解耦。

**参考**：

- 太吾：怀孕概率 = 基础 ×男方生育力%×女方生育力%；春宵60/情难自禁20；生育力受年龄衰减；孕期冷却12-36月；孕期健康→流产/死胎/母亡事件。

- 骑砍2：日检基础20%×母亲年龄/已有子女/家族等级/Virile(+30%)；孕妇需与配偶同处。

- CK3：每次分娩 fertility-5%；妊娠并发症。

- RimWorld：避孕/绝育/IVF 人工受孕 + 孕期症状。

**建议（P0，配方模型）**：

1. **受孕概率化**：欢庆受孕改为概率判定 `pregnancy_chance`（默认 0\~40%，随好感/体质/年龄修正）。config 给每 NPC `romance.pregnancy_base`。
2. **生育力/年龄曲线**：参考太吾「生育力随年龄」；`relations.json` 补年龄分段倍率，或简单按 `age` 分段降低 base。
3. **受孕冷却与上限**：每次分娩后进入 `pregnancy_cooldown`（如 30-60 天）+ 每配偶 `max_children`（如 3-5，参考修仙家族模拟器 15 上限 + 我方更克制）。
4. **受孕门槛**：受孕发生在「欢庆/同房」动作内（简化为当日有欢庆才掷骰）。
5. **孕期可干预（P1）**：用「安胎丹/药膳」提保胎、接生用品提分娩成功率、胎教道具影响婴儿基础属性——服药走 InventoryService 公开 API。

**事件信号（新增到 EventBus，P0-P2）**：

- `bond_pregnancy_started(npc_id, child_index?)`

- `bond_pregnancy_milestone(npc_id, week, kind)`（孕肚变化/胎动/家喜）

- `bond_pregnancy_risk(npc_id, risk)`（流产/难产征兆）

- `bond_miscarriage(npc_id)`

- （复用现有）`bond_child_born(npc_id, child_id)`

## 阶段3：分娩（目前为一行，建议提为事件）

**我方现状**：`_birth()` 直接写 children 记录，无分娩代价/选择/事件。

**参考**：太吾孕期健康决定分娩结果(顺/死胎/母亡/双亡)；sims 家/医院生产，难产可剖腹；RimWorld 需医者药品干净房间，产后体弱；骑砍2 死产1%/产褥1.5%/双子3%。

**建议（P1）**：

1. 分娩触发由「满期瞬发」改为**分娩事件**：`_birth` 前广播 `bond_labor_started`，由 UI/演出层结算「顺产 / 难产(需接生品或医师) / 死胎 / 双子」的加权事件（默认顺产为主，难产/死胎低频，作为真实感与资源消耗点）。
2. 产后 **母亲体弱期**（产后冷却）：如 `puerperium_days`，期间婘眷值互动受限或需照料，顺带天然构成受孕冷却。
3. 双多胞胎：`multi_birth_chance`（如 5% 双子）→ `_birth` 产出多 child\_id 并均入 `children`。

***

## 阶段4：子嗣成长与传承（最大空白，建议分两期 P1/P2）

**我方现状**：子嗣仅 `{mother_id, born_day, name}`，无年龄/成长/属性/交互，出生即终态；`family_outing` 只检查 `children` 非空。这是「设定不完美」最明显的部位。

**参考**：

- 成长阶段：sims 婴儿→幼儿→儿童→青少年；RimWorld 婴儿0-3→儿童3-13→青年13-18（7/10/13 结学习）；三国志10 0满月/1周岁/3玩具/4玩耍/5动物/6教育/7马/8志向/10冠礼/15成年。

- 属性/遗传：RimWorld 技能热情随机+环境放大；三国志10 事件选择定方向；CK3 特质 active/inactive 遗传；阶段成长拿基础属性 = 父母均值 + 随机偏差 + 教育修正。

- 传承：三国志10 子女成为自势力武将；骑砍 继承人延续领地/头衔；太吾 传剑/轮回/传衣钵。

**建议**：

- **成长阶段（P1）**：子嗣记录扩为 `{mother_id, born_day, age_days, stage, name, attributes{body,spirit,mind,...}, talent{...}, personality, education_path}`。阶段用 `advance_days` 联动推进：婴儿(0-1岁)→幼儿(1-5)→童年(6-12)→少年(13-16)→成年(17+)。每阶段广播 `bond_child_stage_up(child_id, stage)`。

- **阶段事件（P1）**：抓周(1岁/随机先天倾向)、启蒙/教育(选文/武/德一条线，参考三国志10 0满月...15成年)、成年仪式(收为弟子/继承/入族谱/可成为随从或战力)。均发 EventBus 事件供 UI 呈现，不阻塞主流程。

- **遗传模型（P2）**：出生时按父母快照初始化子嗣。参考公式见 §5；近亲可加「先天薄弱」debuff（参考太吾畸形50%/CK3 inbreeding）。

- **传承/家族树（P2）**：建 `family_tree`：parent/child/spouse/旁系/过继；成年子嗣可选「继承衣钵/入 npc 势力/过继」。`get_relationship_graph()` 已在预留结构，填实即可。

## §5 遗传属性公式（建议草案，P2）

对可落地的数值，建议统一用「父母均值 + 随机偏差 + 教育修正」：

```
child_attr = clamp( (p_attr + s_attr)/2 + randint(-spread, +spread) + edu_bonus, min, max )
talent (灵根/根骨/资质) = 父倾向加权 + 母倾向 -> 取 top-k 继承（参考觅长生「继承最高3项」）
personality = 父母性格各取1 + 教育事件改写
近亲：with X% chance → 先天薄弱 debuff（体质/资质 -）
```

其中 `spread`/`edu_bonus` 走 config；孩子 `attributes` 可并入现 attribute 体系。

## §6 落地载体映射（不改主权、对齐既有架构）

**数据（config，改** **`relations.json`** **/ 新 JSON）**：

```
romance: {
  propose_affection, wedding_type,
  dowry_required: [items...],
  pregnancy_base: 0.35,        # 单次受孕基础概率
  fertility_age_factor: {...}, # 年龄→倍率
  max_children: 3,
  pregnancy_cooldown_days: 45,
  gestation_days: 280,          # 取代硬编码300，默认10月
  multi_birth_chance: 0.05,
  allow_marry_outside: true,    # 势力禁婚开关
}
```

**服务（`RomanceService`** **内做，不重写好感逻辑）**：

- `begin_celebration` 受孕段改为概率判定 + 命中才启动 pregnancy。

- `advance_days(n)` 已驱动孕期；扩展同时驱动子嗣 `age_days` 与阶段升级。

- `propose()` 增加 `RELATION_CONFLICT` 校验。

- `_birth()` 改为走分娩事件，可返回多胎。
