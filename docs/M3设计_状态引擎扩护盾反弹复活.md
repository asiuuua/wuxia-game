# M3 设计 · 状态引擎扩护盾/反弹/复活（战斗窗口主权）

> 日期：2026-08-29　·　窗口：战斗　·　上游：M1 战斗逻辑内核 / M2 演出编排 / M3-1 敌人 AI 选技能
> 提交策略：**git 提交统一由 UI 模块执行**（用户治理规则），本窗口只产代码 + 本设计 + 后续《变更通告》+ 对话内精确文件清单，不自 `git commit`。

## 一、目标

把状态引擎从「属性修正 + DoT/HoT」扩到三个战斗常用机制，全部**数据驱动**（走现有 `status_effects.json` + `_apply_status` 管线）：

1. **护盾 (Shield)**：吸收伤害，优先于气血扣减，持续到被消耗。
2. **反弹 (Reflect / 荆棘)**：受到攻击时，把所承受伤害的一部分反弹给攻击者（不引发连锁）。
3. **复活 (Revive / 不屈)**：单位气血归零本应死亡/倒地时，若挂有复活状态则消耗一层、原地拉起。

约束：共享地基**只增不改**；演出可视化（血条旁的护盾条 / 反弹飘字 / 复活特效）归入 **M3-3 演出动效令牌化**，本 M3-2 只交付逻辑 + 事件契约，演出层对未知事件类型 `match` 静默跳过（已验证安全，不会崩）。

## 二、现状（已读码确认）

- 伤害唯一入口：`combat_core.gd::_resolve_hit(attacker, target, power)` —— 闪避 → `dmg=max(1, power-def*0.5)` → 暴击 → `damage_taken_mult` → `target.hp = max(0, hp-dmg)`。玩家/敌人普攻与 `_cast_skill` 都走它。
- 死亡判定：`_try_down(target, events)` —— `hp<=0 && is_alive()` 时按 `can_be_downed` 置 `is_downed` 或 `is_dead`。仅在 `_resolve_hit` 之后的调用点触发。
- **🔴 既有缺口**：`tick_unit` 的 DoT 直接 `unit.hp = clampi(...)` 并 emit `STATUS_TICK`，**未调 `_try_down`** → 致命 DoT 不会致死。M3-2 顺带修（复活也对 DoT 致死生效）。
- `StatusEffect`（status_effect.gd）：字段 `effect_id/type/stat/mode/value/stacks/max_stacks/remaining/dot_per_turn/clear_on_rest`；`_status_total(stat,mode)` 聚合属性修正。
- `EffectType`（core/enums/combat_enums.gd）：`BUFF, DEBUFF, DOT, HOT, CONTROL` —— **无 SHIELD/REFLECT/REVIVE**。
- `CombatEvent.Type`（combat_event.gd）：到 `OUTCOME` —— **无 SHIELD_ABSORB/REFLECT/REVIVE**。

## 三、方案

### 3.1 数据层（只增不改共享地基）
- `combat_character.gd`：`CombatCharacter` 新增 `var shield: int = 0`（运行时资源，类 hp/mp；受击先扣它）。
- `core/enums/combat_enums.gd`：`enum EffectType` 末尾追加 `SHIELD, REFLECT, REVIVE`（追加，不重排已有值）。
- `combat_event.gd`：`enum Type` 末尾追加 `SHIELD_ABSORB, REFLECT, REVIVE`；并追加「演出直设」字段 `var target_shield_after: int = 0`（M3-3 用，本期只写值）。
- `data/configs/abilities/status_effects.json` 新增三项（向后兼容，不动既有 7 项）：
  - `huti` 护体真气：`type=SHIELD, value=20(每层护盾点), max_stacks=5, duration=3`
  - `jingci` 荆棘：`type=REFLECT, value=30(反弹百分比), max_stacks=3, duration=3`
  - `buqu` 不屈：`type=REVIVE, value=30(复活到 30% 上限气血), max_stacks=1, duration=99`

### 3.2 逻辑钩子（combat_core.gd）
- **`_apply_status` SHIELD 特例**：`type==SHIELD` 时 `unit.shield = min(unit.shield + int(value*stacks), unit.max_hp)`，**不**登记 StatusEffect（避免到期误扣已消耗护盾）。其余类型行为不变。
- **`_resolve_hit` 护盾吸收**（在 `target.hp -= dmg` 前）：
  ```
  var dealt := dmg
  if target.shield > 0:
      var absorbed := min(target.shield, dealt)
      target.shield -= absorbed
      dealt -= absorbed
      events.append(SHIELD_ABSORB ev, value=absorbed, target_shield_after=target.shield)
  target.hp = max(0, target.hp - dealt)
  ```
- **`_resolve_hit` 反弹**（在造成伤害后、且 `attacker!=null && attacker.is_alive() && attacker!=target`）：
  ```
  var rp := _reflect_pct(target)            # 0.0~1.0，sum(value*stacks)/100 并 clamp
  if rp > 0:
      var r := int(dmg * rp)
      attacker.hp = max(0, attacker.hp - r)  # 直写，绕过 _resolve_hit 防连锁
      _try_down(attacker, events)            # 反弹致死也走复活
      events.append(REFLECT ev, actor=target, target=attacker, value=r, target_hp_after=attacker.hp)
  ```
  > 简化：反弹伤害**无视攻击者护盾**（直伤），避免与护盾吸收互绕；记为已知简化，M3-3 可再议。
- **`_try_down` 复活**（在置 `is_dead` 前）：
  ```
  if target.hp <= 0 and target.is_alive():
      var rv := _revive_amount(target)
      if rv > 0:
          target.is_dead = false; target.is_downed = false
          target.hp = max(1, rv)
          target.status_effects 消耗一层 REVIVE
          events.append(REVIVE ev, actor=target, target=target, value=target.hp, target_hp_after=target.hp)
          return
      ...原 is_downed / is_dead 逻辑
  ```
  `_revive_amount(unit)`：扫 `unit.status_effects` 找 `type==REVIVE`，取首个的 `value`（视作复活百分比，`value>=100` 视为绝对气血），返回 `int(max_hp*value/100)` 或绝对值；同时消耗一层。
- **`tick_unit` 补 `_try_down`**（修致命 DoT 缺口）：DoT 写血后 `events.append(STATUS_TICK...)` 紧接着 `_try_down(unit, events)`，使 DoT 致死与复活对 DoT 生效。

### 3.3 辅助方法（均 `_` 私有，不进契约总表公开接口）
- `_shield_absorb(target, dmg) -> int`（返回实际扣血，顺带 emit 事件）
- `_reflect_pct(target) -> float`
- `_revive_amount(unit) -> int`
- `_consume_revive(unit)`（消耗一层 REVIVE 状态）

### 3.4 演出层（**本 M3-2 不动**，归 M3-3 / UI 窗口）
BattleView 对 `SHIELD_ABSORB/REFLECT/REVIVE` 在 `match` 中静默跳过（GDScript `match` 无 default 不报错）。M3-3 再接：UnitHud 加护盾条 `set_shield` + 三类飘字。本 M3-2 仅把 `target_shield_after` / `value` 写足，等 M3-3 消费。

## 四、验收（双闸门 + 单测）

- **双闸门**：`--headless --quit` 零错误；`run_all.tscn` 零失败（战斗套件 19→23）。
- **单测 +4 项**：
  1. `test_shield_absorb_reduces_damage`：玩家 `shield=20`，敌人普攻 `dmg=12` → `player.hp` 不变、`player.shield=8`、事件含 `SHIELD_ABSORB(value=12)`；`dmg=25` → 先扣 20 盾再扣 5 血。
  2. `test_reflect_damages_attacker`：玩家挂 `jingci`（30%），敌人打玩家造成 `dmg=20` → 事件含 `REFLECT(value=6)`，敌人 `hp` 降 6。
  3. `test_revive_on_lethal`：玩家挂 `buqu`（复活 30%），敌人致死 `dmg>hp` → 玩家 `hp>0`（约 30% 上限）、`is_alive()` 仍 true、事件含 `REVIVE`；二次致死（已无复活层）→ 真正死亡。
  4. `test_dot_lethal_triggers_down`（修缺口）：玩家挂 `zhuoshao`（DoT -3/回合）且 `hp` 极低，连续 tick 至 `hp<=0` → 战斗 `is_over()` 正确判负（此前致命 DoT 不致死）。

## 五、风险与决策

- **护盾不过期**：选「持续到被消耗」而非「按 duration 衰减」，规避「到期误扣已消耗护盾」的脏状态 bug；若后续要衰减，加 `shield_decay` 字段即可，不影响本结构。
- **反弹直伤不绕盾**：M3-2 简化；连锁已用直写阻断。
- **复活对 DoT 生效**：因 `tick_unit` 补 `_try_down`，不屈也能挡致命毒/灼。
- **演出零改动**：新事件类型对现有 BattleView 安全（静默跳过）；M3-3 统一做可视化，避免本 M3-2 与 M3-3 重复改 BattleView。
- **共享地基只增不改**：`EffectType`/`CombatEvent.Type` 枚举纯追加；`combat_character.shield` 为新增 var（非方法，不进契约总表公开接口）；`EventBus`/`ConfigManager`/`screens.json`/`strings.csv`/`ui_anim.json` 均不动。`gen_contract` 重跑确认无漂移。
