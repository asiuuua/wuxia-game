## 4. 运行时冒烟抓到并修复的 2 个真 bug（静态双闸门漏掉）
静态门禁（`--quit` / `run_all`）只编译与单测，**不实例化新 UI 屏幕**，故以下运行期错误未被捕获；`tests/ui/m6_ui_smoke.tscn` 当主场景跑才暴露：
1. **`BondRomanceScreen._add_child_section`**：原 `rs.get_children()` —— `RomanceService` 无此方法（实际为 `get_all_children()` 返回子嗣 id 数组），运行期 `Invalid call. Nonexistent function 'get_children' in base 'RefCounted (RomanceService)'`，`_refresh` 在构建中途崩溃。
   → 改为消费关系网数据中枢：`GameManager.relationship_service.get_relationship_graph()["children"]`（UI 关系网视图统一入口，每条为 `{child_id,name,mother_id,...}` 记录），符合"数据源与关系中枢对齐"铁律。
2. **`Hud._refresh`**：原 `ps.get(a["key"], 0)` —— Godot 4.7 `Object.get` 仅 1 参（无默认值），`Parse Error: Too many arguments for "get()"`，HUD 脚本整体加载失败（头像框/属性条全空）。
   → 改 null-safe：`var raw = ps.get(a["key"]); b.set_level(int(raw) if raw != null else 0, 100)`。

修复后 m6 输出 `ALL_M6_OK`，HUD 子节点数=3（状态卡+姻缘+菜单按钮），三屏均 `children=2` 正常构建。

## 5. 双闸门结果
- **门禁① `--headless --quit`**：零 `SCRIPT ERROR`/`Parse Error`/`Compile Error`/`ERROR`（仅无害启动 `Frame spike` 告警，Exit 0）。
- **门禁② `res://tests/unit/run_all.tscn`**：**套件 通过 13 · 失败 0 · 跳过 0**，无 `✗`（出现的 `存档解析失败` 为存读档负向用例预期日志，非失败）。
- **运行时冒烟③ `res://tests/ui/m6_ui_smoke.tscn`**：`ALL_M6_OK`，四屏无运行期报错。

## 7. 设计要点（便于复核）
- HUD 纯展示层：订阅 `player_hp_changed/player_mp_changed/player_level_up/player_exp_changed/player_stats_changed/player_money_changed/bond_relationship_changed`，不写业务数据。
- 配色/字号全部走 `UIPalette` 令牌；按钮交互走 `UIFeedback.attach`（悬停/按下反馈 + 音效），无裸 Color/像素字面量。
- `GameMenu` 四分类：人物(属性/背包/装备) · 江湖(姻缘·情缘录[红点]/门派/地图) · 技艺·生产(江湖技艺/锻造/炼药/商铺) · 系统(设置/存档)；点击 `_open` 先 `open_screen` 后 `close_screen(self)`。
- `AbilitiesScreen` 列 `ability_service.learned` 已学武学，读 `ConfigManager.get_ability` 展示 名称/修炼重数/内力消耗/描述；空态提示"前往门派拜师学艺"。
