## 一、目标
按《四大系统落地路线图》切片 A，交付结缘系统 **M1 后端内核 + 契约 + 测试**（不含 UI）：
1. **好感度等级**：STRANGER→ACQUAINTANCE→FRIENDLY→CLOSE→LOVED→DEVOTED（0–100 夹紧），跨阈值升级广播。
2. **送礼反应**：loved(+20) / liked(+12) / disliked(-5) / neutral(+3)，超 5 次衰减×0.5；按背包实例 iid 消耗 1 个（与用药同源 `consume_instance`），广播 `bond_gift_given` / `bond_gift_disliked`。
3. **好感度事件**：达阈值触发（对话/任务+奖励），一次性事件去重（`fired_events`），可发奖励物品（InventoryService.add_item）+ 奖励好感（关事件防递归）。

约束：共享地基**只增不改**；数据驱动（relations.json 一次性铺齐 M2+ 字段，婚礼/结义/师徒公开 API 留 M2）；跨模块只走 EventBus；业务层不持 Node（铁律）；送礼消耗走 InventoryService 公开 API，不碰其内部代码。

## 四、顺带修复（收尾双闸门发现的真实缺口）
1. **`_init()` 空函数体解析失败（阻塞级）**：初版 `func _init() -> void:` 后仅有注释无语句，GDScript 要求函数体非空。该解析错误导致 `BondService` 类未注册 → `GameManager.gd` 找不到类型 → 连锁拖垮 `EventBus`/`save_validator`/全部存档套件。补 `pass` 修复。
2. **`save()` 引用 mutation 致存档往返还原为空**：`save()` 原样返回内部 `affections` 等 Dictionary 引用，随后 `reset()` 的 `.clear()` 会连带清空快照，使 `load()` 还原为空（好感度/已触发事件丢失）。改为 `.duplicate(true)` 深拷贝快照，与 PlayerState/InventoryService 等既有 `save()` 范式一致。
3. **测试 `test_give_gift_disliked` 信号捕获失真（测试层 bug，服务正确）**：原测试用 `var caught := false` + `func(...): caught = true` lambda 捕获，GDScript 对局部图元变量的 lambda 赋值不回写外层，断言恒 false。调试打印已证实服务**确实广播**了 `bond_gift_disliked`。改用 dict 盒子（`{"v": false}`）可靠回传。服务的事件契约本身无问题。
