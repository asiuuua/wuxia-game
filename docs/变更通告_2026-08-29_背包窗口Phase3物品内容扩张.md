## 二、数据契约（铁律）
- `flags` 严格按 `core/enums/item_enums.gd` 的 `ItemFlag` 位掩码：
  - 武器/装备：`EQUIPPABLE(64)+SELLABLE(2)+DISCARDABLE(1)=67`，`max_stack=1`
  - 丹药：`CONSUMABLE(32)+STACKABLE(16)+SELLABLE(2)+DISCARDABLE(1)=51`，`max_stack=10`
  - 材料：`STACKABLE(16)+SELLABLE(2)+DISCARDABLE(1)=19`，`max_stack=99`
- 字段只填系统已消费的：`weapon`→attack/bonus_attack/durability/speed/equip_slot；`pill`→heal_hp/heal_mp；`armor/accessory`→equip_slot+bonus_defense/hp/mp/attack；`material`→基础字段。不写未消费字段，避免死配置。
- 未新建 `misc.json`（quest/key 物品 type=QUEST 不在 `ConfigManager` 加载清单内，需改共享地基才能加载）——**留待任务窗口定义**，本窗口不越界。

## 三、配套自检测试
`tests/unit/test_inventory_service.gd` 新增 `test_item_config_integrity`：直接读 4 个 JSON，校验
- 顶层为对象、至少 1 条；
- `id` 非空且全局唯一（防撞名）；
- `type` ∈ {weapon,armor,pill,material,accessory,quest}、`rarity` ∈ {common,uncommon,rare,epic,legendary}；
- `flags` 为正整数；
- `EQUIPPABLE` 必 `max_stack=1`、`STACKABLE` 必 `max_stack>1`（flag 与堆叠自洽）。
→ 后续任何人写坏物品 JSON / 配错 flag，单测立即红。
