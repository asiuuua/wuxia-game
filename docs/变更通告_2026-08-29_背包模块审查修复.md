## 二、缺陷核实与修复清单

核实原则：每一项均回到源码/测试逐条核对，成立则修，不成立则说明。共 9 项，7 项成立并修复，2 项归口（非背包主权越权）。

### P0 — UI 丢弃绕过保护（成立，已修）
- **核实**：`InventoryScreen.gd` 右键丢弃分支原走 `inv.remove_instance(iid)`，直接绕过 `drop_item` 的 `DISCARDABLE`/`LOCKED` 校验 → 招牌锁定道具可被静默丢弃。
- **修复**：丢弃改走 `inv.drop_item(iid, tgt.count)`；拒绝时保留物品并 `GameLogger.info` 记录（不静默绕过保护）。
- **位置**：`scenes/ui/overlays/inventory/InventoryScreen.gd` `match id: 2:` 分支。

### P1-2 — 事务非原子（静默丢料）（成立，已修）
- **核实**：`InventoryTransaction.commit` 原顺序 add→remove，且 remove 失败时未回滚已加入的产物，存在「扣了料、产物没进」风险。
- **修复**：`commit` 重构为 ① 收集三段（remove/add/consume）② **预校验**（不改状态：`get_unlocked_count`/`can_add`/`get_instance_by_id`）③ `add → remove → consume` 顺序 ④ remove 失败则 `remove_item_by_id` 回滚已加产物。整体要么全成要么全不成。
- **位置**：`services/inventory/inventory_transaction.gd`。

### P1-3 — `use_item` battle 空壳（成立，已修）
- **核实**：`_apply_use_heal`/`_apply_use_exp` 的 `context=="battle"` 分支原直接改 `PlayerState`，破坏背包不直接改玩家状态的边界，且战斗场景无法接管结算（护盾/溢出/HUD）。
- **修复**：battle 分支改为 `consume_instance` + `EventBus.item_used_in_battle.emit(item_id, effect)` 返回 `{ok:true, reason:"BATTLE_PENDING"}`；town 仍直改。战斗场景订阅信号做结算。
- **位置**：`services/inventory/inventory_service.gd` + `autoload/EventBus.gd`（信号）。

### P1-4 — 实例身份丢失（成立，已修）
- **核实**：装备换装/卸装走 `add_item`（按 item_id mint 新实例），丢失原 `iid` 与 `durability`；铸造/喂道具按新 id 计数会错配。
- **修复**：
  - 背包新增 `func add_instance(inst: ItemInstance) -> bool`：原样归还实例（保留 `instance_id`/`durability`/`locked`），可堆叠并入同物实例，否则入空槽，满包 `false`。
  - 装备 `equip` 抽包后保留 `inst` 引用入 `_equipped_inst[slot]`；换装退旧用 `add_instance(old_inst)` 原样归还（失败回滚用 `add_instance(inst)`）；`unequip` 存在 `_equipped_inst` 则 `add_instance` 原样归还，否则 `add_item` 兼容旧档。
- **位置**：`services/inventory/inventory_service.gd` + `services/equipment/equipment_service.gd`。

### P2-5 — 重量每格全栏重算（成立，已修）
- **核实**：`add_item` 循环内每格都跑 `_recalculate_weight()`（全 280 格扫描 + 发事件），冗余。`count` 索引实测无 over-count（回归已覆盖），仅重算冗余为真。
- **修复**：循环内去全栏重算，保留 `current_weight += unit_w*put` 增量；`_stack_to_existing` 增加增量同步；循环外末尾 `emit` 一次 `inventory_weight_changed`。
- **位置**：`services/inventory/inventory_service.gd`。

### P2-6 — 类型双真源（成立，已修）
- **核实**：`item_data.gd` 用 `int` 枚举（`type`/`rarity`），与运行时/JSON 字符串契约不一致，产生 int↔String 双真源死代码。
- **修复**：`type: String = ""` / `rarity: String = ""`，与运行时一致，`flags` 位掩码解耦。
- **位置**：`data/schemas/item_data.gd`。

### P2-8 — `query_add` 陷阱（成立，已修）
- **核实**：`query_add` 原 `maxi(0, ...)` 过早 clamp，超重时 `added` 可能为负或越界。
- **修复**：去掉 premature clamp，改 `var weight_room = int((get_max_weight()-current_weight)/unit_w)`，末尾 `var added = maxi(0, mini(count, room))`。
- **位置**：`services/inventory/inventory_service.gd`。

### P2-7 — 溢出事件（归口，未越权）
- **核实**：背包侧 `add_item` 溢出逻辑设计无误（团灭丢物已配置化）。监听/兜底 UI 提示属 UI 窗口主权。
- **处置**：已派 UI 窗口单 `37c9ca18f539`，背包窗口不越权。

### P2-9 — 拖拽 no-op（部分归口）
- **核实**：服务层 `move_instance` 对跨类型拒绝正确（类型不变式守卫）。UI 组件 `_can_drop_data` 预览允许跨栏属 UI 窗口主权表现层。
- **修复（背包侧）**：`InventoryScreen._on_slot_drop` 捕获 `move_instance` 返回值，拒则 `GameLogger.info` 记录，不再静默 no-op。
- **归口**：`_can_drop_data` 预览逻辑归 UI 窗口主权，本窗口仅修服务调用回执。
