# 变更通告 · 协同总纲（骨血）· 多 AI 并行开发 Git 冲突 / 仓库损坏规避

> 类型：协同流程总纲（全员必须遵守，地位等同「骨血」）
> 生效：即时（发出后所有窗口 / 任何参与本仓库的 AI 或人都必须遵守）
> 地位：本通告为协同最高约束，取代此前零散的协同约定；操作细则见《变更通告_协同规则_git提交权归本对话.md》（PM 收口 SOP）。**两者冲突以本总纲为准。**

---

## 〇、这东西是干嘛的（为什么要有这份总纲）

多 AI / 多人同时改同一个 Git 仓库，最常见的翻车就四类，本总纲就是为钉死它们：

1. **tscn 场景被 git 自动合并搞坏** —— Godot 的 `.tscn` 是文本格式，git 自动合并 90% 会把场景并坏、直接打不开。
2. **文件被互相覆盖** —— 两个窗口同时改同一个文件，后提交的把前一个的活儿冲掉。
3. **未测试的坏代码直接入库** —— 跳过验证就 commit，把别人也带崩。
4. **大资源把仓库撑爆** —— 立绘 / 视频 CG / 大音频进 Git，仓库越来越卡、clone 越来越慢。

本总纲把「谁能动什么文件、什么时候能提交、提交前必须过什么关」钉死，让多 AI 并行**不踩踏**。

---

## 一、主干与提交权（铁律）

- **当前拍板**：单 `master` 主干；提交统一由本对话（PM / 背包窗口）收口，各窗口（战斗 / UI / 结缘 / 背包）**不自行 `git commit`**。
- **严禁 `git add -A` / `git add .`**：必须逐窗口 `git add <本窗口文件>`，精确入库。
- 提交信息统一 `[窗口名] 改动；影响：xxx；不影响：xxx` 前缀。
- ⚠️ **待拍板（见第九节）**：是否升级为「feature 分支 + MR 双闸门合并」。当前维持单主干收口，不推翻。

---

## 二、双闸门（入库前必须过，否则绝不入库）

- **GATE1**：Godot `console --headless --path "D:/武侠游戏" --quit` 零 `SCRIPT ERROR / Parse Error / Compile Error`。
- **GATE2**：`res://tests/unit/run_all.tscn` 零 `✗` 且套件失败数 = 0（判绿须同时满足 `grep -c "✗"==0` 且 `套件：失败 M` 的 M==0）。
- 任一闸门红 → 不入库、不收口，先修。

---

## 三、文件主权 / 文件锁（防互相覆盖，最高优先级）

- 每个任务**开工前**必须显式声明「本次会改动哪些文件」（《变更通告》的「改动文件清单》+ 提交队列 `pending_*.jsonl` 的 `files` 字段），这就是**活台账**。
- **同一时刻、同一个文件只分配给一个任务 / 一个 AI**；其他任务禁止改动，直到该任务合入释放。
- **冻结主权（只增不改）**：`EventBus.gd` / `ConfigManager.gd` / `core/enums/*_enums.gd` / `screens.json` / `strings.csv`；跨主权改动必须走《变更通告》并打招呼。
- 任何窗口提交前先核对清单：**不在自己清单内的改动一律丢弃**，绝不顺手带别人的文件。

---

## 四、tscn 场景文件特殊保护（最高风险点）

- **git 绝不自动合并 `.tscn`**。两处同改一个 tscn 时，冲突以其中一版为基准**手动重改**，合并前必须本地打开场景验证能正常加载。
- **B 路线（已落地）结构性规避**：大界面拆成大量小 tscn 预制，一个预制只管一小块，不同 AI 操作不同预制，从源头减少抢同一文件。
- 定期用 Godot「清理场景」删废弃节点 / 无效引用，减小 tscn 体积、降低合并概率。

---

## 五、并发上传互斥（2026-09-02 硬性条件，已落地 `commit_queue.py`）

- 任何窗口执行 `git commit` / `git push`（含 `commit_queue.py flush` 真正出队提交）**之前**，必须做并发上传检测：
  - 推送锁 `.workbuddy/commits/_push_lock` 被他人持有 → 跳过；
  - `git fetch` 后 `origin/<分支>` 领先本地（有人已先推）→ 跳过；
  - 本机存在其他 `git push` / `git commit` 进程 → 跳过。
- 命中即**本次不提交、不推送，等下一次 flush 再试**（返回码 4=锁冲突 / 5=远端领先）。**严禁在检测到他人上传时强行 add/commit/push。**
- 完整规则见《变更通告_协同规则_git提交权归本对话.md》「新增铁律 · 并发上传互斥」。

## 六、.gitignore 硬化（防仓库膨胀）

- **已排除**：`.godot/` `export/` `build/` `dist/` `*.exe` `*.pck` `*.zip` `.workbuddy/commits/` `.workbuddy/handovers/` `tools/desktop_studio/safety_data/` `__pycache__/`。
- **补强（待确认）**：仓库只管「脚本 / .gd / .tscn / .csv / 文档 / 小资源」，**大体积媒体（立绘 / 视频 CG / 大音频）不进 Git**，走外部素材库或 Git LFS。
  - ⚠️ 现状：`assets/` 约 **123MB**、13 个大文件（>1MB）。建议仅入库必要小资源，大媒体外置；具体策略见第九节待拍板。

## 七、常见事故应急

| 事故 | 处置 |
|---|---|
| 合并后 tscn 打不开 | 该文件回退到合入前版本，新功能手动重贴，**不用 git 合并产物**；合并前先本地验证加载 |
| 代码被互相覆盖 | 任务分配阶段就规避同文件；合并前逐行 diff 核对 + 双闸门冒烟 |
| 仓库膨胀卡顿 | 查 `.gitignore`，把大资源移出；必要时清理历史大文件 |
| AI 自作主张改了无关文件 | 提交前 `git diff` 核对，不在清单的改动直接丢弃 |

## 八、知识库沉淀（建议入 Project_Knowledge_Base）

- **K006 · tscn 禁自动合并**：任何 `.tscn` 冲突必须手动重改 + 加载验证，绝不信任 git 合并结果。
- **K007 · 主干受保护**：未过双闸门、未精确 add、未收口，代码不得入库。
- **K008 · 大资源不进 Git**：媒体外置；仓库只承载可文本评审的源码与配置。
- **K009 · 文件清单即活锁**：每个任务的「改动文件清单」是互斥单元，同一文件同时只归一个任务。

## 九、已拍板（用户 2026-09-02 续拍板，最终封版）

1. **分支模型（维持现状：单 `master` + PM 收口）**：各窗口不自行 commit，由本对话统一收口。
   - **为何不选 feature 分支 + MR**：本工程是多 AI 窗口共用**同一本地工作树**（同机同 checkout）。实际翻车根因是「并行 `git stash` / `reset` 等本地写操作互相踩踏 `.git`」，而非推送/合并冲突。feature 分支要真正隔离，需各自 `git worktree` / 独立克隆 + 平台 CI——既没解决本地踩踏、又徒增环节；而「主权边界 + 提交队列（文件级互斥）+ 并发互斥锁 + 双闸门」已在本机层面把隔离与绿主干都兜住。
   - feature+MR 仅作为**未来可选升级路径**（如改为多人 / 多机协作、要强制人工 review 网关时）另发通告，不推翻当前拍板。
2. **`assets/` 大媒体（方向已定：外置）**：大体积媒体（立绘 / 视频 CG / 大音频，当前约 123MB、13 个 >1MB 文件）不进 Git 文本库。
   - 执行：待 git 恢复后审计这 13 个大文件，移出仓库或走外部素材库 / Git LFS；小资源（图标、必要贴图）保留入库。
   - 过渡期：仓库以 `.gitignore` 排除大媒体类型（见第六节），保证 clone/协作不卡；运行时资源仍从本地磁盘加载，不影响游戏运行。
3. **并发互斥（已落地并验证）**：见第五、六节与 `commit_queue.py`——flush 命中他人上传即返回 4/5、本次不提交、改下次再试。
