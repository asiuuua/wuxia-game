## 二、战斗窗口主权内改动（其他窗口请勿改这些文件）

- `data/runtime/combat_event.gd`（**新增**，逻辑层 ↔ 演出层唯一契约）：`enum Type`（TURN_START / ACTION_BASIC / ACTION_SKILL / QI_COST / QI_GAIN / COOLDOWN_SET / DAMAGE / HEAL / STATUS_APPLIED / STATUS_TICK / STATUS_EXPIRED / OUTCOME）+ 字段 actor_id / target_id / value / crit / dodged / status_id / stacks / skill_id。
- `services/combat/combat_core.gd`（**新增**，纯 `RefCounted` 逻辑内核，零 Node / 零全局 `randf` / 零 Tween）：ATB 行动顺序 `action_order()`、双资源（气血 hp + 真气 mp）、招式分阶与冷却（`qi_cost` / `cooldown`）、状态引擎（`tick_unit`：DoT/HoT + 持续递减 + 到期移除；`StatusEffect` 含 flat/pct/层数/持续/clear_on_rest）、确定性随机（注入 `SeededRNG`）。
- `services/combat/combat_service.gd`（门面，**保留全部旧接口零回归**：`player_attack` / `player_cast` / `run_enemy_turns` / `finalize` / `try_escape`），内部委托 `_core`；**新增** `get_core()` / `player_rest()` / `player_use_item()`。
- `data/runtime/combat_character.gd` / `combat_state.gd` / `status_effect.gd`（重写）：双资源 / ATB 运行时字段 / 状态引擎；`CombatCharacter` 增 `effective_attack/defense/crit_rate/dodge_rate/charge_rate` 聚合器。
- `core/utils/seeded_rng.gd`（**新增**，可注入种子的确定性随机源；同 seed 同结果，可存档/回放/单测）。
- `data/configs/abilities/skills.json`（升 v1.2.0：普攻/二式/三式/绝世/轻功/心法/调息 七类，含 `target` / `qi_cost` / `cooldown` / `effects`）。
- `data/configs/abilities/status_effects.json`（**新增**：破甲/强攻/固守/灼烧/中毒/聚气/疾行）。
- `data/configs/scenes/battles.json`（加 `turn_mode`，`battle_bandit_001` = `atb`）。
- `data/configs/npcs/enemies.json`（`speed` 字段被内核消费，作 ATB 集气速率）。
- `tests/unit/test_combat_smoke.gd`（战斗单测扩到 13 项：ATB 顺序 / 真气冷却 / DoT tick / 确定性同 seed）。

## 三、其他窗口写代码时的配合约定

1. **战斗内用药走 `CombatService.player_use_item`**，切勿直调 `InventoryService.use_item`（后者结算到 `PlayerState`，战斗面板不刷新，且 `finalize` 快照回写会覆盖恢复量——吃过药等于白吃）。
2. **状态数值由内核托管**：DoT/HoT/属性修正/层数/持续一律在 `CombatCore.tick_unit` 里走，演出层只读 `CombatEvent` 演出，不要自己改 `CombatCharacter` 字段。
3. **确定性测试陷阱**：`combat_service` 是单例，每个 run 必须「开战 → 行动 → 记录」自成一体；先开两次战再行动会让两次行动都作用在最后一次激活态（已栽过，`test_deterministic_same_seed`）。
4. **演出层（M2）血条直设**：当前 `CombatEvent` 暂无 `target_hp_after`，M2 会补（属共享契约，届时重跑 `gen_contract`）。
