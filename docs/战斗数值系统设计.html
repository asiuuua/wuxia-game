侠风录 · 战斗数值系统设计

对标《逸剑风云决》战斗数值体系，为本地项目重构一套「可配置、有成长、有判定层次、防数值膨胀」的详细数值系统。输出属性换算、伤害乘区、武学维度、敌人难度刻度与全流程量级曲线，并映射到现有 Godot 代码与 JSON 配置表。

1方案概览与目标

本地项目当前的战斗判定偏「线性」「单层」：伤害 = 威力 − 防御×0.5，属性仅 hp / attack / defense / speed / crit / mp 六个维度。早期可用，但在中后期会出现：防御线性减伤导致坦克不可控、攻血无法按统一曲线设计、只有单暴击、武学无阶层与成长弧度。

本次设计借鉴《逸剑风云决》成熟三层结构——五维根属性 → 战斗面板属性 → 判定属性，引入双暴击（会心 / 会意）、命中判定（精准 / 擦伤）、乘区伤害与属性攻击体系，落到现有配置表上，做到「改造不重写、逐表可开关」。

设计原则：① 数值全部进 JSON 配置，代码只读取不硬编码；② 旧配置在「简化模板」下无感兼容；③ 每条曲线给出公式与抽样档位，便于数值策划调参。

2逸剑风云决数值扒解

2.1 五维属性 → 战斗属性换算

逸剑风云决通过「体 / 御 / 劲 / 敏 / 势」五维派生面板属性，装备与升级只涨五维，把「堆哪一维」变成流派选择。

五维转化目标换算系数流派取向
体气血最大值+62 / 点血厚
御外功防御+0.6 / 点肉盾
御气血最大值+16.95 / 点
劲最小外功攻击 / 最大外功攻击+0.17 / +1.41 每点输出
敏会心率 / 最小外功攻击+0.081 / +0.9 每点
势最大外功攻击 / 会意率+0.9 / +0.035 每点
启发：攻击是「最小 / 最大」区间而非单一值——这是「擦伤 / 会意」判定的根基；「劲 / 敏 / 势」分别驱动区间两端与两种暴击，天然形成 build 分支。

2.2 判定属性：双暴击与命中层次

逸剑风云决的「暴击」被拆成两条并行曲线，命中失败不再是 miss=0，而降级为「擦伤」。

判定属性触发效果关键约束
精准率决定是否「精准命中」未精准 → 进入擦伤分支
会心率伤害 +40%，治疗 +50%仅精准命中后可触发；上限 80%（直接会心另 +20% 突破）
会意率伤害 +25%，且必定按攻击最大值结算不受精准限制，命中与擦伤皆可触发；上限 40%
擦伤转化率把「擦伤」转回普通伤害的概率擦伤基于最小值结算、不可暴击

结算流程：攻击 → 判精准命中？
· 命中 → 判 会心（+40%）且同时判 会意（+25%、按最大攻）→ 两者可同时叠加
· 未命中 → 判 擦伤（按最小攻、不暴击）或 会意

2.3 特殊属性（乘区词条）

维度攻击侧防御侧
外功外功穿透 / 外功伤害加成外功抗性 / 外功伤害减免
属性属攻穿透（鸣金/裂石/牵丝/破竹）、属攻伤害加成、属性治疗（牵丝）属攻抗性 × 4

属性攻击不是特效攻击，而是「额外攻击区间」：武学天赋突破到三重时，对应属性带来额外伤害，对应属性额外 +50% 伤害。

武学按兵刃分为剑 / 刀 / 拳 / 暗器 / 棍；招式按阶位分层，与真气消耗、冷却节奏强绑定。

8伤害计算公式（乘区体系）

核心改动：线性防御减伤 → 带软上限的乘区减伤，并把伤害拆成多个相乘因子，便于各配置表独立调参。

单段伤害 =
· 基础区间：base = rand(min_atk, max_atk)（未命中段用 min_atk）
· × 武学威力：power_mult（普攻 1.0 ~ 绝式 6.0，见 §9）
· × 暴击倍率：会心 ×1.40、会意 ×1.25（可叠加 → ×1.75）
· × 增伤乘区：(1 + 外功伤害加成 − 目标外功伤害减免)
· × 属性克制：(1 + 属性额外加成)，对应属性 +50% 封顶
· − 防御减免（非线性，软上限）→ 先经 穿透 削弱敌方防御
· → max(1, 最终)，再经护盾吸收 / 反弹 / 血量结算（沿用现有）

防御软上限公式（替代 −def×0.5）：

reduction = 1 − K / (K + 有效防御)
其中 有效防御 = max(0, 防御 − 减益 − 外功穿透)，K 为常数（建议初值 60，存配置表）
意义：防御越高单点收益越低，从「线性堆防无限减伤」变为「曲线趋近上限」，避免后期攻防数值崩坏，也让 穿透 真正有意义。
防御值旧式减伤 def×0.5新式减伤 K=60备注

6030（线性）30.0（50%）收益拐点

14状态效果与控制体系（封招 / 点穴定身 / 流血…）

前 13 章解决了「伤害 / 暴击 / 成长」等判定层，但本地 status_effects.json 目前只有 flat 属性修正 + 少量 DOT（破防 / 聚气 / 守拙 / 灼烧 / 中毒），缺「控制类」主态（封招 / 点穴定身 / 锁足 / 闭气）与完整的结算 / 驱散 / 抗性体系。本章深扒回合制网游（梦幻西游、大话西游、问道、神武、阴阳师、剑网三、崩铁）并补充此缺口——它是把「数值战斗」升级成「有博弈的战术战斗」的关键一环。为贴合武侠题材，本体系所有状态统一采用江湖武学命名（封招 / 点穴定身 / 走火入魔 / 罡气护体…），英文 id 作为技术键保持不变。

设计原则：① 所有状态走 JSON（status_effects.json 扩展），代码只读取不硬编码；② 状态分「可驱散 / 印记 / 特殊」三层，明确互斥与结算时机；③ 全套默认弱化，未配置即为高容错基线，向后兼容。

14.6 结算时机与优先级（核心法则）

结算顺序（参照「回血先、扣血后」）：
① 回合开始：中毒（扣血/扣蓝）→ 瘴毒扩散 → 出手
② 行动中：真伤 / 反震 / 噬血 / 灼伤受击触发；控制类效果在此段生效
③ 回合结束：灼伤 → 流血 → 蛊咒反噬 → 调息回血 / 回蓝（治疗类）→ 自然递减 / 生效计数

必须固定：① 回血类最后结算，避免「先回后伤」误判；② 点穴定身 / 昏睡等「无法行动」状态覆盖所有行动判定；③ 持续伤害在解控 / 免死后仍继续按回合结算，除非另有互斥；④ 点穴定身期间受击：先扣「冰劲封体」血量再判定是否伤血（可配 freeze_takes_no_real_hp，默认定身期间不受真实伤害）。

14.8 驱散 / 净化 / 解除三层

层目标规则
驱散去除目标身上可驱散的增益 / 减益（敌方增益 / 我方减益）可指定「清己方减益 / 清敌方增益」；驱散不受效果命中与抵抗影响
净化仅清「可驱散」层级的己方负面（如清心诀）不能清印记与特殊状态
解除移除指定「特殊」不可驱散状态严格按状态 clearable_by 白名单

多个状态同屏时按「队列顺序」从后往前清；建议把关键控制排前以便数值策划调整清取优先级。

14.11 实施建议

  • 阶段 B2（判定后）：先把「结算时机两段式 + is_locked 拦截 + 驱散三层」框架接入 combat_core，全部默认弱化，行为不回归。
  • 阶段 C2（内容）：status_effects.json 建档核心 8~12 状态（§14.9，武学命名），招式 / 丹药 / 敌人引用 display_name。
  • 阶段 D2（调参）：按「封招命中率 40~45%、点穴定身追一口冰劲护体血量」等口径跑回合模拟，校验控制链上限与首领最低保护。
验收：控制类状态全流程不掉链子——施加 → 效果命中 vs 抵抗 → 行动拦截 → 回合结算 →（递减 / 免疫 / 驱散）回避死；旧状态在缺省字段下行为与现在完全一致。
本文档为数值方案设计，落地代码改动需先经双闸门验证并按提交队列（架构窗口）统一 flush。所有新增/扩展 JSON 字段保持缺省兜底兼容。
