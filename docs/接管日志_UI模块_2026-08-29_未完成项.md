## 6. 已知坑（本轮已踩过，勿再踩）

- **⚠️ 沙箱 git 视图不可信（本轮头号坑）**：Bash 沙箱内的 `git status`/`git diff` 可能显示"25 修改+6 未跟踪"或把已跟踪文件显示成 HEAD 内容，**与真实磁盘不符**。判定"改动是否落盘"必须以 **unsandboxed** 的 `git status`/`git diff HEAD` + 直接 `Read` 文件为准。本轮曾据此误判"VFS 拦截已跟踪文件写入、9 文件未落盘"，实则早已提交——**切记先 unsandboxed 核实，别重做已完工**。
- **中文文件名 git 编码陷阱**：`git add "中文路径.md"` 字面传参会被双重编码成乱码幽灵条目（如 `代码审查`→`代码析`）。安全做法：用 `git add -- "$(git diff --name-only | grep '^docs/')"` 或 glob `git add docs/UI*` 让 shell 展开正确字节，避免中文字面量。
- **退出码不传播**：GATE2 靠"套件：… 失败 N"的 N 判成败，勿信 `$?`。
- **typed Array 禁 `as Array[String]`**（崩）→ 循环 append；`mini/maxi` 仅 2 参 → 多参嵌套。
- **EventBus 双源**：共享地基信号已在 master（`popup_close_requested`/`ui_action_requested`/`item_used_in_battle`/`notify_skill_bar_changed`/`notify_skill_cd_update`/`notify_quest_track_changed`），改前先 grep 确认是否已有，避免重复声明级联 Parse Error。
- **`add_child busy` / 存档解析 ERROR** 是测试环境固有噪声，不计入套件失败（失败数=0 即绿），无需为它们改代码（除非某套件真带 ✗）。
