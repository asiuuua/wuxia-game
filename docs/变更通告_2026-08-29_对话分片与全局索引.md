# 变更通告：对话系统工业化扩容 P1 —— 分片 + 全局索引 + 懒加载 + 自动卸载

**日期**：2026-08-29
**模块**：对话系统（工业化扩容第一阶段，对应"前置核心定位"方案第 2.1/2.2/2.3 节）
**原则**：不推翻现有代码、不重构业务逻辑，仅在数据层 + 加载层做工业化升级（JSON 铁律 / Service 持逻辑 / EventBus 不变）。

## 背景与痛点

原 `data/configs/npcs/dialogs.json` 为**单文件全量加载**：启动即把全部台词解析进内存，百万字后加载卡顿、内存暴涨；NPC 台词无索引、无分包，查找遍历全量数据。

## 改动内容

### 1. 数据分包分片（废弃单文件）
- 原单文件 `dialogs.json` 拆分为 **per-dialog 分片**：`data/configs/npcs/dialogs/shards/<dialog_id>.json`，每段独立成文件（单文件台词上限由分片自然约束）。
- 旧 `dialogs.json` 已删除（不再被加载）。

### 2. 全局索引表（O(1) 定位，不存文本）
- 新增 `data/configs/npcs/dialogs/_index.json`：`dialog_id -> {file, npc_id, chapter}`，只存映射、KB 级常驻，**不存任何台词文本**。
- `ConfigManager` 启动**仅加载索引**，不再加载任何台词分片。

### 3. 按需懒加载 + 闲置自动卸载
- `ConfigManager.get_dialog(id)`：命中缓存直接返回；否则按索引加载对应分片并缓存。
- 闲置回收（`_sweep_idle_dialogs`）：超过 `DIALOG_IDLE_TTL_MS=2000ms` 且未被 pin 的分片自动从缓存释放；超 `DIALOG_CACHE_MAX=256` 时按最近访问淘汰最久未用。
- **pin/unpin 保护**：`DialogueService.start` 时 `pin_dialog` 锁定当前对话分片，`_terminate_session` 时 `unpin_dialog` 释放，避免会话中途被回收。

### 4. 接口纯追加（不破坏既有调用）
- `ConfigManager` 新增：`pin_dialog / unpin_dialog / unload_dialog / get_all_dialog_ids`。
- `DialogueService` 仅在 `start`/`_terminate_session` 接入 pin/unpin，其余逻辑不变。
- `has_dialog` 改查索引（`_dialog_index`），`get_dialog` 保持 O(1)。

## 验证

- 单测新增 3 项（`test_dialogue_service.gd`）：
  - `test_dialog_lazy_load_and_unload`：懒加载 + 显式卸载 + 卸载后重载。
  - `test_dialog_pin_blocks_unload`：pin 后 `unload_dialog` 不释放，unpin 后释放。
  - `test_active_session_pins_shard`：对话进行中分片被 pin、结束后解除。
- 双闸门（--quit 零硬错 / run_all 零 ✗）通过。

## 性能收益

- 启动内存：从"全量台词"降为"仅索引（KB 级）"，百万字台词不占启动内存。
- 运行期：仅当前/近期对话分片驻留，闲置 2s 后释放，内存有界（≤256 段）。
- 检索：索引 O(1) 定位分片文件，告别遍历全量。
