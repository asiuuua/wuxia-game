# 变更通告 · UI 图标替换接口预留（2026-08-29）

## 1. 变更概述
- **类型**：接口预留 / 基础设施（无生产玩法改动）
- **窗口**：UI 窗口（主权内）
- **性质**：为"后期美工加图标、替换图标"预留统一解析接口与资源目录；当前项目零图标资源，正是最佳介入点
- **关联派单**：无（纯 UI 主权，不触发跨窗 emit 改动）

## 2. 背景与动机
用户指出后期会有美工给物品/技能/NPC/状态/界面按钮设计图标，需要"替换图标让游戏更美观"，但要求美术**不碰代码**。此前项目 `resources/` 下无任何图片资源（UI 全代码绘制），故现在定下接口成本最低。

## 3. 决策结论
- 所有图标资源集中在 `resources/icons/<分类>/<名>.<ext>`，按 `id`（不含扩展名、可带子目录）引用。
- 取图标唯一入口 `UIManager.get_icon(id)`（底层 `scenes/ui/icon_registry.gd`）：找不到返回统一占位图（品红棋盘），**永不返回 null**。
- 数据配置用固定字段 `"icon": "<id>"` 引用（items/skills/relations/status 由各主权窗口自行接入）。
- 美术加图=丢文件+（首次）写一行配置；换图=同名覆盖。零代码。

## 6. 验证（双闸门 + 图标自测）
- 门禁① `Godot --headless --quit`：零 `SCRIPT/PARSE/COMPILE/ERROR`（会顺带导入新 PNG 样例）。
- 门禁② `tests/unit/run_all.tscn`：新增 `test_icon_registry` 6 项全绿，全工程套件无 `✗`。
- 重点验证：缺图标返回非 null 占位图（不崩）；`_sample/sample_heart` 正确加载；带子目录 id 解析；缓存命中；`UIManager.get_icon` 委托有效。

## 7. 后续动作（各窗口按节奏接入，不阻塞）
- 背包窗：`ItemSlot` 接 `UIManager.get_icon(item.icon)`。
- 战斗窗：`skills.json` / `status_effects.json` 补 `icon` 字段 + 技能栏/buff 条渲染。
- 结缘窗：`relations.json` 补 NPC `icon` + 头像渲染。
- UI 窗（v2）：技能栏格子、菜单按钮图标接 `get_icon`。
- 美术：按 `resources/icons/README.md` 丢图即可。
