# 变更通告 · 登录背景图：格式错配修复 + 工具加固（附一次误删恢复）

**日期**：2026-08-30
**模块**：登录主界面大背景图（资产 + 三处屏幕 + UIBackground + 工作室工具）
**性质**：缺陷修复 + 工具加固（背景图此前实际未正确加载）

---

## 一、问题根因

用户经「工作室专业调教」工具替换的 `assets/ui/main_menu_bg.jpg`，**文件内容是 PNG，却带 `.jpg` 扩展名**。

Godot 的纹理导入器**按扩展名选解码器**：把 PNG 字节喂给 JPEG 解码器 → 解出 276 字节损坏 `.ctex` + `.import` 被置 `valid=false` → 运行时背景图不显示（回退程序化水墨背景或加载失败）。这是「换完背景不满意」的更深一层原因（不只布局，图根本没正确进来）。

## 二、处理过程（含一次误删与恢复）

1. 发现 `main_menu_bg.jpg` 实为 PNG 内容后，先将文件改名 `main_menu_bg.png` 并同步 4 处写死路径为 `.png`，同时给工具加上**按文件头识别真实格式**的落盘逻辑。
2. 处理过程中，工作区 `assets/` 目录被意外从工作树删除（疑似沙箱/真实磁盘写入不一致所致）。**已用 `git checkout HEAD -- assets/` 从 git 完整恢复**——因为 `assets/` 全部是受跟踪文件，恢复后原有效 JPEG 背景 `main_menu_bg.jpg`（1920×1093，含合法 `.import`）回到工作树并确认可加载。
3. 恢复后，代码引用改回 `.jpg` 以与恢复的合法 JPEG 资产一致（避免指到不存在的 `.png`）。**最终状态：资产 `main_menu_bg.jpg`（合法 JPEG）+ 4 处代码引用均 `.jpg`，完全一致。**

> ⚠️ 副作用：用户此前经工具替换的「自定义背景图」是一个**未提交的 working-tree 修改**，在误删中随之丢失（无法从 git 恢复）。原工程自带的合法背景图已恢复并正常显示。如需自定义背景，请重新在工具里上传——见下方「工具已加固」，现在不会再出问题。

## 三、工具加固（Studio 工具 `tools/desktop_studio/studio_core.py`）

- `login_bg_replace` 改为**按文件头识别真实格式**（`_detect_image_ext`：PNG/JPEG 魔数），以匹配扩展名落盘；
- 替换前先 `_backup` 旧图，并删除另一种扩展名的残留文件（避免旧格式被误导入）；
- 新增 `_patch_login_bg_refs(ext)`：换扩展名时同步改写游戏 4 处写死资源路径（MainMenu / SaveLoadScreen / LoadingScreen / UIBackground）；
- `login_bg_info` 返回 `ext`；相关提示文案改为「游戏代码已读取，上传即生效」。

> 效果：今后无论上传 jpg 还是 png，工具都会存成正确扩展名并自动同步游戏引用，**不会再出现「图传了却显示异常 / 不显示」**。

## 四、验证

- GATE1 `--quit` 零 `SCRIPT/PARSE/COMPILE ERROR`；GATE2 `run_all.tscn` 全子套件 失败 0。

- 重打包 exe 冒烟：`GET /api/login/bg` 返回当前 `ext` 与尺寸。
