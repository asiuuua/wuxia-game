# 变更通告 · 背包窗口 · 负重真化（2026-08-29）

> 窗口：背包窗口 ｜ 依赖：PlayerState.strength（只读）｜ 类型：P1 能力补全 + 存量 bug 修复
> 生成器：`tools/gen_contract.gd` 已重跑，契约总表已收录 `get_max_weight`。

## 一、本次改动内容

### 1. 真负重公式落地（原"假负重"修复）
- 新增常量 `ItemConstants.STRENGTH_WEIGHT_COEFF := 2.5`（只增不改，背包窗口主权）。
- 新增公开方法 `InventoryService.get_max_weight() -> float`：
  `max = BASE_MAX_WEIGHT(50) + strength * COEFF`。力量成长后负重上限自动提高。
- `add_item` / `query_add` 现在**同时受槽位与负重双重约束**：超重即停止放入，剩余走 `inventory_add_overflow` 事件（掉落/发奖等未预检方据此提示玩家；商店/锻造/炼药走预检则整体失败，不丢钱不丢料）。
- `_recalculate_weight` 发射的 max 由写死的 `BASE_MAX_WEIGHT` 改为 `get_max_weight()`，事件订阅方（含 UI）拿到的是真上限。

### 2. 测试基建加固（无功能变更，隔离存量用例）
- `test_inventory_service` / `test_phase2_pilot` 的"满包"用例原本用武器（单件 3.5 重）填 30 格，现被真负重卡住（力量 10 只能装 21 件）。已在这些用例里临时拉高 `PlayerState.strength` 隔离槽位逻辑，并新增 `after_each` 复位力量，杜绝跨用例/跨套件污染。
- 新增 3 条负重回归用例：`get_max_weight` 力量耦合 / `query_add` 重量限制 / `add_item` 卡负重上限并正确发溢出。

### 3. 双闸门结果
- `--quit` 脚本错误：**0**（中途抓到 1 个 `mini()` 三参编译错误，已当场修正，未流入）
- `run_all.tscn`：**5 套件 50 用例 0 失败 0 跳过**（原 47，背包套件 +3）

## 二、影响范围
- **影响**：战斗（掉落受负重上限约束，玩家可能捡不全）、商店/锻造/炼药（超重时购买/产出整体失败，reason 仍为 `BAG_FULL`）、UI（负重显示需接真上限）。
- **不影响**：存档数据结构、装备逻辑、任务推进、门派。
