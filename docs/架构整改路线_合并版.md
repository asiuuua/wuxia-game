---

## 零、一句话结论

**当前是"可玩的多个系统原型"，不是"可持续生产大型 CRPG 内容的平台"。**
不推倒重来，做**底层接缝重构 + 渐进迁移**。
最急的不是统一代码风格，而是**止血**：数据正在漂移，已写好的区域剧情运行时根本解释不了。

## 三、领域覆盖对照（对外部文档的答复）

**结论：系统确实按领域划分，不是按表堆的 —— 这道分水岭我们已过。**
`services/` 与 `data/configs/` 均为领域结构。

| 领域 | 状态 | 说明 |
|---|---|---|
| Combat | ✅ 最完整 | combat_core/battle_entity/grid/view/director + `battles`\|`combat` |
| Relationship | ✅ 超预期 | 婚配/名分/子嗣/结义/师徒齐全 |
| Item / Faction(sect) / Economy(shop) / Tools | ✅ | 均有独立服务与配置 |
| Quest | ⚠️ | 无 conditions/branch/chain，目标类型写死 |
| Narrative | ⚠️ | dialogue 强，Story/Chapter/Scene/Cutscene/Lore 无独立领域 |
| World | ⚠️ | 有两套区域（见问题 1） |
| Character | ⚠️ | Stats/Talent/Trait 偏弱 |
| AI | ❌ 缺失 | 需新建领域 |

**结构判定（重要，其他窗口勿改）**：
顶层保持 **`autoload → core → data → services → scenes → resources`（层优先）**，
**不改成文档主张的域优先顶层**。理由：① 单向依赖铁律靠此分层强制；② Godot 工程惯例；③ 单人 2D 项目改成域优先是纯 churn 零收益。

**Core 原语覆盖 5/10**：缺 **ID / Command / Condition / Tag / Reference**。补齐这 5 个 = 下面的 P3。

## 四、整改路线

### P0 止血（最急 —— 不停双写，后面全白做）

| 项 | 动作 | 验收标准 |
|---|---|---|
| a 基线 | 盘点 158 项变更并分类；flush 提交队列；用**变更通告**向各窗口宣布冻结扩张 | 工作区干净或全部有主，冻结已通告 |
| b **停双写** | 冻结 `town_npcs.json` 写入链：`addons/content_studio/npc_panel.gd` + `tools/story_import/convert.py`，改为只读兼容或下线 | **无任何工具再写旧真源** |
| c 一键验证 | 新建 `tools/verify_all.py`（串 GATE1 + GATE2 + JSON 校验） | 一条命令可复现全绿 |
| d 构建阻断 | "JSON 可解析"从运行后 `push_error` 升级为构建期阻断 | 坏 JSON 无法提交 |

**158 项变更实测分类**（重要：外部评估高估了风险）：

| 目录 | 数量 | 性质 |
|---|---|---|
| resources | **113** | 纹理压缩 `.import`/`.bak` 机械改动，**非架构问题** |
| docs | 17 | 文档 |
| data | 13 | 配置（需 triage） |
| tools | 6 | 工具 |
| .workbuddy | 4 | 记忆 |
| scenes / tests / assets / 其他 | 4 | 需 triage |
| **合计** | **158** | M=129 / ??=25 / D=4 |

→ **真正需要 triage 的只有约 45 项**，113 项是机械改动。

### P1 统一区域真源

- 保留 `data/configs/regions/<id>/`（已有剧情内容），把 `world/regions.json` 的传送连接并入 `RegionDefinition.connections`。
- **强制：区域 ID = 世界传送 ID = 内容分片 ID**（同一个概念，三处不得各自一套）。
- 禁止"先加载全局表、区域后覆盖"的隐式优先级。
- 验收：新增一个区域只需新增一个目录 + 一条索引；运行时 / 地图 / 编辑器 / 导入器解析同一份定义。

### P2 让已写好的内容真正跑起来（当前最痛）

- 统一区域对话协议：`speaker`/`choices`/`effects` 与 `speaker_id`/`options`/`cond`/`trigger_events` 归一（适配转译或改数据）。
- 补齐 `effects` 命令处理器（`set_flag:` 等）。
- 补登记漂移内容（如 `newbie_village` 漏登记的 `nv_qg_demo`）。
- 验收：`newbie_village` 全部分片能被对话服务正常解释并跑通一条完整链路。

### P3 统一 Condition / Command（由原 P0 下调）

> 下调理由：**数据漂移比代码重复更致命**。条件重复只是"以后加功能麻烦"，双写 + 剧情跑不了是"现在就在坏"。

- 三套条件方言 → 统一 `ConditionSpec` DSL（`all`/`any`/`not` + 类型化条件）。
- 命令执行器 + `quest_graph.gd` action → 接入统一 `CommandDispatcher`，各领域注册处理器。
- 任务目标类型改 handler 注册表（新增目标 = 新增数据/handler，不改 `quest_service`）。
- EventBus **短期保留为 adapter**，逐模块迁移，不一次性删除。
- 验收：新增一种条件/命令/奖励 = 加数据 + 注册 handler，**不改核心服务**。

### P4 状态所有权与存档

- 砍掉好感三重真源，**只留 `RelationshipState`**（删除 `GameState.affinity` 与 `FlagStore` 的 `favor:` 写入）。
- 装备实例建稳定 `instance_id`，槽位存实例引用而非模板 ID。
- 保存当前区域 / 地图坐标 / 内容包版本。
- 存档迁移：**发布前可从简**（版本不符直接判不兼容并提示），不必现在建 vN→vN+1 迁移器。

### P5 工具边界（轻量版）

- 编辑器直写 JSON 保留（单人开发的即时生效优势）。
- 补**校验器 + 引用索引**（能查"这个 NPC/任务/flag 被谁引用"）。
- 事务式导出：校验失败不写入正式运行时内容。

## 五、明确不做（防过度设计，其他窗口勿越界）

| 不做 | 原因 |
|---|---|
| 全量 ID 类型化迁移（`base:npc.xxx` + `{kind,id}`） | 大爆炸改名风险 > 收益。**新内容用新规范，老内容走 adapter** |
| 顶层改域优先结构 | 见第三节结构判定 |
| authoring→compile 完整导出流水线 | 直写即时生效是单人优势；只补校验器 + 引用索引 |
| DLC / Mod / ContentPackManifest | 单人项目，无此需求 |
| 100 / 1000 张表、完整 ER、Data Dictionary | 当前仅 4 条任务，做了是纸面架构 |
| 存档 vN→vN+1 迁移框架（现阶段） | 发布前无真实老存档，可从简 |
| 把所有状态塞进更大的 GameState | 只是把"多个真源"变成"一个上帝对象" |

## 六、执行纪律（铁律，违反即回滚）

1. **增量小步**：每步一个提交，每步可回退。严禁一次性大重构。
2. **双闸门必过**：每次改动后 GATE1（`--headless --quit` 零错误）+ GATE2（`run_all.tscn` 零 ✗）全绿才可提交。
3. **精确 add**：`git add <具体文件>`，禁 `-A`；不提交其他窗口的文件。
4. **共享地基先通告**：动 `EventBus` / `ConfigManager` / `core/enums` / `screens.json` / `strings.csv` 前，必须 handoff 派单 + `change_log.py notice` 变更通告 + PM 认可。
5. **留痕**：`change_log.py add` 登记；`MEMORY.md` 同步关键决策。
6. **验证前先 commit**（沙箱 git 不落盘），且 `.godot` 缺失 = 全崩，勿删。
7. **JSON 用 `JSON.new()` + `parse() != OK`**；`Color()` 写满 4 参；`mouse_filter` 装饰子节点必须 IGNORE(2)。
