## 3. 重点文件分析

### 3.1 P0：核心单点（目录迁移必改）

**`autoload/ConfigManager.gd`**（29 行路径定义）
- 集中定义所有配置表路径：abilities、items、npcs、quests、dialogs、combat、alchemy、forge、shop、sect、bond、world、ui、difficulty、maps、regions、content_schemas 等
- 是目录迁移的**核心单点改造点**——改一个文件可覆盖 30+ 路径

### 3.2 P1：工具层（批量替换 + 回归验证）

tools/ 下 33 个文件，92 行引用。主要集中在：
- **校验器组**（ref_index、id_validator、schema_validator、schema_guard、region_validator、localization_validator、pack_manifest_validator、check_crossref）：扫描面路径硬编码
- **DataSink / 服务层**（data_sink.py、各 service / repository）：读写路径
- **生成器**（gen_icons、build_content_indexes）：输入/输出路径
- **工作室工具**（studio_smoke、desktop_studio/*）：夹具路径

工具层可脚本化批量替换，用 GATE6/7/10/11 回归验证。

### 3.3 P2：生产代码（Godot 侧全局替换）

scenes/ + services/ + application/ + addons/ 共 23 个文件，37 行引用。
- 大部分是 UI 界面读配置表
- 可 Godot 编辑器全局替换 + GATE1 编译验证兜底

## 6. 关键发现

1. **ConfigManager 是核心单点**：29 行路径集中定义，改一处覆盖大半生产代码引用
2. **工具层引用占比最高**（92/176 = 52%）：但有完整门禁体系兜底，批量替换风险低
3. **注释中引用占一定比例**：约 15~20 行是注释/文档字符串，迁移时同步改即可
4. **无 user:// 路径**：所有 data/configs 引用均为 res:// 或相对路径，符合数据只放资源目录的设计
