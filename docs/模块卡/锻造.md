# 模块卡：锻造（Forge）

> L2 模块卡 · 主权窗口：**锻造窗口** · 沉淀自真实代码（据实不臆造）

- **职责**：配方锻造（按 `recipes.json` 扣材料产出装备/物品）、锻造可行性预检、配方输入描述。
- **层定位**：服务层（无状态锻造逻辑）+ 数据层（配方配置）+ UI 层（锻造屏）。

## 关键文件
- 服务：`res://services/forge/forge_service.gd`（`class_name ForgeService`，extends RefCounted，**无状态**）
- UI 主权：`res://scenes/ui/screens/forge/ForgeScreen.gd`（screens.json `ForgeScreen`）
- 配置：`res://data/configs/forge/recipes.json`

## 依赖（上游，它用到）
- `ConfigManager`：读 `recipes.json`（配方/材料/产出）
- `InventoryService`：锻造前 `try_consume` 原子扣料 + `add_item` 产出（**走背包事务防资产损失 P0**）
- `EventBus` 信号：`cmd_forge(recipe_id,count)`（**已声明未 emit**，空壳）

## 被依赖（下游，谁用它）
- `ForgeScreen.gd`（唯一直接驱动方：`forge`/`can_forge`/`describe_inputs`）
- `GameManager.gd`（装配 `ForgeService.new()`）
- 单测：`tests/unit/test_forge_service.gd`（BUG-15 补测，`a44ddc4`）

## 对外 API（核心入口）
- `forge(recipe_id,count)→int`（扣料+产出，返回实锻数）
- `can_forge(recipe_id,count=1)→bool`（纯预检：材料足 + `count>0`）
- `describe_inputs(recipe_id)→String`（配方输入人类可读描述，供 UI 展示）
