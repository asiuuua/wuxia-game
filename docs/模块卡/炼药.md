# 模块卡：炼药（Alchemy）

> L2 模块卡 · 主权窗口：**炼药窗口** · 沉淀自真实代码（据实不臆造）

- **职责**：丹药炼制（按 `recipes.json` 扣材料产出丹药）、炼制可行性预检。
- **层定位**：服务层（无状态炼制逻辑）+ 数据层（配方配置）+ UI 层（炼药屏）。

## 关键文件
- 服务：`res://services/alchemy/alchemy_service.gd`（`class_name AlchemyService`，extends RefCounted，**无状态**）
- UI 主权：`res://scenes/ui/screens/alchemy/AlchemyScreen.gd`（screens.json `AlchemyScreen`）
- 配置：`res://data/configs/alchemy/recipes.json`

## 依赖（上游，它用到）
- `ConfigManager`：读 `recipes.json`（配方/材料/产出）
- `InventoryService`：炼制前 `try_consume` 原子扣料 + `add_item` 产出（**走背包事务防资产损失 P0**）
- `EventBus`：炼药**未声明** `cmd_refine` 类信号（与 shop/forge 不同，连空壳信号都无——交易由 AlchemyScreen 直调服务）

## 被依赖（下游，谁用它）
- `AlchemyScreen.gd`（唯一直接驱动方：`refine`/`can_refine`）
- `GameManager.gd`（装配 `AlchemyService.new()`）
- 单测：`tests/unit/test_alchemy_service.gd`（BUG-15 补测，`a44ddc4`）

## 对外 API（核心入口）
- `refine(recipe_id)→bool`（扣料+产出，成功返回 true）
- `can_refine(recipe_id)→bool`（纯预检：材料足）

## 架构备注

- shop/forge/alchemy 三服务皆无状态、皆不实现 ISaveable、皆不进档——是经济/产出类服务的统一范式。
