# 模块卡：存档（Save / Load）

> L2 模块卡 · 主权窗口：**未单独立窗**（SaveManager/GameState/SaveValidator 为共享地基级 autoload 中枢；其 UI 表现 `SaveLoadScreen` 归 **UI 窗口**）· 沉淀自真实代码（据实不臆造）

- **职责**：可存档对象注册、原子写（.tmp→校验→.bak→替换）、读档（损坏回退 .bak + 版本校验 + 分发）、槽位管理（6 槽 + auto）；全局状态唯一真源（GameState）；读档后任务条件校验与修复（SaveValidator）。
- **层定位**：autoload 中枢（共享地基级）+ 接口层（ISaveable）+ UI 层（存档屏）。

## 关键文件
- 管理器：`res://autoload/SaveManager.gd`（`SaveManager`，extends Node，**无 class_name**——注册/原子写/读档/槽位）、`res://autoload/game_state.gd`（`GameState`，extends Node，**无 class_name**——全局状态真源，存档唯一真源）、`res://autoload/save_validator.gd`（`SaveValidator`，extends Node——读档后校验）
- 接口：`res://core/interfaces/i_saveable.gd`（`ISaveable`，RefCounted 抽象基类，约定 `get_save_key()/save()/load()`）
- 落盘：`user://saves/`（代码常量 `SAVE_DIR="user://saves/"`）：`save_<1..6>.json`、`auto_<N>.json`、`.bak`、`.tmp`；`MAX_SLOTS=6`、`SAVE_VERSION="1.0.0"`
- UI 主权：`res://scenes/ui/screens/save_load/SaveLoadScreen.gd`（extends BaseScreen，screens.json `SaveLoadScreen`，`cache:true`）、`components/save_card/SaveCard.gd`、`save_name_dialog/SaveNameDialog.gd`；`EscMenu` 走 `quick_save`
- 已注册 saveable（GameManager，key 列表）：`player_state`(`"player"`)、`inventory_service`(`"inventory"`)、`ability_service`、`quest_service`、`equipment_service`(`"equipment"`)、`sect_service`、`bond_service`(`"bond"`)、`romance_service`(`"romance"`)、`sworn_service`(`"sworn"`)、`master_service`(`"master"`)、`GameState`(`"game_state"`)、`weather_time_service`（经 `register_saveable(state)`）

## 依赖（上游，它用到）
- `EventBus`：`game_saved(slot)`（写/删后 emit）、`game_loaded(slot)`（读档后 emit，SaveValidator 订阅）
- OS 层：`DirAccess` / `FileAccess` / `JSON`（原子写/备份/校验）
- `SaveValidator` 依赖：`GameManager.quest_service`（`fail_quest`）、`GameState.is_unit_alive`、`ConfigManager.get_quest`

## 架构备注
- 原子写 + .bak 回退是防存档损坏 P0 底线；版本校验保前向兼容。
- GameState 为「共享地基」，多服务依赖其全局 flag/单位态，改前须 `change_log query --module` + handoff（避免回归影响全工程）。
- 无独立窗口署名：属核心 autoload 中枢，不在任一业务窗口署名下，遵循「共享地基冻结、跨窗改动先 handoff」铁律。
