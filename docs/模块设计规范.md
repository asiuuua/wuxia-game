> 本规范以用户在对话中提供的《武侠单机游戏业务模块详细设计规范（Godot 4.7）》为**权威设计基线**。
> 全文 11 维（模块定位→功能清单→数据结构→业务逻辑→接口→事件→交互→性能→存档→测试→规划）覆盖 P0–P3 全部模块。
> 下方为**工程落地摘要**与 Phase 1 切片范围决策，详细条款以对话原文为准，本文件不重复粘贴。

## 一、模块分级（优先级）

| 级别 | 模块 |
| --- | --- |
| **P0 核心** | 玩家、背包、装备、武功、战斗、任务、存档、场景、UI |
| **P1 重要** | NPC对话、锻造、炼丹、商店、门派、输入、音频、本地化 |
| **P2 增强** | 马匹、家园、成就、收集、天气时间、探索交互 |
| **P3 可选** | 多周目、难度选择、Mod、手柄震动、拍照 |

## 二、模块间通信铁律（任何阶段不可妥协）

1. 禁止直接引用：A 模块不得 `get_node("/root/...")` 访问 B 模块
2. 事件总线唯一通道：`EventBus`，参数用值类型
3. 依赖注入：模块间调用通过 `GameManager` 注册/获取接口
4. 数据单向流动：业务层 → 事件 → UI 层，UI 层不得反向修改业务数据

## 四、与既有工程标准的关系

- 架构分层 / 事件驱动 / 数据驱动 / 命名规范：**四底线一致**，本规范是业务层数据结构与接口的权威来源。
- 代码编写遵守 `docs/代码规范.md`（腾讯级速查）与 `docs/开发规范.md`（20 章硬性标准）。
- GDScript 4.x 无 `implements` 关键字，接口以「继承抽象基类」实现（如 `extends ISaveable`）。
