# 变更通告 · 对话系统解耦（NPC / 台词 / 对话框）

## 一、需求背景
用户要求：对话框外观/位置固定，但不同 NPC 显示不同台词；NPC、台词、对话框三者解耦；NPC 可随意修改台词、绑定 id。

## 二、对标大厂单机的核心设计
- **View 与 Data 分离**：对话框 `DialogOverlay` 只负责"怎么呈现"，不持有任何具体台词。
- **NPC 只做绑定**：NPC 配置通过 `dialog_id` 字段指向独立台词表 `dialogs.json`。
- **台词表集中管理**：所有对话内容放在 `data/configs/npcs/dialogs.json`，改台词只动一张表。
- **运行时解析规则**：`DialogueService.resolve_for_npc(npc_id, dialog_id)` 优先用 NPC 显式 `dialog_id`，未命中则以 `npc_id` 为键回退，兼容未来一 NPC 多对话分支。

## 三、改动文件

### 新增
- `services/dialogue/dialogue_service.gd`：对话数据服务（`class_name DialogueService`），提供 `get_dialog / has_dialog / resolve_for_npc / get_lines`。
- `tests/unit/test_dialogue_service.gd`：6 项单测覆盖查询与回退规则。

### 修改
- `autoload/GameManager.gd`：新增 `dialogue_service` 字段并在 `_init_services` 实例化。
- `scenes/ui/overlays/dialog/DialogOverlay.gd`：
  - 改走 `UIManager.open_screen` 标准 `_on_open(data)` 入口，接收 `{"npc_id", "dialog_id"}`。
  - 通过 `GameManager.dialogue_service` 查询台词；通过 `ConfigManager.get_npc` 取名字/立绘/任务/战斗入口。
  - 保留 `show_for_npc(npc_data)` 兼容层，内部转调新逻辑。
  - 引入 `_built` 标志，解决 `_on_open` 先于 `_ready` 导致节点未构建的问题（与 `CelebrationOverlay` 一致）。
- `scenes/gameplay/town/TownScene.gd`：`_open_dialog` 改为 `UIManager.open_screen("DialogOverlay", ..., {"npc_id":..., "dialog_id":...})`。
- `data/configs/npcs/dialogs.json`：把原本内联在 `town_npcs.json` 中的 NPC 台词全部迁移到本表，新增 `npc_village_chief`、`demo_npc`、`npc_bandit`、`npc_hunter`、`npc_sect_elder`、`npc_merchant`、`tactical_demo_master` 等条目；保留原有 `dlg_tutorial` 等通用对话。
- `data/configs/npcs/town_npcs.json`：移除所有 NPC 的 `dialogs` 数组，新增 `dialog_id` 字段指向 `dialogs.json` 对应键；保留 `name / portrait / quest_id / battle_id`。
- `tests/unit/test_icon_wiring.gd`：更新 `DialogOverlay` 测试调用为新的 `{id, dialog_id}` 形式。

## 四、使用方式
1. **给 NPC 绑台词**：在 `town_npcs.json` 中给 NPC 加 `"dialog_id": "你想要的键"`。
2. **写/改台词**：在 `dialogs.json` 中新增/编辑同 `id` 的条目，`lines` 为 `{speaker, text}` 数组。
3. **调外观**：改 `DialogOverlay.gd` 的 `_build()` 中面板位置/尺寸/颜色，不影响任何 NPC 台词。

## 五、验证
- Gate1 `--quit`：零 SCRIPT/PARSE/COMPILE ERROR。
- Gate2 `run_all.tscn`：**25 套件 · 0 失败 · 0 跳过**（新增 `test_dialogue_service` 6 项全过）。

## 六、后续可扩展（未本次实现）
- 分支对话/选项：在 `dialogs.json` 条目加 `choices` 字段，DialogOverlay 根据选择切换 `next_dialog_id`。
- 剧情事件脚本：lines 条目加 `event` 字段（如 `{event: "give_item", item_id: "x", count: 1}`），DialogueService 解析后通过 EventBus 派发。
- 编辑器插件：若需要可视化绑定/改台词，可仿 `addons/celebration_manager` 再做 `addons/dialogue_manager`。
