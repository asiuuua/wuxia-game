## 1. 本次做了什么

把上轮预留的图标取图接口（`UIManager.get_icon`）**实际接到三个归 UI 窗口主权的界面**，让物品 / 技能 / NPC 图标显示链路跑通（当前用品红占位图，美术出图后即变真实图）。**全程零数据层改动**——图标 id 直接从已有实体 id 派生。

| 界面 | 文件 | 接线点 | 图标 id 派生 |
|---|---|---|---|
| 背包物品格 | `scenes/ui/components/item_slot/ItemSlot.gd` | 新增 `_icon: TextureRect`（占满槽位核心区，名垂直底部） | `items/<item_id>` |
| 武学屏技能行 | `scenes/ui/screens/abilities/AbilitiesScreen.gd` | `_build_ability_row` 头部前置 40×40 图标 | `skills/<ability_id>` |
| 结缘屏 NPC 行 | `scenes/ui/screens/bond_romance/BondRomanceScreen.gd` | `_row` 行首 36×36 头像 | `npc/<npc_id>`（关系 id） |

空槽 / 缺图时：`ItemSlot` 空槽 `_icon.texture = null`；其余走 `UIManager.get_icon` 的占位图兜底（永不返回 null，防运行期崩溃）。

## 5. 美术接入（零代码）

美术把图标按以下命名丢进 `resources/icons/` 对应子目录即可，游戏自动生效：

- 物品：`resources/icons/items/<item_id>.png`（`<item_id>` 同 `data/configs/items/*` 里的 id）
- 技能：`resources/icons/skills/<ability_id>.png`（`<ability_id>` 同 `abilities` 配置 key）
- NPC：`resources/icons/npc/<npc_id>.png`（`<npc_id>` 同 `data/configs/bond/relations.json` 的 id）
- 敌人：`resources/icons/enemies/<enemy_id>.png`（待战斗窗接线）

换图 = 同名覆盖；加图 = 丢文件。详见 `resources/icons/README.md`（美术大白话）。
