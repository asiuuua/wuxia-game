# 变更通告 · UI 窗口 · 背包溢出全局订阅（handoff 37c9ca18f539）

- 日期：2026-08-29
- 窗口：UI 窗口（收口：UI 模块）
- 来源：背包窗口派单 `37c9ca18f539`（inventory_add_overflow 信号无游戏内订阅方，满包时物品静默丢失）

## 问题
`EventBus.inventory_add_overflow(item_id, lost_count)` 已在背包窗口定义并由 `InventoryService.add_item` 在槽位/超重溢出时 emit，但**全工程无任何游戏内订阅方**（仅 `test_inventory_service.gd` 为单测临时 connect）。结果：掉落/发奖/任何满包 add 失败都静默丢物，玩家无感知。

## 改动
### 1. `autoload/ui_manager.gd`（UI 主权）
- `_ready()` 新增 `EventBus.inventory_add_overflow.connect(_on_inventory_add_overflow)`。放 UIManager 而非 InventoryScreen，因溢出常发生在背包界面未打开时（战斗掉落、任务发奖），全局订阅才能 100% 覆盖。
- 新增处理函数 `_on_inventory_add_overflow(item_id, lost_count)`：解析物品中文名（`ConfigManager.get_item(item_id).name`，缺失回退 item_id），经 `EventBus.notification_show` 弹 Toast：
  `背包已满，%d 个%s未能放入`（lost_count, 物品名）。`lost_count<=0` 短路不提示。

### 2. `data/configs/localization/strings.csv`（共享地基·纯追加，未动任何已有行）
- 追加一行 `ui_inventory_overflow,背包已满，%d 个%s未能放入,背包已滿，%d 個%s未能放入,Backpack full: %d %s could not be stored`（满足共享地基「只增不改」铁律）。

## 影响
- 正向：任何满包/超重导致的物品丢失现在对玩家可见，不再静默。
- 不影响：背包模块逻辑、战斗/结缘/设置窗口、信号/枚举契约（仅新增一处订阅 + 一处翻译 key）。
