# Godot 武侠单机游戏企业级开发规范与标准（硬性标准）

> **性质**：本项目硬性开发标准，所有 Phase 1 起提交的代码必须遵循。
> **适用范围**：Godot 4.x（目标 4.7）工程全部脚本 / 场景 / 配置 / 资源。
> **与 `docs/代码规范.md` 的关系**：`代码规范.md` 是**编码层速查**（命名 / 注释 / 安全 / 腾讯铁律）；本文是**工程全标准**（架构 / 目录 / EventBus / 存档 / 模块 / UI / 性能 / CI 等二十章）。二者冲突时，以本文「四底线」为准。
> **四底线（任何阶段不可妥协）**：架构分层、事件驱动、数据驱动、命名规范。

## 采纳与裁剪说明（针对纯个人初学者）
- **必须尽早落地**：目录分层、`EventBus`、数据驱动（`ConfigManager` / 资源即数据）、`SaveManager`（`ISaveable` 注册）。
- **可暂缓（单人项目）**：Git LFS、CI 自动化检查、PR 双人审批、主机平台导出流程。但这些"流程"的**规范文本保留**，待团队/上线前补齐。
- **GDScript 4.x 修正**（本文已修正原稿错误）：
  - Godot 4 的 GDScript **没有 `implements` 关键字**，接口用「抽象基类 + 继承」实现（见 §10.2）。
  - `@export` 必须带 `var`（原稿 `@export sub_type` 缺 `var`，已补）。
  - `ResourceLoader.load_threaded_request()` 返回 `Error`，异步加载须轮询状态（见 §11.1 修正版）。

## 一、总体架构原则

### 1.1 核心设计理念

```
┌─────────────────────────────────────────────────┐
│                   表现层 (View)                    │
│  Scene / Node / Control / Animation / Audio      │
├─────────────────────────────────────────────────┤
│                  视图模型层 (ViewModel)             │
│  UI State / Binding / Command Adapter             │
├─────────────────────────────────────────────────┤
│                   业务层 (Service)                  │
│  背包/战斗/任务/武功/锻造/存档 等业务逻辑            │
├─────────────────────────────────────────────────┤
│                  数据访问层 (Repository)            │
│  配置表 / 存档 / 缓存 / 资源加载                    │
├─────────────────────────────────────────────────┤
│                   基础层 (Core)                     │
│  事件总线 / 工具库 / 扩展方法 / 常量 / 类型定义     │
└─────────────────────────────────────────────────┘
```

**铁律：**

- 下层不依赖上层，上层通过接口/事件调用下层
- 业务层不持有 Node 引用，所有 Node 操作在表现层完成
- 跨模块通信**只走事件总线**，禁止直接引用其他业务模块
- 数据驱动优先，逻辑与数据分离

### 1.2 Godot 特有架构约束

| 约束 | 说明 |
| --- | --- |
| **场景即模块** | 每个功能模块有且仅有一个主场景入口，内部子节点组织清晰 |
| **Autoload 极简** | Autoload 只放**全局管理器 / 单例**，每个必须有单一明确职责：**不持有业务数据、不直接操作其他模块的 Node、跨模块只走 EventBus**。初期建议 ≤5；随功能增长可扩展，但**新增 autoload 须评审**（见 §1.3 实际清单）。 |
| **信号即事件** | 模块间通信用信号，不用 `get_node()` 跨场景硬引用 |
| **资源即数据** | 配置用 `.tres` Resource 或 JSON，不用脚本里硬编码常量 |
| **节点树即层级** | 运行时节点树深度不超过8层，避免查找和性能问题 |

---

### 1.3 实际 Autoload 清单（本工程）

> 原标准「不超过 5 个」是**初期参考值**。本工程已按功能扩展为下列单例，均符合「Autoload 只做全局管家」原则：**只持有全局状态 / 提供全局能力，不持有业务数据、不直接操作其他模块的 Node、跨模块只走 EventBus**。新增 autoload 须评审（确认它确实是最合适的全局单例，而非应下沉到 `services/` 的业务）。

| Autoload | 职责 | 类别 |
| --- | --- | --- |
| EventBus | 全局事件总线（模块间唯一通信通道） | 核心 |
| ConfigManager | 配置表（JSON/CSV）加载与查询 | 核心 |
| SaveManager | 存档读写、版本迁移、备份 | 核心 |
| AudioManager | BGM / SFX / Voice 播放与音量 | 核心 |
| GameManager | 全局游戏状态、流程编排 | 核心 |
| UIManager | 界面注册 / 打开关闭 / 层级 / Toast | UI 中枢 |
| SettingsManager | 设置项（画面 / 音频 / 控制 / 语言）读写 | 配置 |
| LocalizationManager | 多语言加载与即时切换 | 配置 |
| WeatherTimeService | 天气 / 时辰系统（世界氛围） | 世界 |
| PoolManager | 对象池（子弹 / 伤害数字 / 特效复用） | 性能 |
| PerformanceMonitor | 性能监控（FPS / 内存 / DrawCall） | 调试 |
| ErrorHandler | 全局错误捕获与上报 | 调试 |
| PatchManager | 补丁 / 版本管理 | 系统 |

> 说明：UIManager / SettingsManager / LocalizationManager 是 M4–M6 核心，强行压回 ≤5 会撕裂现有功能、带来高回归风险，故保留并文档化。

## 三、命名规范

### 3.1 脚本与类名

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 脚本文件名 | snake_case | `inventory_service.gd` |
| class_name | PascalCase | `class_name InventoryService` |
| 场景文件名 | PascalCase | `InventoryScreen.tscn` |
| 节点名 | PascalCase（场景根节点）/ snake_case（子节点） | 根：`InventoryScreen`，子：`item_grid` |
| 枚举名 | PascalCase，后缀 `Enum` | `ItemTypeEnum` |
| 常量名 | UPPER_SNAKE_CASE | `MAX_STACK_SIZE` |
| 信号名 | past tense，snake_case | `item_added`、`inventory_sorted` |
| 函数名 | snake_case，动词开头 | `add_item()`、`can_equip()` |
| 变量名 | snake_case | `current_weight`、`item_count` |
| 私有变量 | `_` 前缀 + snake_case | `_inventory_data`、`_dirty_slots` |
| 导出变量 | `@export` + snake_case | `@export var max_slots: int = 30` |
| 接口类 | `I` 前缀 + PascalCase（或抽象基类） | `ISaveable`、`IInitializable` |
| 数据模型 | 后缀 `Data`（静态）/ `Instance`（运行时） | `ItemData`、`ItemInstance` |
| 管理器 | 后缀 `Manager` | `SaveManager`、`ConfigManager` |
| 服务 | 后缀 `Service` | `InventoryService`、`CombatService` |

### 3.2 节点命名约定

```
InventoryScreen (Control)           # 根节点：场景名
├── Background (ColorRect)          # 背景
├── Content (VBoxContainer)         # 内容区
│   ├── Header (HBoxContainer)      # 头部
│   │   ├── TitleLabel (Label)
│   │   └── CloseButton (Button)
│   ├── TabContainer (TabContainer) # 分类页签
│   └── ItemGrid (GridContainer)    # 物品格子
│       ├── ItemSlot_0 (ItemSlot)   # 动态生成，带下标
│       └── ItemSlot_1 (ItemSlot)

```

- 节点名用**功能描述**，不用类型名（`CloseButton` 而非 `Button2`）
- 动态生成的节点用 `名称_索引`：`ItemSlot_0`
- 唯一标识节点用 `@onready` 引用，不用路径字符串硬编码

### 4.1 文件头部模板

```
# inventory_service.gd
# 背包业务服务：管理物品增删改查、容量校验、负重计算

# 作者：XXX
# 创建日期：2025-01-15

class_name InventoryService
extends RefCounted

# === 信号 ===
signal item_added(item_instance: ItemInstance, slot_index: int)
signal item_removed(item_id: String, count: int)
signal weight_changed(current_weight: float)

# === 导出变量（编辑器配置）===
@export var max_slots: int = 30
@export var base_max_weight: float = 50.0

# === 公共变量 ===
var current_weight: float = 0.0

# === 私有变量 ===
var _slots: Array[ItemInstance] = []
var _instance_map: Dictionary = {}  # instance_id -> slot_index
var _dirty: bool = false

# === 生命周期 ===
func _init() -> void:

    EventBus.game_saved.connect(_on_game_saved)
    EventBus.game_loaded.connect(_on_game_loaded)

### 4.2 函数规范

```
# 函数顺序：公共 -> 私有 -> 回调
# 每个函数不超过 40 行，超过则拆分

# 公共函数：有文档注释
## 添加物品到背包
## item_id: 物品配置ID
## count: 数量
## 返回: AddItemResult，包含成功数量、剩余数量、放入的格子索引
func add_item(item_id: String, count: int) -> AddItemResult:
    if not _validate_add(item_id, count):
        return AddItemResult.new(0, count, [])
    
    var added: int = 0
    var slots: Array[int] = []
    
    # 先尝试堆叠到已有格子
    added = _stack_to_existing(item_id, count, slots)
    count -= added
    
    # 再放入空格子
    if count > 0:
        var new_added: int = _fill_empty_slots(item_id, count, slots)
        added += new_added
        count -= new_added
    
    _recalculate_weight()
    _dirty = true
    
    for slot_idx in slots:
        item_added.emit(_slots[slot_idx], slot_idx)
    
    return AddItemResult.new(added, count, slots)

# 私有函数：_ 前缀
func _validate_add(item_id: String, count: int) -> bool:
    if count <= 0:
        return false
    if not ConfigManager.has_item(item_id):
        push_error("Item not found: %s" % item_id)
        return false
    return true

# 回调函数：_on_ 前缀
func _on_game_saved() -> void:
    if _dirty:
        SaveManager.set_data("inventory", _serialize())
        _dirty = false
```

### 4.4 控制流规范

```
# 早返回（Guard Clause），避免深层嵌套
func equip_item(slot_index: int) -> bool:
    if slot_index < 0 or slot_index >= max_slots:
        return false
    
    var item: ItemInstance = _slots[slot_index]
    if item == null:
        return false
    
    if not item.is_equippable():
        return false
    
    if not _can_equip(item):
        return false
    
    _do_equip(item, slot_index)
    return true

# 优先用 match 代替长 if-elif
func get_item_category(item_type: int) -> String:
    match item_type:
        ItemTypeEnum.WEAPON:
            return "weapon"
        ItemTypeEnum.ARMOR:
            return "armor"
        ItemTypeEnum.PILL:
            return "pill"
        _:
            return "other"

# 循环用 for-in，避免索引遍历
for item in _slots:
    if item != null:
        total += item.count
```

## 五、场景与节点规范

### 5.1 场景设计原则

1. **一个场景一个职责**：`InventoryScreen.tscn` 只做背包界面，不包含战斗逻辑
2. **场景可独立运行**：按 F6 能单独打开该场景测试，不依赖外部状态（用 mock 数据）
3. **根节点脚本即控制器**：场景根节点挂主脚本，子节点不挂业务逻辑脚本（纯展示组件除外）
4. **节点引用用 @onready**：不用 `get_node()` 或 `$` 路径在运行时查找

```
# 正确
@onready var _item_grid: GridContainer = $Content/ItemGrid
@onready var _title_label: Label = $Content/Header/TitleLabel

# 错误
func _ready():
    var grid = get_node("Content/ItemGrid")
    var label = $Content/Header/TitleLabel
```

### 5.3 实例化与销毁

```
# 动态实例化用场景常量 + 工厂函数
const ItemSlotScene = preload("res://scenes/ui/components/item_slot/ItemSlot.tscn")

func _create_slot(index: int) -> ItemSlot:
    var slot: ItemSlot = ItemSlotScene.instantiate()
    slot.name = "ItemSlot_%d" % index

extends Node

const SAVE_VERSION := "1.2.0"
const SAVE_DIR := "user://saves/"

var _saveables: Array[ISaveable] = []

func register_saveable(saveable: ISaveable) -> void:
    _saveables.append(saveable)

func save_to_slot(slot_index: int) -> bool:
    var save_data: Dictionary = {
        "meta": _build_meta(),
    }
    
    for saveable in _saveables:
        save_data[saveable.get_save_key()] = saveable.save()
    
    var path: String = SAVE_DIR + "save_%d.json" % slot_index
    return JSONUtil.save_json(path, save_data)

func load_from_slot(slot_index: int) -> bool:
    var path: String = SAVE_DIR + "save_%d.json" % slot_index
    if not FileAccess.file_exists(path):
        return false
    
    var data: Dictionary = JSONUtil.load_json(path)
    
    # 版本迁移
    data = _migrate(data)
    
    for saveable in _saveables:
        var key: String = saveable.get_save_key()
        if data.has(key):
            saveable.load(data[key])
    
    EventBus.game_loaded.emit(slot_index)
    return true

func _migrate(data: Dictionary) -> Dictionary:
    var version: String = data.get("meta", {}).get("save_version", "0.0.0")
    if version == SAVE_VERSION:
        return data
    
    # 按版本号逐步迁移
    if version == "1.0.0":
        data = _migrate_1_0_to_1_1(data)
        version = "1.1.0"
    if version == "1.1.0":
        data = _migrate_1_1_to_1_2(data)
        version = "1.2.0"
    
    data.meta.save_version = SAVE_VERSION
    return data
```

- **存档前做数据校验**，非法数据不写入
- **自动备份**：覆盖存档前备份上一版，保留最近3个备份
- **关键物品不可丢失**：加载时检测剧情关键物品，缺失则恢复或告警

    # 状态为 THREAD_LOAD_LOADED 后调用 ResourceLoader.load_threaded_get(path)
    # 简化回退（小资源可用同步）：
    # callback.call(ResourceLoader.load(path))
```

### 11.2 资源缓存

```
# 图标缓存：避免重复 load
class_name ResourceCache
extends RefCounted

var _texture_cache: Dictionary = {}
var _scene_cache: Dictionary = {}

func get_texture(path: String) -> Texture2D:
    if path == "":
        return null
    if not _texture_cache.has(path):
        _texture_cache[path] = load(path)
    return _texture_cache[path]

func get_scene(path: String) -> PackedScene:
    if not _scene_cache.has(path):
        _scene_cache[path] = load(path)
    return _scene_cache[path]

func clear() -> void:
    _texture_cache.clear()
    _scene_cache.clear()
```

### 11.3 纹理规范

- 图标统一尺寸：`64x64` 或 `128x128`，PNG 格式
- 背景图：`1920x1080`，压缩纹理（VRAM 压缩）
- 导入设置：图标关闭过滤（像素清晰），背景开启过滤
- 命名：`模块_功能_状态.png`，如 `item_sword_common.png`、`btn_close_hover.png`

### 11.4 音频规范

- BGM：OGG 格式，循环点在元数据中标记
- SFX：WAV 格式，短音效（<3秒），采样率 44100Hz
- 命名：`sfx_模块_动作.wav`，如 `sfx_inventory_pickup.wav`、`sfx_combat_hit.wav`
- 音量分级：BGM 0.6、SFX 0.8、Voice 1.0

## 十六、性能规范

### 16.1 帧率目标

- 目标：**稳定 60 FPS**（最低 30 FPS）
- UI 打开/关闭动画：不掉帧
- 大场景（城镇/战斗）：稳定 60 FPS
- 加载场景：异步加载，显示进度条，不卡死

### 16.2 性能红线

| 项目 | 红线 |
| --- | --- |
| 单帧 _process 耗时 | < 16ms（60FPS） |
| UI 节点总数 | < 500（单界面） |
| 背包格子渲染 | 虚拟列表，只渲染可见区域 |
| 存档读写 | < 500ms（异步） |
| 配置表加载 | < 1s（启动时） |
| 内存占用 | < 2GB（PC） |
| Draw Call | < 500（UI） |

### 16.3 性能优化手段

- **UI 虚拟列表**：1000格背包只渲染可见的 ~30 格
- **对象池**：子弹、伤害数字、特效用对象池复用
- **纹理图集**：UI 图标打包成图集，减少 Draw Call
- **延迟加载**：非紧急资源异步加载
- **信号防抖**：频繁事件（如物品移动）合并刷新
- **避免在 _process 中做查找**：`get_node()`、`find_child()` 缓存到 `@onready`

## 十九、代码审查规范

### 19.1 PR 检查清单（团队阶段强制；单人至少自检）

- 命名符合规范（snake_case / PascalCase）
- 所有变量和函数有类型声明
- 没有硬编码的资源路径和显示文本
- 跨模块通信用 EventBus，没有直接引用
- 业务层没有操作 Node
- 新增公共接口有文档注释
- 新增功能有单元测试
- 没有 `print()` 调试代码残留
- 场景可独立运行（F6 测试）
- 存档兼容性已考虑（数据结构变更需写迁移）

### 19.2 代码审查重点

1. **架构合规**：是否违反分层原则
2. **可维护性**：函数是否过长、命名是否清晰
3. **性能**：是否有明显的性能问题（循环内查找、频繁实例化）
4. **内存**：信号是否断开、资源是否释放
5. **存档兼容**：数据结构变更是否有迁移
6. **错误处理**：边界条件是否处理（空值、越界、满背包）

## 总结：规范执行保障

1. **模板化**：提供场景模板、脚本模板、模块模板，新建即合规
2. **自动化检查**：CI 运行命名检查、类型检查、测试、配置校验
3. **编辑器插件**：Godot 编辑器内集成规范检查器，实时提示
4. **代码审查**：PR 必须过检查清单（团队阶段 2 人审批；单人阶段自检）
5. **定期复盘**：每迭代回顾规范执行情况，更新规范

> 规范的目的不是束缚，而是让**10个人写的代码像1个人写的**，让**6个月后的自己还能看懂今天的代码**。

以上规范可根据团队规模和项目阶段裁剪，但**架构分层、事件驱动、数据驱动、命名规范**这四条是底线，任何阶段都不应妥协。
