## 一、问题（你记录、我修）

切片 B 的端到端测试 `test_elite_battle_shows_status_mechanics` 断言单次精英战中
`STATUS_APPLIED(huti/jingci/buqu)`、`SHIELD_ABSORB`、`REFLECT`、`REVIVE` 全部发生。
其中 `REFLECT`/`REVIVE`/`SHIELD_ABSORB` 是**下游反应式事件**（需「施放后挨打 / 施放后阵亡」），
依赖敌人加权选招的随机序列 → 非确定性，连跑 3 次 2 败 1 过。

## 二、根因

`services/combat/combat_core.gd` 的 `configure(p_state, seed_val=0)`：

```gdscript
if seed_val == 0:
    seed_val = int(Time.get_unix_time_from_system()) & 0x7FFFFFFF
rng.configure(seed_val)
```

`combat_service.start_combat` 不传 seed → 每次用**系统时间戳**派生 RNG 种子 →
敌人选招序列每跑必变 → 反应式事件概率性出现 → 测试 flaky。

## 三、修复

测试内注入**固定种子**（走 `combat_service.gd:12` 注释「测试可注入固定 seed 验证确定性」既定通道）：

```gdscript
GameManager.combat_service.start_combat(BATTLE_ID)
GameManager.combat_service.get_core().rng.configure(20260829)  # 覆盖时间戳种子 → 确定性回归
```

种子值 `20260829` 经隔离运行器 3 连跑验证：6 条断言稳定全过。
同时修正测试顶部误导性注释（原称「SeededRNG 默认 seed 确定性」，实为时间戳种子）。
