# HUD 常驻系统 · 落地方案 v2（对齐本工程现有约定）

> 本文是原始《RPG 常驻 HUD 系统完整架构设计》的**本地化改造版**。原始设计原则（视图-数据分离、事件驱动、不轮询、生命周期可控、防穿透、多 AI 分工）方向正确、符合大厂规范，但多处与本项目真实代码（EventBus / UIManager / GameManager / Hud.gd / TownScene）冲突。本方案把全部假设翻译成真实文件名、真实信号名、真实 layer 值、真实服务接入方式，并给出多 AI 主权边界与派单计划，可直接作为下一轮协同派单依据。

---

## 0. 相对原始设计的差异摘要（必读）

| 原始设计假设 | 本工程真实情况 | v2 处理 |
|---|---|---|
| `GlobalEventBus` | 单例叫 `EventBus`（`autoload/EventBus.gd`，全局直接 `EventBus.xxx`） | 全部改用 `EventBus` |
| `PopupUIManager.get_instance().fullscreen_popup_opened` | 无 `PopupUIManager`；真实为 `EventBus.ui_screen_opened/closed`（已存在）+ `UIManager.is_popup_open()` | 改用 `EventBus.ui_screen_opened/closed` |
| `QuestService.get_instance()` | `QuestService` 是 RefCounted 业务层，由 `GameManager.quest_service` 持有，**无 `get_instance()`** | 改用 `GameManager.quest_service` |

| 契约文档写「飞书」 | 本项目契约文档是 `docs/契约总表.md`（由 `tools/gen_contract.gd` 自动生成） | 信号增量落 `契约总表.md` + 重跑 `gen_contract` |

## 1. 现有体系事实清单（落笔前已核实）

1. **事件总线**：`autoload/EventBus.gd`（单例 `EventBus`，`extends Node`，**不写 class_name**）。已有信号含：
   - 任务：`quest_accepted` / `quest_objective_updated(quest_id, objective_id, progress)` / `quest_objective_completed` / `quest_completed` / `quest_ready_to_turn_in` / `quest_turned_in` / `quest_phase_changed`
   - 武学：`ability_learned(ability_id)` / `ability_used(ability_id, caster_id)` / `combat_skill_equipped(ability_id, slot)`
   - UI：`ui_screen_opened(screen_name)` / `ui_screen_closed(screen_name)`
   - 背包：`inventory_add_overflow(item_id, lost_count)`
   - 命名铁律：**`cmd_` = 请求指令**（如 `cmd_start_combat`），**`notify_`/`模块名_` = 已发生事实**（如 `combat_finished`、`notify_forge_completed`）。
2. **UI 管理器**：`autoload/ui_manager.gd`（单例 `UIManager`，不写 class_name）。持有 6 个 `CanvasLayer`，`_init_layers()` 里 `canvas.layer = layer_value * 10`，`get_tree().root.call_deferred("add_child", canvas)`。
3. **GameManager 暴露的业务服务**（`autoload/GameManager.gd`）：
   - `quest_service: QuestService`（`GameManager.quest_service`）
   - `ability_service: AbilityService`（`GameManager.ability_service`）
   - `romance_service: RomanceService`、`player_state: PlayerState`
   - 全部 `register_saveable(...)`，存档唯一来源在 `GameState`。
4. **现有 HUD 挂载**：`scenes/gameplay/town/TownScene.gd:146-147`：
   ```gdscript
   var hud: Hud = load(PathConstants.SCENE_HUD).instantiate()
   add_child(hud)   # ⚠️ 挂在 Node2D 下，会被 Camera2D 影响；v2 改为进 UIManager 的 HUD 层
   ```
   `PathConstants.SCENE_HUD = "res://scenes/ui/overlays/hud/Hud.tscn"`。
5. **现有 `Hud.gd` 内容**：左上玻璃拟态状态卡（头像/姓名/等级/银两/气血/内力/六维）、右上「姻缘」按钮（红点）+「菜单」按钮（开 `GameMenu`）、订阅 `player_hp/mp/level/exp/stats/money_changed` + `bond_relationship_changed`。
6. **`GameMenu` 导航屏已存在**（`scenes/ui/screens/game_menu/GameMenuScreen.gd`，注册名 `GameMenu`）：纯导航枢纽，按钮经 `UIManager.open_screen(screen_name, Layer.FULLSCREEN)` 打开各界面。即「背包/地图/任务/设置」逻辑可复用此屏，右上菜单无需另建一套。
7. **真实公开 API（技能栏用）**：
   - `ability_service.equip_combat_skill(slot: int, ability_id: String) -> bool`
   - `ability_service.unequip_combat_skill(slot: int)`
   - `ability_service.use_combat_skill(slot, caster, target)`（战斗内调用）
   - `ability_service.equipped_combat: Array[String]`（装备槽数组，`MAX_COMBAT_SKILLS` 上限）
   - `combat_skill_equipped(ability_id, slot)`（装备变更信号，**已存在**）
   - ❗ **无冷却状态、无 `skill_cd_update` 信号** → 技能栏冷却是绿地依赖。
8. **真实公开 API（任务追踪用）**：
   - `quest_service.get_tracked() -> Array[QuestState]`（**真实方法名**，非 `get_track_quest_list()`）
   - `quest_service.get_active_quest_ids() -> Array[String]`
   - ❗ 当前**无「追踪集合变更」的 emit 点** → 需任务窗口在追踪集合变动处补 `notify_quest_track_changed` emit（派单）。

```

  └─ GameManager.player_state / romance_service

  ├─ 现有：quest_objective_updated / combat_skill_equipped / ui_screen_opened|closed
  └─ 新增（追加，走契约总表）：notify_quest_track_changed / notify_skill_bar_changed / notify_skill_cd_update
        ↓ HUD 只订阅、不轮询
视图层（scenes/ui/overlays/hud/，单一职责预制）
  ├─ Hud.tscn（挂载根，保留 PathConstants.SCENE_HUD）
  │   ├─ StatusCardPanel        （现有状态卡，保留）
  │   ├─ QuestTrackPanel        （左上，新增）
  │   ├─ TopRightMenuPanel      （右上：姻缘红点 + 菜单/快捷入口，重构现有按钮）
  │   └─ SkillBarPanel          （底部，新增）
  └─ 各 Panel 独立 .gd，互不耦合
        ↓ 由场景/ UIManager 装配
场景装配层
  ├─ TownScene     → UIManager.get_layer(Layer.HUD).add_child(hud)
  ├─ Overworld     → 同上（未来新增时）
  ├─ BattleScene   → 不挂载 HUD（战斗用自身 UI）
  └─ MainMenu      → 不挂载 HUD
```

## 3. 渲染层级（真实 UIManager 坐标系）

`UIManager` 的 `layer = 枚举值 * 10`。**在现有枚举中插入 `HUD`，落在「游戏世界(0)」与「转场(100)」之间**，使 HUD 高于世界、被转场遮罩与全屏弹窗共同覆盖（符合「弹窗盖 HUD」需求），且单一 owner（UIManager）管整套坐标，杜绝原始设计「另建 HUDCanvas 平行坐标系」的脆弱性。

**精确枚举增量**（`autoload/ui_manager.gd` 现有 `Layer` 改为带显式值）：

```gdscript
enum Layer {
	BACKGROUND = 0,        # 0    游戏世界底（TileMap/角色/NPC/Camera2D）
	HUD = 5,               # 50   ← 新增：常驻 HUD（任务追踪/右上菜单/技能栏）
	TRANSITION = 10,       # 100  场景淡入淡出转场遮罩
	FULLSCREEN = 20,       # 200  全屏界面（背包/结缘/菜单/任务…）
	POPUP = 30,            # 300  弹窗（确认框等）
	TOOLTIP = 40,          # 400  Toast / 浮动提示
	SYSTEM_OVERLAY = 50,   # 500  系统级浮层（严重告警）
}
```

> 注：原始文档「HUD=10、Popup=20、Toast=30」是它自有的连续编号，与本项目 `*10` 映射不兼容。本方案以 **50** 为 HUD 真实 `CanvasLayer.layer` 值，语义等价于文档意图（HUD 在 Popup 之下）。

**层级规范表（真实值）**：

| 层 | 枚举 | CanvasLayer.layer | 内容 | 由谁拥有 |
|---|---|---|---|---|
| 游戏世界 | （场景内 CanvasItem） | 0 | TileMap / 角色 / NPC / 世界空间 UI（血条/名字） | 场景 |
| **HUD 常驻** | `HUD` | **50** | 任务追踪、右上菜单、技能栏 | **UIManager（UI 窗口主权）** |
| 转场 | `TRANSITION` | 100 | 场景切换淡入淡出 | UIManager |
| 全屏界面 | `FULLSCREEN` | 200 | 背包/结缘/菜单/任务/设置 | UIManager |
| 弹窗 | `POPUP` | 300 | 确认框 | UIManager |
| Toast | `TOOLTIP` | 400 | 提示/掉落飘字 | UIManager |
| 系统浮层 | `SYSTEM_OVERLAY` | 500 | 严重告警 | UIManager |

## 5. 场景装配规范（保留现有挂载线，修复 Camera2D 耦合）

**问题**：现有 `TownScene` 把 `hud` `add_child` 到 Node2D 下，HUD 会成为 Camera2D 的子空间变换对象、随镜头滚动。正确 HUD 必须脱离镜头。

**v2 方案**：HUD 统一挂载到 `UIManager` 的 `HUD` 层 CanvasLayer（该 CanvasLayer 是 root 下的独立层，不受 Camera2D 影响）。在 `UIManager` 新增一个小助手集中处理，避免各场景重复写挂载逻辑：

```gdscript
# autoload/ui_manager.gd 新增
## 把常驻 HUD 根节点挂到 HUD 层（Camera2D 无关，切场景随场景销毁）
func mount_hud(hud: Control) -> void:
	var layer_canvas: CanvasLayer = get_layer(Layer.HUD)
	if layer_canvas == null:
		GameLogger.error("UIManager", "HUD 层不存在")
		return
	layer_canvas.add_child(hud)
```

`TownScene.gd` 挂载行改为：

```gdscript
# 旧：add_child(hud)
# 新：
UIManager.mount_hud(load(PathConstants.SCENE_HUD).instantiate())
```

**生命周期**：`change_scene_to_file()` 切换场景时，旧场景整体销毁，`UIManager` 的 HUD 层 CanvasLayer 仍在（它是 autoload、跨场景常驻），但其中的 `hud` 子节点随旧场景树释放。为避免跨场景残留引用，HUD 根在 `_exit_tree` 断开所有 EventBus 订阅（见第 6 节通用模板）。**BattleScene / MainMenu 不调用 `mount_hud`** → 战斗/主菜单无 HUD（符合需求）。

> 若未来战斗需保留技能栏：仅 `BattleScene` 单独 `mount_hud` 一个 `SkillBarPanel` 实例，其他 HUD 不加载即可。

## 6. 三大 HUD 组件详细设计（真实类名/方法/信号）

### 通用模板（所有 Panel 共用，避免重复踩坑）

```gdscript
extends Control   # 或 MarginContainer 作根

func _ready() -> void:
	_build_ui()                      # 代码构建节点（Anchor+Offset，禁硬编码坐标）
	# 订阅事件总线（状态变化才刷新，禁 _process 轮询）
	EventBus.ui_screen_opened.connect(_on_popup_open)
	EventBus.ui_screen_closed.connect(_on_popup_close)
	_refresh()

func _refresh() -> void:
	pass   # 由 Service 公开 API 取最新数据重绘

func _on_popup_open(_screen: String) -> void:
	mouse_filter = Control.MOUSE_FILTER_IGNORE   # 弹窗打开屏蔽点击，防穿透
func _on_popup_close(_screen: String) -> void:
	mouse_filter = Control.MOUSE_FILTER_STOP

func _exit_tree() -> void:
	# 销毁断开所有信号，防内存泄漏（含 ui_screen_* 与业务信号）
	if is_instance_valid(EventBus) and EventBus.ui_screen_opened.is_connected(_on_popup_open):
		EventBus.ui_screen_opened.disconnect(_on_popup_open)
	if is_instance_valid(EventBus) and EventBus.ui_screen_closed.is_connected(_on_popup_close):
		EventBus.ui_screen_closed.disconnect(_on_popup_close)

# 安全区适配：根节点 _ready 调用 UIManager.apply_safe_area(self)，避开安卓刘海/挖孔
```

### 6.1 左上：任务追踪 `QuestTrackPanel`（新增）

- **数据来源**：`GameManager.quest_service.get_tracked() -> Array[QuestState]`（真实方法）。
- **刷新触发**：订阅新增信号 `notify_quest_track_changed`（追踪集合变更时）+ 现有 `quest_objective_updated`（进度变化时局部刷新）。
- **条目生成**：`preload("res://scenes/ui/overlays/hud/quest_track_entry.gd").instantiate()`，调 `entry.set_data(quest_state)` 填充文本/进度。
- **清理**：`_refresh` 用立即释放避免重复节点：

```gdscript
func _refresh() -> void:
	for child in _scroll_content.get_children():
		child.free()            # 用 free() 而非 queue_free()，同帧多次刷新不产生幽灵节点
	for q in GameManager.quest_service.get_tracked():
		var entry: Control = preload("res://scenes/ui/overlays/hud/quest_track_entry.gd").instantiate()
		entry.set_data(q)
		_scroll_content.add_child(entry)
```

- **大列表量化阈值**：条目 > 30 时升级虚拟列表（当前不急，先留接口）。

### 6.2 右上：菜单 `TopRightMenuPanel`（重构现有按钮，非新建并行）

- **复用 `GameMenu` 导航屏**：现有 Hud 已有「菜单」按钮开 `GameMenu`（内含背包/地图/任务/设置式入口）。v2 不另建一套 4 按钮菜单，而是把现有「姻缘 + 菜单」重构为 `TopRightMenuPanel`：
  - 保留「姻缘」按钮（红点逻辑不变，`romance_service.get_marriageable_npc_ids()`）。
  - 「菜单」按钮保留，开 `GameMenu`。
  - 可选加一排**高频快捷入口**（背包/技能/地图），每个 `pressed` 调 `UIManager.open_screen("Inventory"/"GameMenu"/...)`，避免与 `GameMenu` 功能重复。
- **禁止**：在此 Panel 直接写跳场景逻辑或改它窗数据，只调 `UIManager.open_screen` 与 `EventBus` 信号。

### 6.3 底部：技能栏 `SkillBarPanel`（新增，含绿地依赖）

- **数据来源**：`GameManager.ability_service.equipped_combat: Array[String]`（真实字段）。
- **刷新触发**：订阅现有 `combat_skill_equipped(ability_id, slot)`（装备变更）+ 新增 `notify_skill_bar_changed`（配置改动）+ 新增 `notify_skill_cd_update(skill_id, remain_time)`（冷却 tick，**只更新遮罩不重建**）。
- **格位构建**：

```gdscript
func _refresh() -> void:
	for c in _slot_container.get_children(): c.free()
	var slots: Array[String] = GameManager.ability_service.equipped_combat
	for i in slots.size():
		var slot_ui: Control = preload("res://scenes/ui/overlays/hud/skill_slot.gd").instantiate()
		slot_ui.setup(i, slots[i])
		slot_ui.skill_clicked.connect(func(slot): _use_skill(slot))   # 战斗内才真正释放
		_slot_container.add_child(slot_ui)

func _on_cd_update(skill_id: String, remain: float) -> void:
	# 仅遍历更新对应格子冷却遮罩，不销毁重建（性能优化）
	for slot in _slot_container.get_children():
		if slot.skill_id == skill_id:
			slot.set_cd_mask(remain)
```

- **绿地依赖（必须派单给武学窗口）**：冷却状态当前不存在于 `ability_service`。技能栏的 `notify_skill_cd_update` 与冷却数值，需武学窗口在 `ability_service` 内新增冷却字段 + 计时 emit，UI 窗口只消费。在武学窗口交付前，技能栏可先「只显示已装备技能、无冷却遮罩」灰度上线。

## 7. 事件总线契约增量（精确签名 + 落地到契约总表）

**新增 3 个信号（追加到 `EventBus.gd` 末尾，共享地基只增不改；逐条加 `@warning_ignore("unused_signal")`）**：

```gdscript
# === HUD 常驻系统（UI 窗口主权 · 纯追加） ===
signal notify_quest_track_changed()                       # 追踪任务集合变更（任务窗口在 set_tracked 处 emit）
signal notify_skill_bar_changed()                         # 技能栏配置改动（武学窗口 emit）
signal notify_skill_cd_update(skill_id: String, remain_time: float)  # 技能冷却 tick（武学窗口 emit）
```

**命名遵循铁律**：三者均为「已发生事实」→ `notify_` 前缀（与 `notify_forge_completed` 等一致）。

**落地步骤（共享地基增量协议）**：

## 11. 风险与坑点（结合本项目已知坑）

1. **Camera2D 耦合**：现有 `add_child(hud)` 到 Node2D 会让 HUD 随镜头滚——轮次 A 必须改 `mount_hud` 进 CanvasLayer，否则 HUD 飘移。
2. **信号 disconnect 判空**：`_exit_tree` 里 disconnect 前先 `is_instance_valid(EventBus)` 且 `.is_connected()` 判真，避免切场景时 EventBus 已先于 HUD 释放导致 `Trying to cast a freed object`。
3. **`queue_free` 幽灵节点**：`_refresh` 清空子节点用 `child.free()` 而非 `queue_free()`，防止同帧双刷新出现重复条目。
4. **共享地基增量协议**：EventBus 追加信号后必须同步 `docs/契约总表.md` 并重跑 `tools/gen_contract.gd`，否则 gate 的契约一致性检查红。
5. **主权越权**：UI 窗口**绝不**在 `quest_service` / `ability_service` 内加 emit——那是任务/武学窗口主权，只能派单。
6. **双 HUD 风险**：务必「重构而非并行」，迁移完成后旧按钮/状态卡代码要删干净。
7. **`get_tracked()` 返回 `Array[QuestState]`**：Panel 里遍历要用 typed 数组（`for q in ...` 或显式 `Array[QuestState]`），避免 untyped Variant 推断踩坑（本项目 GDScript 4.x 高频坑）。
8. **BattleScene 不挂载**：确认 `BattleScene.gd` 不调用 `mount_hud`，否则战斗出现常驻 HUD 遮挡战斗 UI。
