## 一、目标
让 M3-2 的三种状态（护盾 `huti` / 反弹 `jingci` / 复活 `buqu`）通过「真实敌人配置 → 真实 ai_kit → 真实战斗事件」链路被触发，而不只是单测里手搓状态。

切口（来自项目记忆 Phase 3 待办 + 切片 A 后状态）：`status_effects.json` 里 `huti`/`jingci`/`buqu` 三种状态虽已由 M3-2 实现并单测覆盖，但**没有任何技能施加它们、没有任何敌人使用、没有任何战斗能触发**——等于「引擎造好却没内容接」。本切片补齐内容侧：新增 3 个自我增益技 + 2 个新敌人 + 1 场精英战，并以端到端测试锁死「配置→选技→状态真实施加」整链。

约束：
- 纯数据 + 测试，不增任何战斗逻辑（状态引擎已由 M3-2 交付并单测覆盖）。
- 不碰共享地基（EventBus / enums / ConfigManager / screens.json / strings.csv / ui_anim.json）。
- `skills.json` / `enemies.json` / `battles.json` 均属**战斗窗口主权**（见 MEMORY 多 AI 协同边界）。

| 用例 | 验证点 |
|---|---|
| `test_elite_enemies_wire_status_mechanics` | **配置完整性（确定性，无 RNG）**：`battle_bandit_elite` 编成含盾卫/狂信徒；`get_enemy` 拿到两敌；其 `abilities[].id` 经 `get_ability` 指向真实技能；这些技能的 `effects` 确实施加 `huti`(盾卫)/`jingci`(盾卫)/`buqu`(狂信徒)——证明状态机制已接入真实战斗内容 |
