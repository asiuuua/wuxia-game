## 一、新增 `core/resource_manager.gd`（class_name ResourceManager，纯静态工具）
统一收口"重资源"（CG 视频/图片/语音/大纹理）的获取与回收，解决工业化体量三类痼疾：
1. **重复加载**：同一 path 全局只持有一份（引用计数，多消费者共享）。
2. **内存无界**：分级回收（L1 常驻 / L2 温存 TTL / L3 冷回收）+ 硬上限，内存有界。
3. **阻塞加载**：`acquire_async` 走后台线程，完成回调不卡帧。

### API
- 同步：`acquire_sync(path, type_hint)`（引用计数 +1，命中即返）、`release(path)`（引用 -1）、`get_resource(path)`、`has(path)`、`get_refcount(path)`。
- 异步：`acquire_async(path, type_hint, cb)`（引用计数 +1 + 后台加载，完成 `cb(res)`；已就绪则同帧回调）。
- 分级回收：`set_cap(n)` / `set_warm_ttl(ms)` / `reclaim_idle()`（限频扫描：引用 0 且超 TTL 或超硬上限者释放）/ `reclaim_all()`（释放全部引用 0 条目，**并集中调用** `PortraitCacheManager.clear()` + `CombatEntityPool.clear()`）/ `force_reclaim_all()`（含引用 >0，仅重启/切档用）。
- 诊断：`get_stats()`。

### 异步完成驱动（不增 Autoload）
- 通过 `Engine.get_main_loop()` 取 `SceneTree`，连接一次 `process_frame` 信号（`_on_process_frame` → `_pump_tick`），每帧泵在途异步加载并触发回调。无主循环环境（纯 `--script` 校验）安全跳过。
- 提供 `pump()` 供测试/确定性驱动。

## 二、集中回收接线（GameManager · 装配中枢）
- 新增 `const ResourceManager = preload("res://core/resource_manager.gd")`。
- 在全部大场景切换边界调用 `ResourceManager.reclaim_all()`：`start_battle` / `return_to_town` / `load_game` / `return_to_title` / `return_to_safe_point`。
- 语义：切场景前集中释放温存/冷资源（CG/语音/立绘缓存/战斗实体池统一释放口），内存有界、无残留累积。

## 三、CG / 语音统一走 acquire_async（见 P5 通告）
- `CelebrationOverlay._apply_media/_play_bgm`、`AudioManager.play_voice` 均经 `ResourceManager.acquire_async`，获得引用计数 + 分级回收能力（语音播完 `release`，CG 关界面时随 reclaim 释放）。

## 四、测试
- 新增 `tests/unit/test_resource_manager.gd`（4 项）：同步引用计数+复用 / reclaim_all 释放温存 / reclaim_all 清理立绘缓存 / acquire_async 完成回调+缓存。

## 五、未涵盖 / 说明
- `PortraitCacheManager`（纹理 LRU）与 `CombatEntityPool`（实体/HUD 池）保持各自专精实现；`ResourceManager.reclaim_all()` 作为"大场景切换统一回收口"集中调用二者 `clear()`，避免散落多处。
- 引用计数 + 分级回收策略覆盖所有重资源；JSON/配置类轻量数据仍由 `ConfigManager` 懒加载分片管理（P1），二者职责互补、不重叠。
