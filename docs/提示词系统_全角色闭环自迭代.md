**桥接策略（保留你的习惯，落到真实位置）**：
- AI 输出仍用你熟悉的 `【K{编号}】｜分类｜现象｜根因｜修复/实现手段｜预防手段｜测试校验点` 格式（便于人读、便于归档）。

- 人工/半自动把该条目合并进对应真实文件后，下一轮 prompt 通过 `knowledge.refs` + `/api/experience` **自动载回**，无需重新粘贴飞书。

## 一、项目真实基底上下文（发给 AI 的「项目基础上下文」固定段）

每次任务都把下面这段 + 「载入知识库」段 + 角色模板拼在一起发送。

```
【项目基础上下文】
项目：Godot 4.7.2 武侠 RPG 单机「武侠江湖」；纯 GDScript；等距 2.5D（实际代码纯 2D）。
目标平台：Win + 安卓；世界为「区域枢纽式」；战斗为「回合制 + 自动 + 战棋」。

【五层解耦架构（单向依赖铁律）】
autoload(19单例) → core → data(JSON) → services(RefCounted纯逻辑,不持Node) → scenes(视图/实体) → resources/tests/tools
四底线（架构宪法，不可破）：
  1. 单向依赖：上层可依赖下层，下层绝不反向引用上层。
  2. 跨模块只走 EventBus：禁止业务模块互相 preload + 直调。
  3. 数值全进 JSON：所有可调数值写在 data/configs/**.json；代码里 .get("x", N) 的 N 仅是「配置缺字段时的安全网」，不是调参入口。
  4. 命名见名知意：禁止 tmp/a/b/x 之类。

【核心枢纽 autoload】
- EventBus：跨模块唯一信号通道（~90 信号，NOTIFY/CMD 分离；cmd_ 前缀 = UI/对话→业务的请求信号）。
- GameManager：装配中枢(DI 容器)；视图层只经 GameManager.xxx_service 调用业务；场景切换统一走 _deferred_change_scene（错开一帧，禁同帧 queue_free+change_scene）。
- ConfigManager：配置总入口，按 ID 查各 JSON 表；对话分片懒加载(_dialog_cache 上限256/TTL2s)。
- UIManager：6 层 CanvasLayer 栈 + Toast 对象池；弹窗关闭统一走 EventBus.popup_close_requested → UIManager 收口；screens.json 用 cache:true 的界面关闭只隐藏。
- SaveManager/SaveValidator/GameState：存档唯一来源（ISaveable 注册 + 原子写 + .bak 回退）。
- 其余：DifficultyManager / WeatherTimeService / AudioManager / LocalizationManager / ErrorHandler / TransitionManager / PatchManager / ObjectPool。

【业务服务层 services/*（均 extends RefCounted，纯逻辑）】
combat / inventory / ability / quest / equipment / alchemy / forge / shop / sect / dialogue / bond(5个) ；资源缓存 core/(resource_manager/portrait_cache_manager/streaming_media_loader/combat_entity_pool)。

【事件执行层（事件→表现翻译器）】
- core/combat_event_renderer.gd：共享战斗事件→表现映射（飘字/震屏），去重两套战斗实现差异。
- services/dialogue/dialogue_event_executor.gd：对话 trigger_events 演出（音效/震屏/接任务）。

【Live-Ops 数据驱动】所有角色/技能/道具/敌人/对话/地图/难度/配方 → data/configs/**.json；文案走 LocalizationManager.tr()（全工程 296 处，禁硬编码字符串）。

【多 AI 协同铁律】
- 主权边界：UI窗口(scenes/ui/**)、战斗窗口(scenes/**/battle*)、背包窗口(services/inventory)、结缘窗口(services/bond) 各有主权；跨窗只派单(handoff)不直改。
- 共享地基冻结：EventBus / ConfigManager / core/enums/* / screens.json / strings.csv / GameManager / GameState 改动须架构师认可 + 写变更通告。
- 三铁律：留痕(change_log.py add；共享地基→change_log.py notice) / 调前先查(change_log.py query + git log + handoff dashboard) / 双闸门才 commit(窗口署名)。
- 双闸门：GATE1(--headless --quit 零 SCRIPT/PARSE/COMPILE ERROR) + GATE2(res://tests/unit/run_all.tscn 零✗ 且「套件失败 0」双满足)。任一门禁红 → 禁提交。
- 高冲突热区（多 AI 必改同一文件，须串行或走扩展点）：EventBus.gd / ConfigManager.gd / GameManager.gd(_init_services/_register_saveables) / 大 JSON 表 / .tscn 场景。

【本次任务约束】单次输出代码控制 400 行以内；输出必须包含风险点、测试要点。
```

## 六、自学习闭环机制（真实落地版：AI 输出 → 精准归档 → 下一轮自动载回）

### 6.1 每次任务结束的自学习条目（已有格式，强调「精准」）

以「修 BUG 后」为例，条目必须能回答：调整了什么 / 修复了什么 / 值得提炼的点 / 归档到哪 / 下次优先查什么：

```
====【本次待沉淀知识库条目】====
【K{自增}】｜BUG经验｜{现象：如主菜单点击继续游戏后引擎卡死无报错}｜
根因：{queue_free 与 change_scene_to_file 同帧竞争，触发 Parent busy adding/removing children 死锁}｜
修复/实现手段：{所有场景切换统一走 GameManager._deferred_change_scene = await process_frame 后切}｜
预防手段：{任何场景切换禁在 UI 关闭/queue_free 同帧调 change_scene_to_file；强制走延迟一帧通道}｜
测试校验点：{GATE2 启动→主菜单→继续游戏→回城 反复 5 次无卡死；test_xxx 新增同帧切换用例}｜

关联：{文件 GameManager.gd:_deferred_change_scene；信号 —；BUG-xx}
```

### 6.2 归档命令（人工复制 / 半自动）

- BUG 经验：`change_log.py add --module <模块> --desc "<根因/修复>"` 留痕；并把 K 条目合并进 `docs/经验库/06` 对应表行；若是新 BUG，登记到 `docs/代码审计报告_2026-09-02.md` 为 BUG-xx。
- 编码/UI/架构/协同/性能：`change_log.py notice`（共享地基改）→ 生成 `变更通告_*.md`；并把 K 条目合并进 `docs/经验库/0x` 对应篇 + 白皮书对应章。
- 跨会话铁律：写入 `.workbuddy/memory/MEMORY.md`（下次会话自动注入）。
- 平台回载：条目所在文件已在 `projects/wuxia_game.yaml` 的 `knowledge.refs`，下一轮 AI 经 `/api/experience` 富化自动拿到，**无需重新粘贴飞书**。

### 6.3 闭环校验（确保「学习」真发生）

- 每月跑一次「全角色复盘提示词」+「工作室平台对照优化提示词」，把通用经验固化进 `经验库/09 可复用模式` 与 `manifest` 的 `reusable_patterns/predecessor_mistakes`。
- 知识库条目超 50 条时做归类、删重复（当前 经验库/00~10 + BUG-01~33，远未超，但需防 prompt 过长）。

## 七、小白通用收获（本项目版，可直接写进文档）

1. 游戏开发优先做**数据驱动、分层解耦**（五层单向依赖），后期维护成本指数级下降——本工程 212 个 .gd / 49 个 .tscn / ~35000 行仍能多 AI 并行，靠的就是铁律。
2. 正向写代码同时必须有**逆向思维**：写完就问「哪里会坏？边界是什么？怎么测？」（对应 6 类自审查清单）。
3. BUG 别只修好就结束，要**沉淀踩坑**（K 条目 → 经验库/06 → 下一轮自动避坑）。最高频真教训：切场景 `call_deferred`、资产操作先预检再 apply 失败回滚、状态单一真源、删文件先查引用、装饰节点 `mouse_filter=IGNORE(2)`。
4. **UI 视图与业务逻辑严格分离**是 CRPG 最大避坑点（UIManager 收口弹窗、菜单只 emit `ui_action_requested`）。
5. 多角色协同，**文件/模块职责边界清晰**（主权窗口 + handoff 派单），否则冲突和 BUG 大量涌现。
6. 性能隐患多在细节：**帧回调重逻辑、节点不销毁、一次性全量加载、压缩纹理取像素**。
